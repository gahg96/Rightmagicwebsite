# 4.21 CUDA 与其他 API 的互操作

从 CUDA 直接访问 GPU 数据的 API，可以用 CUDA 核函数读写这些数据，从而在使用这些 API 时发挥 CUDA 的特性。主要有两个概念：直接法，即与 OpenGL 和 Direct3D[9-11] 的图形互操作（Graphics Interoperability），它能将 OpenGL 和 Direct3D 的资源映射到 CUDA 地址空间；更灵活的方法是外部资源互操作（External resource interoperability），其中内存和同步对象可以通过操作系统级别的句柄导入和导出进行访问。目前支持的 API 包括 Direct3D[11-12]、Vulkan，以及 NVIDIA 软件通信接口互操作。

## 4.21.1 图形互操作

在使用 CUDA 访问 Direct3D 或 OpenGL 资源（例如 VBO，即顶点缓冲对象）之前，必须先注册（register）并映射（map）该资源。用相应的 CUDA 函数注册（见下文示例）会返回一个类型为 `struct cudaGraphicsResource` 的 CUDA 图形资源，其中保存着 CUDA 设备指针或数组。要在核函数中访问设备数据，必须先映射该资源。资源注册后，可以根据需要多次映射和取消映射。映射后的资源可由核函数通过以下方式访问：对于缓冲，使用 `cudaGraphicsResourceGetMappedPointer()` 返回的设备内存地址；对于 CUDA 数组，使用 `cudaGraphicsSubResourceGetMappedArray()`。当 CUDA 不再需要该资源时，可以将其注销（unregister）。

主要步骤如下：

1. 向 CUDA 注册图形缓冲
2. 映射该资源
3. 访问映射资源的设备指针或数组
4. 在 CUDA 核函数中使用设备指针或数组
5. 取消映射该资源
6. 注销该资源

注意，注册资源的代价较高，因此理想情况下每个资源只注册一次；不过，对于每一个打算使用该资源的 CUDA 上下文，都需要单独注册一次。可以用 `cudaGraphicsResourceSetMapFlags()` 指定用法提示（如只写、只读），CUDA 驱动可用其优化资源管理。还请注意，当资源处于映射状态时，若通过 OpenGL、Direct3D 或另一个 CUDA 上下文访问它，结果是未定义的。

### 4.21.1.1 OpenGL 互操作

可以映射到 CUDA 地址空间的 OpenGL 资源包括 OpenGL 缓冲、纹理和渲染缓冲对象。用 `cudaGraphicsGLRegisterBuffer()` 注册缓冲对象，在 CUDA 中它呈现为普通的设备指针。用 `cudaGraphicsGLRegisterImage()` 注册纹理或渲染缓冲对象，在 CUDA 中它呈现为 CUDA 数组。

如果纹理或渲染缓冲对象注册时带了 `cudaGraphicsRegisterFlagsSurfaceLoadStore` 标志，则可以向其写入。`cudaGraphicsGLRegisterImage()` 支持所有带 1、2 或 4 个分量、内部类型为浮点（例如 `GL_RGBA_FLOAT32`）、归一化整数（例如 `GL_RGBA8`、`GL_INTENSITY16`）和非归一化整数（例如 `GL_RGBA8UI`）的纹理格式。

示例：simpleGL 互操作

以下代码示例用一个核函数动态修改存储在顶点缓冲对象（VBO）中的二维 `width x height` 顶点网格，主要步骤如下：

1. 向 CUDA 注册 VBO
2. 循环：映射 VBO 供 CUDA 写入
3. 循环：运行 CUDA 核函数修改顶点位置
4. 循环：取消映射 VBO
5. 循环：用 OpenGL 渲染结果
6. 注销并删除 VBO

限制与注意事项。

- 正在共享资源的 OpenGL 上下文必须是调用任何 OpenGL 互操作 API 的主机端线程的当前上下文。
- 当 OpenGL 纹理被设为无绑定（bindless）后（例如通过 `glGetTextureHandle` 或 `glGetImageHandle` API 请求图像或纹理句柄），它不能再向 CUDA 注册。应用程序需要在请求图像或纹理句柄之前，先为互操作注册该纹理。

### 4.21.1.2 Direct3D 互操作

Direct3D 互操作支持 Direct3D9、Direct3D10 和 Direct3D11，但不支持 Direct3D12。本节重点介绍 Direct3D11，Direct3D9 和 Direct3D10 请参阅 CUDA Programming Guide 12.9。可以映射到 CUDA 地址空间的 Direct3D 资源包括 Direct3D 缓冲、纹理和表面。这些资源用 `cudaGraphicsD3D11RegisterResource()` 注册。

CUDA 上下文只能与 `DriverType` 设置为 `D3D_DRIVER_TYPE_HARDWARE` 创建的 Direct3D11 设备互操作。

示例：2D 纹理 Direct3D11 互操作

以下代码片段来自 simpleD3D11Texture 示例：https://github.com/NVIDIA/cuda-samples/tree/master/Samples/5_Domain_Specific/simpleD3D11Texture。完整示例包含大量样板式的 DX11 代码，这里只关注 CUDA 部分。

CUDA 核函数 `cuda_kernel_texture_2d` 在闪烁的蓝色背景上绘制移动的红/绿斜线图案，生成 2D 纹理，它依赖于纹理之前的值。底层数据是一个二维 CUDA 数组，其行偏移由 pitch（间距）定义。

```cpp
/*
 * 在闪烁的蓝色背景上绘制移动的红/绿斜线图案，生成 2D 纹理。注意此核函数
 * 既读纹理又写纹理，因此此纹理没有按 WriteDiscard 方式映射。
 */
__global__ void cuda_kernel_texture_2d(unsigned char *surface, int width,
                                        int height, size_t pitch, float t) {
   int x = blockIdx.x * blockDim.x + threadIdx.x;
   int y = blockIdx.y * blockDim.y + threadIdx.y;
   float *pixel;

    // 由于网格量化，可能出现线程数多于像素数的情况，
    // 跳过那些不对应有效像素的线程
    if (x >= width || y >= height) return;

    // 获取 (x,y) 处像素的指针
    pixel = (float *)(surface + y * pitch) + 4 * x;

    // 填充像素
    float value_x = 0.5f + 0.5f * cos(t + 10.0f * ((2.0f * x) / width - 1.0f));
    float value_y = 0.5f + 0.5f * cos(t + 10.0f * ((2.0f * y) / height - 1.0f));
    pixel[0] = 0.5 * pixel[0] + 0.5 * pow(value_x, 3.0f); // 红
    pixel[1] = 0.5 * pixel[1] + 0.5 * pow(value_y, 3.0f); // 绿
    pixel[2] = 0.5f + 0.5f * cos(t);                       // 蓝
    pixel[3] = 1;                                          // alpha
}

extern "C" void cuda_texture_2d(void *surface, int width, int height,
                                size_t pitch, float t) {
  cudaError_t error = cudaSuccess;

    dim3 Db = dim3(16, 16); // 块维度固定为 256 个线程
    dim3 Dg = dim3((width + Db.x - 1) / Db.x, (height + Db.y - 1) / Db.y);

    cuda_kernel_texture_2d<<<Dg, Db>>>((unsigned char *)surface, width, height,
                                       pitch, t);

    error = cudaGetLastError();

    if (error != cudaSuccess) {
      printf("cuda_kernel_texture_2d() failed to launch error = %d\n", error);
    }
}
```

Direct3D 设备和纹理初始化完成后，资源向 CUDA 注册一次。为了匹配 Direct3D 的像素格式，CUDA 数组按相同的宽高分配，pitch 与 Direct3D 纹理的行间距一致。

```cpp
    // 注册 CUDA 核函数中使用的 Direct3D 资源
    // g_texture_2d 既读又写，因此不为其设置特殊的映射标志

    cudaGraphicsD3D11RegisterResource(&g_texture_2d.cudaResource,
                                       g_texture_2d.pTexture,
                                       cudaGraphicsRegisterFlagsNone);
    getLastCudaError("cudaGraphicsD3D11RegisterResource (g_texture_2d) failed
");

    // CUDA 不能直接写入纹理：纹理被视为 cudaArray，只能作为纹理映射
    // 创建一个缓冲供 CUDA 写入
    // 像素格式为 DXGI_FORMAT_R32G32B32A32_FLOAT
    cudaMallocPitch(&g_texture_2d.cudaLinearMemory, &g_texture_2d.pitch,
                    g_texture_2d.width * sizeof(float) * 4,
                    g_texture_2d.height);
    getLastCudaError("cudaMallocPitch (g_texture_2d) failed");
    cudaMemset(g_texture_2d.cudaLinearMemory, 1,
               g_texture_2d.pitch * g_texture_2d.height);
```

在渲染循环中，映射资源，启动 CUDA 核函数更新纹理数据，然后取消映射资源。此后用 Direct3D 设备将更新后的纹理绘制到屏幕上。

```cpp
      cudaStream_t stream = 0;
      const int nbResources = 3;
      cudaGraphicsResource *ppResources[nbResources] = {
```

### 4.21.1.3 可扩展链路接口（Scalable Link Interface，SLI）配置下的互操作

在多 GPU 系统中，所有支持 CUDA 的 GPU 都可通过 CUDA 驱动和运行时作为独立设备访问。而系统处于 SLI 模式时则有所不同。SLI 是一种硬件配置的多 GPU 配置，通过将工作负载分配到多个 GPU 来提升渲染性能。驱动自动假设的隐式 SLI 模式已不再支持，但显式 SLI 仍受支持。显式 SLI 指应用程序通过 API（例如 Vulkan、DirectX、GL）知晓并管理 SLI 组中所有设备的 SLI 状态。

系统处于 SLI 模式时有特殊注意事项：

- 在一个 GPU 上的一个 CUDA 设备中分配内存，会占用属于 Direct3D 或 OpenGL 设备 SLI 配置的其他 GPU 上的内存。因此，分配可能比预期更早失败。
- 应用程序应创建多个 CUDA 上下文，SLI 配置中的每个 GPU 一个。虽然这不是硬性要求，但可以避免设备之间不必要的数据传输。应用程序可以用 `cudaD3D[9|10|11]GetDevices()`（Direct3D）和 `cudaGLGetDevices()`（OpenGL）这组调用，识别在当前帧和下一帧执行渲染的设备的 CUDA 设备句柄。获知这些信息后，应用程序通常会选择合适的设备，并当 `deviceList` 参数设置为 `cudaD3D[9|10|11]DeviceListCurrentFrame` 或 `cudaGLDeviceListCurrentFrame` 时，将 Direct3D 或 OpenGL 资源映射到 `cudaD3D[9|10|11]GetDevices()` 或 `cudaGLGetDevices()` 返回的 CUDA 设备上。
- `cudaGraphicsD3D[9|10|11]RegisterResource` 和 `cudaGraphicsGLRegister[Buffer|Image]` 返回的资源只能在发生注册的设备上使用。因此，在 SLI 配置中，当不同帧的数据在不同的 CUDA 设备上计算时，有必要为每个设备分别注册资源。

## 4.21.2 外部资源互操作

外部资源互操作允许 CUDA 导入由 API 显式导出的某些资源。这些对象通常用操作系统原生的句柄导出，例如 Linux 上的文件描述符或 Windows 上的 NT 句柄。这使得资源可以在其他 API 与 CUDA 之间高效共享，无需在两者之间复制或重复。目前支持的 API 包括 Direct3D[11-12]、Vulkan，以及 NVIDIA 软件通信接口互操作。

可导入的资源有两种类型：

- **内存对象**：可以用 `cudaImportExternalMemory()` 导入到 CUDA 中。导入的内存对象随后可以在核函数中访问，方式是用 `cudaExternalMemoryGetMappedBuffer()` 将设备指针映射到内存对象上，或用 `cudaExternalMemoryGetMappedMipmappedArray()` 映射 CUDA mipmap 数组。根据内存对象的类型，单个内存对象上可能设置多个映射。映射必须与导出 API 设置的映射相匹配。任何不匹配的映射都会导致未定义行为。导入的内存对象必须用 `cudaDestroyExternalMemory()` 释放。释放内存对象不会释放其上的任何映射。因此，映射到该对象上的任何设备指针都必须用 `cudaFree()` 显式释放，映射到该对象上的任何 CUDA mipmap 数组都必须用 `cudaFreeMipmappedArray()` 显式释放。对象销毁后访问其映射是非法的。
- **同步对象**：可以用 `cudaImportExternalSemaphore()` 导入到 CUDA 中。导入的同步对象随后可以用 `cudaSignalExternalSemaphoresAsync()` 发出信号，用 `cudaWaitExternalSemaphoresAsync()` 等待。在发出相应的信号之前发出等待是非法的。另外，根据导入同步对象的类型，后续章节所述的、对其如何发信号和等待可能还有额外的约束。导入的信号量对象必须用 `cudaDestroyExternalSemaphore()` 释放。所有未完成的信号和等待都必须在销毁信号量对象之前完成。

### 4.21.2.1 Vulkan 互操作

在同一硬件上耦合执行 Vulkan 图形和计算工作负载，可以最大化 GPU 利用率并避免不必要的复制。注意，本节不是 Vulkan 指南，只关注与 CUDA 的互操作，Vulkan 指南请参阅 https://www.vulkan.org/learn#vulkan-tutorials。

实现 Vulkan–CUDA 互操作的主要步骤如下：

1. 初始化 Vulkan，创建并导出外部缓冲和/或同步对象
2. 用匹配的设备 UUID 设置 Vulkan 所在的 CUDA 设备
3. 获取内存和/或同步句柄
4. 用这些句柄在 CUDA 中导入内存和/或同步对象
5. 将设备指针或 mipmap 数组映射到内存对象上
6. 通过对同步对象发信号和等待定义执行顺序，在 CUDA 和 Vulkan 之间交替使用导入的内存对象

本节借助 simpleVulkan 示例逐步讲解上述步骤：https://github.com/NVIDIA/cuda-samples/tree/master/Samples/5_Domain_Specific/simpleVulkan。我们逐段走读示例，聚焦 CUDA 互操作所需的代码部分。一些变体用独立代码片段说明。

> **注意**
>
> 本节使用的代码示例采用直接内存分配和资源创建。由于多种原因（包括可创建实例数量的限制），这不是最先进（state of the art）的做法。但要理解互操作，需要了解底层的 Vulkan 代码和特定的标志。若想看使用 VulkanMemoryAllocator 的更先进的示例，请参阅 NVProSamples 仓库中的 sample_cuda_interop。

#### 4.21.2.1.1 设置 Vulkan 设备

要导出内存对象，必须创建 Vulkan 实例时启用 `VK_KHR_external_memory_capabilities` 扩展，并创建设备时启用 `VK_KHR_external_memory`。还必须启用平台特定的句柄类型扩展：Windows 上为 `VK_KHR_external_memory_win32`，基于 UNIX 的系统上为 `VK_KHR_external_memory_fd`。

类似地，要导出同步对象，在设备级别需要启用 `VK_KHR_external_semaphore_capabilities`，在实例级别需要启用 `VK_KHR_external_semaphore`。以及句柄的平台特定扩展，即 Windows 上的 `VK_KHR_external_semaphore_win32` 和基于 Unix 的系统上的 `VK_KHR_external_semaphore_fd`。

#### 4.21.2.1.2 用匹配的设备 UUID 初始化 CUDA

#### 4.21.2.1.4 导出 Vulkan 同步对象

在 GPU 上执行的 Vulkan API 调用是异步的。要定义执行顺序，Vulkan 提供了可与 CUDA 共享的信号量（semaphore）和栅栏（fence）。与内存对象类似，信号量可由 Vulkan 导出，需根据信号量类型用导出标志创建。有二进制信号量和时间线信号量两种。二进制信号量只有 1 位计数器，要么已发信号，要么未发信号。时间线信号量有一个 64 位计数器，可用同一信号量定义执行顺序。在 simpleVulkan 示例中有时间线和二进制信号量两条代码路径。

#### 4.21.2.1.5 导入内存对象

Vulkan 导出的专用（dedicated）和非专用内存对象都可以导入 CUDA。导入 Vulkan 专用内存对象时，必须设置 `cudaExternalMemoryDedicated` 标志。

在 Windows 上，用 `VK_EXTERNAL_MEMORY_HANDLE_TYPE_OPAQUE_WIN32_BIT` 导出的 Vulkan 内存对象，可以用与该对象关联的 NT 句柄导入 CUDA，如下所示。注意，CUDA 不接管 NT 句柄的所有权，应用程序负责在不再需要时关闭句柄。NT 句柄持有对资源的引用，因此在底层内存释放之前，必须先显式释放它。

#### 4.21.2.1.9 对导入的同步对象发信号/等待

导入的 Vulkan 信号量可以如下所示发信号和等待。对信号量发信号会将其置为已发信号状态；对于时间线信号量，会将其计数器置为发信号调用中指定的值。等待该信号的对应等待必须在 Vulkan 中发出。另外，对于二进制信号量，等待该信号的等待必须在该信号发出之后才能发出。

等待信号量会一直等待，直到它达到已发信号状态或达到指定的等待值。已发信号的二进制信号量随后会被重置回未发信号状态。该等待所等待的对应信号必须在 Vulkan 中发出。另外，对于二进制信号量，必须先发出信号，该等待才能发出。

以下取自 simpleVulkan 示例的代码片段中，只有当 Vulkan 对顶点缓冲周围的信号量发信号后，才会调用仿真步骤 / CUDA 核函数。仿真步骤之后，会对另一个信号量发信号；对于时间线信号量，则是由 CUDA 将同一个信号量加一，使得正在等待此信号量的 Vulkan 部分可以继续用更新后的顶点缓冲渲染。

```cpp
    signalValue += 2;
#else
    cudaExternalSemaphoreWaitParams waitParams = {};
    waitParams.flags = 0;
    waitParams.params.fence.value = 0;

      signalParams.flags = 0;
      signalParams.params.fence.value = 0;
```

```cpp
     // 填充属性值
     NvSciBufAttrKeyValuePair rawbuffattrs[] = {
          { NvSciBufGeneralAttrKey_Types, &bufType, sizeof(bufType) },
          { NvSciBufRawBufferAttrKey_Size, &rawsize, sizeof(rawsize) },
          { NvSciBufRawBufferAttrKey_Align, &align, sizeof(align) },
          { NvSciBufGeneralAttrKey_NeedCpuAccess, &cpuaccess_flag,
sizeof(cpuaccess_flag) },

          { NvSciBufGeneralAttrKey_RequiredPerm, &perm, sizeof(perm) },
          { NvSciBufGeneralAttrKey_GpuId, &gpuid, sizeof(gpuid) },
          { NvSciBufGeneralAttrKey_EnableGpuCache, &gpuCache, sizeof(gpuCache)
},

          { NvSciBufGeneralAttrKey_EnableGpuCompression, &gpuCompression,
sizeof(gpuCompression) }

     };

      // 通过设置属性创建列表
      err = NvSciBufAttrListSetAttrs(attrListBuffer, rawbuffattrs,
              sizeof(rawbuffattrs)/sizeof(NvSciBufAttrKeyValuePair));
       NvSciBufAttrListCreate(NvSciBufModule, &attrListBuffer);

       // 调和并分配
       NvSciBufAttrListReconcile(&attrListBuffer, 1, &attrListReconciledBuffer,
                          &attrListConflictBuffer)
       NvSciBufObjAlloc(attrListReconciledBuffer, &bufferObjRaw);
       return bufferObjRaw;
}

NvSciBufObj bufferObjRo; // 只读 NvSciBuf 内存对象
// 创建指向同一内存缓冲的重复句柄，降低权限
NvSciBufObjDupWithReducePerm(bufferObjRaw, NvSciBufAccessPerm_Readonly, &
bufferObjRo);

return bufferObjRo;
```

分配的 NvSciBuf 内存对象可以用 NvSciBufObj 句柄导入 CUDA，如下所示。应用程序应查询分配的 NvSciBufObj 的属性，用于填充 CUDA 外部内存描述符。注意，属性列表和 NvSciBuf 对象应由应用程序维护。如果导入到 CUDA 的 NvSciBuf 对象也被其他驱动映射，则应用程序必须根据 `NvSciBufGeneralAttrKey_GpuSwNeedCacheCoherency` 输出属性的值，使用 NvSciSync 对象（参阅导入同步对象）作为适当的屏障，以保持 CUDA 与其他驱动之间的一致性。

> **注意**
>
> 关于如何分配和维护 NvSciBuf 对象的更多细节，请参阅 NvSciBuf API 文档。

```cpp
cudaExternalMemory_t importNvSciBufObject (NvSciBufObj bufferObjRaw) {

       /*************** 查询 NvSciBuf 对象 ***************/
       NvSciBufAttrKeyValuePair bufattrs[] = {
                   { NvSciBufRawBufferAttrKey_Size, NULL, 0 },
                   { NvSciBufGeneralAttrKey_GpuSwNeedCacheCoherency, NULL, 0 },
                   { NvSciBufGeneralAttrKey_EnableGpuCompression, NULL, 0 }
       };
       NvSciBufAttrListGetAttrs(retList, bufattrs,
           sizeof(bufattrs)/sizeof(NvSciBufAttrKeyValuePair)));
                   ret_size = *(static_cast<const uint64_t*>(bufattrs[0].value));

    // 注意缓存和压缩是按 GPU 的属性，因此按 UUID 比较读取特定 GPU 的值
    // 读取 NvSciBuf 授予的缓存能力
    int numGpus = bufattrs[1].len / sizeof(NvSciBufAttrValGpuCache);
    NvSciBufAttrValGpuCache[] cacheVal = (NvSciBufAttrValGpuCache
*)bufattrs[1].value;

    bool ret_cacheVal;
    for (int i = 0; i < numGpus; i++) {
        if (memcmp(gpuid[0].bytes, cacheVal[i].gpuId.bytes, sizeof(CUuuid))
== 0) {
                ret_cacheVal = cacheVal[i].cacheability);
            }
        }

    // 读取 NvSciBuf 授予的压缩
    numGpus = bufattrs[2].len / sizeof(NvSciBufAttrValGpuCompression);
    NvSciBufAttrValGpuCompression[] compVal = (NvSciBufAttrValGpuCompression
*)bufattrs[2].value;

    NvSciBufCompressionType ret_compVal;
    for (int i = 0; i < numGpus; i++) {
        if (memcmp(gpuid[0].bytes, compVal[i].gpuId.bytes, sizeof(CUuuid)) ==
0) {

            ret_compVal = compVal[i].compressionType);
        }
    }

        /*************** 在 CUDA 中注册 NvSciBuf ***************/

        // 填充 CUDA_EXTERNAL_MEMORY_HANDLE_DESC
        cudaExternalMemoryHandleDesc memHandleDesc;
        memset(&memHandleDesc, 0, sizeof(memHandleDesc));
        memHandleDesc.type = cudaExternalMemoryHandleTypeNvSciBuf;
        memHandleDesc.handle.nvSciBufObject = bufferObjRaw;
        // 在这一步设置 NvSciBuf 对象所需的访问权限
        memHandleDesc.handle.nvSciBufObject = bufferObjRo;
        memHandleDesc.size = ret_size;
        cudaImportExternalMemory(&extMemBuffer, &memHandleDesc);
        return extMemBuffer;
    }
```

#### 4.21.2.3.2 将缓冲映射到导入的内存对象上

如下所示，可将设备指针映射到导入的内存对象上。映射的偏移和大小可按分配的 NvSciBufObj 的属性填充。所有映射的设备指针都必须用 `cudaFree()` 释放。

```cpp
void * mapBufferOntoExternalMemory(cudaExternalMemory_t extMem, unsigned long

     cudaExternalMemoryBufferDesc desc = {};

        memset(&desc, 0, sizeof(desc));

        desc.offset = offset;
        desc.size = size;

        cudaExternalMemoryGetMappedBuffer(&ptr, extMem, &desc);

        // 注意：'ptr' 最终必须用 cudaFree() 释放
        return ptr;
```

#### 4.21.2.3.4 导入同步对象

用 `cudaDeviceGetNvSciSyncAttributes()` 可以生成与给定 CUDA 设备兼容的 NvSciSync 属性。返回的属性列表可用于创建一个 NvSciSyncObj，保证与给定 CUDA 设备的兼容性。

```cpp
NvSciSyncObj createNvSciSyncObject() {
    NvSciSyncObj nvSciSyncObj
    int cudaDev0 = 0;
    int cudaDev1 = 1;
    NvSciSyncAttrList signalerAttrList = NULL;
    NvSciSyncAttrList waiterAttrList = NULL;
    NvSciSyncAttrList reconciledList = NULL;
    NvSciSyncAttrList newConflictList = NULL;

       NvSciSyncAttrListCreate(module, &signalerAttrList);
       NvSciSyncAttrListCreate(module, &waiterAttrList);
       NvSciSyncAttrList unreconciledList[2] = {NULL, NULL};
       unreconciledList[0] = signalerAttrList;
       unreconciledList[1] = waiterAttrList;
    cudaDeviceGetNvSciSyncAttributes(signalerAttrList, cudaDev0, CUDA_
NVSCISYNC_ATTR_SIGNAL);
    cudaDeviceGetNvSciSyncAttributes(waiterAttrList, cudaDev1, CUDA_NVSCISYNC_
ATTR_WAIT);



       NvSciSyncAttrListReconcile(unreconciledList, 2, &reconciledList, &
   newConflictList);

       NvSciSyncObjAlloc(reconciledList, &nvSciSyncObj);

       return nvSciSyncObj;
}
```

如上创建的 NvSciSync 对象可以用 NvSciSyncObj 句柄导入 CUDA，如下所示。注意，即使在导入之后，NvSciSyncObj 句柄的所有权仍归应用程序。

```cpp
cudaExternalSemaphore_t importNvSciSyncObject(void* nvSciSyncObj) {
    cudaExternalSemaphore_t extSem = NULL;
    cudaExternalSemaphoreHandleDesc desc = {};

       memset(&desc, 0, sizeof(desc));

       desc.type = cudaExternalSemaphoreHandleTypeNvSciSync;
       desc.handle.nvSciSyncObj = nvSciSyncObj;

       cudaImportExternalSemaphore(&extSem, &desc);

       // 此后删除/释放 nvSciSyncObj 会在 CUDA 中导致未定义行为

       return extSem;
}
```

#### 4.21.2.3.5 对导入的同步对象发信号/等待

导入的 NvSciSyncObj 对象可如下发信号。对 NvSciSync 支撑的信号量对象发信号，会初始化作为输入传入的 fence 参数。该 fence 参数会被与上述信号对应的等待操作等待。另外，等待该信号的等待必须在该信号发出之后才能发出。如果标志设置为 `cudaExternalSemaphoreSignalSkipNvSciBufMemSync`，则默认作为信号操作一部分执行的内存同步操作（针对本进程中所有导入的 NvSciBuf）会被跳过。当 `NvSciBufGeneralAttrKey_GpuSwNeedCacheCoherency` 为 FALSE 时，应设置此标志。

```cpp
void signalExternalSemaphore(cudaExternalSemaphore_t extSem, cudaStream_t
stream, void *fence) {

     cudaExternalSemaphoreSignalParams signalParams = {};

       memset(&signalParams, 0, sizeof(signalParams));

      signalParams.params.nvSciSync.fence = (void*)fence;
      signalParams.flags = 0; // 或 cudaExternalSemaphoreSignalSkipNvSciBufMemSync

      cudaSignalExternalSemaphoresAsync(&extSem, &signalParams, 1, stream);

}
```

导入的 NvSciSyncObj 对象可如下等待。等待 NvSciSync 支撑的信号量对象会一直等待，直到输入的 fence 参数被对应的发信号方发信号。另外，必须先发出信号，该等待才能发出。如果标志设置为 `cudaExternalSemaphoreWaitSkipNvSciBufMemSync`，则默认作为信号操作一部分执行的内存同步操作（针对本进程中所有导入的 NvSciBuf）会被跳过。当 `NvSciBufGeneralAttrKey_GpuSwNeedCacheCoherency` 为 FALSE 时，应设置此标志。

```cpp
void waitExternalSemaphore(cudaExternalSemaphore_t extSem, cudaStream_t
stream, void *fence) {

      cudaExternalSemaphoreWaitParams waitParams = {};

      memset(&waitParams, 0, sizeof(waitParams));

      waitParams.params.nvSciSync.fence = (void*)fence;
      waitParams.flags = 0; // 或 cudaExternalSemaphoreWaitSkipNvSciBufMemSync

      cudaWaitExternalSemaphoresAsync(&extSem, &waitParams, 1, stream);
}
```
