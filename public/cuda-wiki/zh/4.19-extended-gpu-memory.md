# 4.19 扩展 GPU 内存

扩展 GPU 内存（Extended GPU Memory，EGM）功能利用高带宽 NVLink-C2C，使 GPU 能高效访问单节点和多节点系统中的所有系统内存。EGM 适用于集成的 CPU-GPU NVIDIA 系统：允许分配物理内存，让该配置中的任何 GPU 线程都能访问。EGM 保证所有 GPU 以 GPU-GPU NVLink 或 NVLink-C2C 的速度访问其资源。

在这种配置中，内存访问走本地高带宽 NVLink-C2C。对于远程内存访问，使用 GPU NVLink，在某些情况下用 NVLink-C2C。借助 EGM，GPU 线程能够访问所有可用的内存资源，包括 CPU 直连内存和 HBM3，走的都是 NVSwitch 交换网。

## 4.19.1 预备知识

在深入 EGM 功能的 API 变更之前，先介绍当前支持的拓扑、标识符分配、虚拟内存管理的先决条件，以及 EGM 的 CUDA 类型。

### 4.19.1.1 EGM 平台：系统拓扑

目前 EGM 可在以下几种平台启用：(1) 单节点、单 GPU：由基于 Arm 的 CPU、CPU 直连内存和一块 GPU 组成；CPU 与 GPU 之间有高带宽 C2C（Chip-to-Chip）互联。(2) 单节点、多 GPU：由基于 ARM 的 CPU（各带直连内存）和多块 GPU 组成，GPU 通过基于 NVLink 的网络互联。(3) 多节点、多 GPU：两个或更多单节点系统（如上 (1) 或 (2)）通过基于 NVLink 的网络互联。

> **注意**
>
> 用 cgroup 限制可用设备会阻断经由 EGM 的路由并导致性能问题。请改用 `CUDA_VISIBLE_DEVICES`。

### 4.19.1.2 套接字标识符：是什么？如何获取？

NUMA（非统一内存访问）是多处理器计算机系统中的一种内存架构：内存被划分到多个节点，每个节点有自己的处理器和内存。在这种系统中，NUMA 把系统划分成节点，并为每个节点分配唯一标识符（numaID）。

EGM 使用操作系统分配的 NUMA 节点标识符。注意，这个标识符不同于设备的序号，它关联的是最近的主机节点。除了已有的方法，用户还可以用 `cuDeviceGetAttribute` 并传入 `CU_DEVICE_ATTRIBUTE_HOST_NUMA_ID` 属性类型来获取主机节点的标识符（numaID），如下：

```c
int numaId;
cuDeviceGetAttribute(&numaId, CU_DEVICE_ATTRIBUTE_HOST_NUMA_ID, deviceOrdinal);
```

### 4.19.1.3 分配器与 EGM 支持

把系统内存映射为 EGM 不会造成性能问题。实际上，访问映射为 EGM 的远程套接字系统内存会更快，因为 EGM 保证流量走 NVLink 路由。目前，`cuMemCreate` 和 `cudaMemPoolCreate` 分配器配合适当的位置类型和 NUMA 标识符受支持。

### 4.19.1.4 对现有 API 的内存管理扩展

目前，EGM 内存可以用虚拟内存（`cuMemCreate`）或流序内存（`cudaMemPoolCreate`）分配器映射。用户负责分配物理内存，并把它们映射到所有套接字上的虚拟内存地址空间。

> **注意**
>
> 多节点、多 GPU 平台需要进程间通信。因此建议读者参阅第 4.16 章。

> **注意**
>
> 建议读者阅读 CUDA 编程指南的第 4.17 章和第 4.3 章以便更好理解。

为让这些方法能用类 NUMA 节点标识符理解分配位置，API 新增了以下 CUDA 属性类型：

| CUDA 类型 | 搭配使用 |
|---|---|
| `CU_MEM_LOCATION_TYPE_HOST_NUMA` | `cuMemCreate` 的 `CUmemAllocationProp` |
| `cudaMemLocationTypeHostNuma` | `cudaMemPoolCreate` 的 `cudaMemPoolProps` |

> **注意**
>
> 关于 NUMA 相关 CUDA 类型的更多信息，请参阅 CUDA 驱动 API 和 CUDA 运行时数据类型文档。

## 4.19.2 使用 EGM 接口

### 4.19.2.1 单节点、单 GPU

任何现有的 CUDA 主机端分配器以及系统分配的内存都可以用来受益于高带宽 C2C。对用户来说，本地访问就是今天主机端分配的样子。

> **注意**
>
> 关于内存分配器和页面大小的更多信息，请参阅调优指南。

### 4.19.2.2 单节点、多 GPU

在多 GPU 系统中，用户必须提供主机信息来确定放置位置。如前所述，用 NUMA 节点 ID 表达这种信息是最自然的方式，EGM 采用了这种做法。因此，用户可以用 `cuDeviceGetAttribute` 函数得知最近的 NUMA 节点 ID（见"套接字标识符：是什么？如何获取？"一节）。然后用户可以用 VMM（虚拟内存管理）API 或 CUDA 内存池分配和管理 EGM 内存。

#### 4.19.2.2.1 使用 VMM API

用虚拟内存管理 API 分配内存的第一步是创建一个物理内存块，作为分配的后备存储。更多细节见 CUDA 编程指南的虚拟内存管理一节。在 EGM 分配中，用户必须显式提供 `CU_MEM_LOCATION_TYPE_HOST_NUMA` 作为位置类型、`numaID` 作为位置标识符。此外在 EGM 中，分配必须按平台的适当粒度对齐。下面的代码片段展示用 `cuMemCreate` 分配物理内存：

```c
CUmemAllocationProp prop{};
prop.type = CU_MEM_ALLOCATION_TYPE_PINNED;
prop.location.type = CU_MEM_LOCATION_TYPE_HOST_NUMA;
prop.location.id = numaId;
size_t granularity = 0;
cuMemGetAllocationGranularity(&granularity, &prop, MEM_ALLOC_GRANULARITY_MINIMUM);

size_t padded_size = ROUND_UP(size, granularity);
CUmemGenericAllocationHandle allocHandle;
cuMemCreate(&allocHandle, padded_size, &prop, 0);
```

物理内存分配完后，需要预留地址空间并把它映射到一个指针。这些步骤没有 EGM 特有的变更：

```c
CUdeviceptr dptr;
cuMemAddressReserve(&dptr, padded_size, 0, 0, 0);
cuMemMap(dptr, padded_size, 0, allocHandle, 0);
```

最后，用户必须显式保护映射的虚拟地址范围，否则访问映射空间会导致崩溃。与内存分配一样，用户必须提供 `CU_MEM_LOCATION_TYPE_HOST_NUMA` 作为位置类型、`numaId` 作为位置标识符。下面的代码片段为为该主机节点和 GPU 创建访问描述符，给两者对映射内存的读写访问权限：

```c
CUmemAccessDesc accessDesc[2]{{}};
accessDesc[0].location.type = CU_MEM_LOCATION_TYPE_HOST_NUMA;
accessDesc[0].location.id = numaId;
accessDesc[0].flags = CU_MEM_ACCESS_FLAGS_PROT_READWRITE;
accessDesc[1].location.type = CU_MEM_LOCATION_TYPE_DEVICE;
accessDesc[1].location.id = currentDev;
accessDesc[1].flags = CU_MEM_ACCESS_FLAGS_PROT_READWRITE;
cuMemSetAccess(dptr, size, accessDesc, 2);
```

#### 4.19.2.2.2 使用 CUDA 内存池

要定义 EGM，用户可以在一个节点上创建内存池并授予对端访问权限。此时用户必须显式定义 `cudaMemLocationTypeHostNuma` 作为位置类型、`numaId` 作为位置标识符。下面的代码片段展示用 `cudaMemPoolCreate` 创建内存池：

```c
cudaSetDevice(homeDevice);
cudaMemPoolProps props{};
props.allocType = cudaMemAllocationTypePinned;
props.location.type = cudaMemLocationTypeHostNuma;
props.location.id = numaId;
cudaMemPoolCreate(&memPool, &props);
```

此外，对于直连对端访问，还可以用现有的对端访问 API `cudaMemPoolSetAccess`。下面是为一个 `accessingDevice` 授权的示例代码片段：

```c
cudaMemAccessDesc desc{};
desc.flags = cudaMemAccessFlagsProtReadWrite;
desc.location.type = cudaMemLocationTypeDevice;
desc.location.id = accessingDevice;
cudaMemPoolSetAccess(memPool, &desc, 1);
```

内存池创建并授权完毕后，用户可以把创建的内存池设到 `residentDevice`，并用 `cudaMallocAsync` 开始分配内存：

```c
cudaDeviceSetMemPool(residentDevice, memPool);
cudaMallocAsync(&ptr, size, memPool, stream);
```

> **注意**
>
> EGM 用 2MB 页面映射。因此，访问非常大的分配时用户可能遇到更多 TLB 未命中。

### 4.19.2.3 多节点、多 GPU

除内存分配外，远程对端访问没有 EGM 特有的修改，遵循 CUDA 进程间（IPC）协议。IPC 的更多细节见 CUDA 编程指南。

用户应使用 `cuMemCreate` 分配内存，同样必须显式提供 `CU_MEM_LOCATION_TYPE_HOST_NUMA` 作为位置类型、`numaID` 作为位置标识符。此外还应把 `CU_MEM_HANDLE_TYPE_FABRIC` 定义为请求的句柄类型。下面的代码片段展示在节点 A 上分配物理内存：

```c
CUmemAllocationProp prop{};
prop.type = CU_MEM_ALLOCATION_TYPE_PINNED;
prop.requestedHandleTypes = CU_MEM_HANDLE_TYPE_FABRIC;
prop.location.type = CU_MEM_LOCATION_TYPE_HOST_NUMA;
prop.location.id = numaId;
size_t granularity = 0;
cuMemGetAllocationGranularity(&granularity, &prop,
                              MEM_ALLOC_GRANULARITY_MINIMUM);
size_t padded_size = ROUND_UP(size, granularity);
size_t page_size = ...;
assert(padded_size % page_size == 0);
CUmemGenericAllocationHandle allocHandle;
cuMemCreate(&allocHandle, padded_size, &prop, 0);
```

用 `cuMemCreate` 创建分配句柄后，用户可以调用 `cuMemExportToShareableHandle` 把该句柄导出到另一个节点——节点 B：

```c
cuMemExportToShareableHandle(&fabricHandle, allocHandle,
                              CU_MEM_HANDLE_TYPE_FABRIC, 0);
// 此时 fabricHandle 应经由 TCP/IP 发送到节点 B。
```

在节点 B 上，句柄可以用 `cuMemImportFromShareableHandle` 导入，并像其他 fabric 句柄一样对待：

```c
// 此时 fabricHandle 应已从节点 A 经由 TCP/IP 接收。
CUmemGenericAllocationHandle allocHandle;
cuMemImportFromShareableHandle(&allocHandle, &fabricHandle,
                                CU_MEM_HANDLE_TYPE_FABRIC);
```

句柄在节点 B 导入后，用户可以按常规方式预留地址空间并在本地映射：

```c
size_t granularity = 0;
cuMemGetAllocationGranularity(&granularity, &prop,
                              MEM_ALLOC_GRANULARITY_MINIMUM);
size_t padded_size = ROUND_UP(size, granularity);
size_t page_size = ...;
assert(padded_size % page_size == 0);
CUdeviceptr dptr;
cuMemAddressReserve(&dptr, padded_size, 0, 0, 0);
cuMemMap(dptr, padded_size, 0, allocHandle, 0);
```

最后一步，用户应给节点 B 的每个本地 GPU 授予适当的访问权限。下面是给 8 个本地 GPU 授予读写访问权限的示例代码片段：

```c
// 给所有 8 个本地 GPU 授予对位于节点 A 的导出 EGM 内存的访问权限。
CUmemAccessDesc accessDesc[8];
for (int i = 0; i < 8; i++) {
   accessDesc[i].location.type = CU_MEM_LOCATION_TYPE_DEVICE;
   accessDesc[i].location.id = i;
   accessDesc[i].flags = CU_MEM_ACCESS_FLAGS_PROT_READWRITE;
}
cuMemSetAccess(dptr, size, accessDesc, 8);
```

> **注意**
>
> 这里展示的跨节点共享是以地址为中心的：导入的分配被映射到本地虚拟地址空间，用普通的加载和存储访问。对于用 NVLink 交换网连接的 GPU，计算交换网传输（Compute fabric transport）提供了一种以资源为中心的替代方案：用异步交换网操作针对具名逻辑端点而非映射地址来搬运数据。它报告显式的每操作完成状态，适合需要交换网错误恢复的大型交换网。
