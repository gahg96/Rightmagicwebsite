# 4.16 进程间通信

由不同主机端进程管理的多个 GPU 之间的通信，通过进程间通信（IPC）API 和可 IPC 共享的内存缓冲实现：创建进程可移植的句柄，再用它获得对端 GPU 设备端内存的进程本地设备指针。

一个主机端线程创建的任何设备内存指针或事件句柄，都可以直接被同一进程内的任何其他线程引用。但设备指针或事件句柄在其创建进程之外无效，因此不能被其他进程的线程直接引用。要跨进程访问设备内存和 CUDA 事件，应用程序必须用 CUDA 进程间通信（IPC）或虚拟内存管理 API 创建进程可移植的句柄，再用标准的主机操作系统 IPC 机制（例如进程间共享内存或文件）与其他进程共享。一旦进程可移植的句柄在进程间交换完毕，就必须用 CUDA IPC 或 VMM API 从句柄获得进程本地的设备指针。之后，进程本地设备指针的用法与在单个进程内一样。

用于单节点、单个操作系统实例内 IPC 的可移植句柄方法，同样用于多节点 NVLink 互联集群中 GPU 之间的点对点（P2P）通信。在多节点场景中，通信的 GPU 由各集群节点上独立操作系统实例中运行的进程管理，需要在操作系统实例层面之上再加一层抽象。多节点对端通信通过在多节点 GPU 对端之间创建并交换所谓的"fabric"句柄实现，再在参与的进程和各多节点 rank 对应的操作系统实例内获得进程本地设备指针。

单节点 CUDA IPC 见下文；用于建立和交换进程可移植、节点和操作系统实例可移植句柄的具体 API 见虚拟内存管理（virtual memory management）一节，这些句柄用于获得 GPU 通信的进程本地设备指针。

> **注意**
>
> CUDA IPC API 和虚拟内存管理（VMM）API 用于 IPC 时各有优缺点和限制。
> CUDA IPC API 目前只在 Linux 平台上受支持。
> CUDA 虚拟内存管理 API 允许在分配内存时对每个分配的对端可访问性和共享进行精细控制，但要求使用 CUDA 驱动 API。

## 4.16.1 用传统进程间通信 API 做 IPC

要在进程间共享设备内存指针和事件，应用程序必须用 CUDA 进程间通信 API，参考手册中有详细说明。IPC API 允许应用程序用 `cudaIpcGetMemHandle()` 获取给定设备内存指针的 IPC 句柄。CUDA IPC 句柄可以用标准的主机操作系统 IPC 机制（例如进程间共享内存或文件）传给另一个进程。`cudaIpcOpenMemHandle()` 用该 IPC 句柄取回一个在另一个进程内可用的有效设备指针。事件句柄可用类似的入口点共享。

一个典型的 IPC API 用例是：单个主进程生成一批输入数据，供多个从进程使用，而无需重新生成或拷贝。

> **注意**
>
> IPC API 只在 Linux 上受支持。
> 注意 IPC API 不支持 `cudaMallocManaged` 分配。
> 用 CUDA IPC 相互通信的应用程序应使用相同的 CUDA 驱动和运行时来编译、链接和运行。
> `cudaMalloc()` 的分配可能为了性能从更大的内存块中子分配。这种情况下，CUDA IPC API 会共享整个底层内存块，可能导致其他子分配也被共享，进而造成进程间的信息泄露。为防止这种情况，建议只共享 2MiB 对齐大小的分配。
> 在计算能力 7.x 及以上的 L4T 和嵌入式 Linux Tegra 设备上，只支持 IPC 事件共享 API；IPC 内存共享 API 在 Tegra 平台上不受支持。

## 4.16.2 用虚拟内存管理 API 做 IPC

CUDA 虚拟内存管理 API 允许创建可 IPC 共享的内存分配，并通过操作系统特定的 IPC 句柄数据结构支持多个操作系统。
