# 4.11 流水线

流水线（pipeline）在"高级同步原语"（Advanced Synchronization Primitives）一节中引入，是一种暂存工作、协调多缓冲生产者–消费者模式的机制，常用于把计算与异步数据拷贝重叠。

本节主要通过 `cuda::pipeline` API 讲解流水线的用法（必要处会指向底层原语）。

## 4.11.1 初始化

`cuda::pipeline` 可以在不同的线程作用域下创建。对于除 `cuda::thread_scope_thread` 之外的作用域，需要一个 `cuda::pipeline_shared_state<scope, count>` 对象来协调参与的线程。该状态封装了有限资源，使流水线最多能同时处理 `count` 个阶段。

```cpp
// 在线程作用域创建流水线
constexpr auto scope = cuda::thread_scope_thread;
cuda::pipeline<scope> pipeline = cuda::make_pipeline();

// 在线程块作用域创建流水线
constexpr auto scope = cuda::thread_scope_block;
constexpr auto stages_count = 2;
__shared__ cuda::pipeline_shared_state<scope, stages_count> shared_state;
auto pipeline = cuda::make_pipeline(group, &shared_state);
```

流水线可以是统一的（unified）或分区的（partitioned）。在统一流水线中，所有参与的线程既是生产者又是消费者。在分区流水线中，每个参与的线程要么是生产者、要么是消费者，其角色在流水线对象的生命周期内不能改变。线程局部的流水线不能分区。要创建分区流水线，需要向 `cuda::make_pipeline()` 提供生产者数量或线程角色：

```cpp
// 在线程块作用域创建分区流水线，其中只有线程 0 是生产者
constexpr auto scope = cuda::thread_scope_block;
constexpr auto stages_count = 2;
__shared__ cuda::pipeline_shared_state<scope, stages_count> shared_state;
auto thread_role = (group.thread_rank() == 0) ? cuda::pipeline_role::producer : cuda::pipeline_role::consumer;

auto pipeline = cuda::make_pipeline(group, &shared_state, thread_role);
```

为了支持分区，共享的 `cuda::pipeline` 会带来额外开销，包括为每个阶段使用一组共享内存屏障来做同步。即使流水线是统一的、本可以用 `__syncthreads()`，这些开销也照样存在。因此，在可能的情况下，优先使用线程局部流水线以避免这些开销。

## 4.11.2 提交工作

向流水线阶段提交工作包括：

- 用 `pipeline.producer_acquire()` 从一组生产者线程集体获取流水线头（head）。
- 向流水线头提交异步操作，例如 `memcpy_async`。
- 用 `pipeline.producer_commit()` 集体提交（推进）流水线头。

如果所有资源都已用完，`pipeline.producer_acquire()` 会阻塞生产者线程，直到消费者线程释放下一个流水线阶段的资源。

## 4.11.3 消费工作

从先前提交的阶段消费工作包括：

- 从一组消费者线程集体等待该阶段完成，例如用 `pipeline.consumer_wait()` 等待尾（tail，最旧）阶段。
- 用 `pipeline.consumer_release()` 集体释放该阶段。

对于 `cuda::pipeline<cuda::thread_scope_thread>`，还可以用友元函数 `cuda::pipeline_consumer_wait_prior<N>()` 等待除最后 N 个阶段之外的所有阶段完成，类似于原语 API 中的 `__pipeline_wait_prior(N)`。

## 4.11.4 线程束纠缠

同一线程束（warp）中的 CUDA 线程共享流水线机制。这种共享导致提交的操作序列在线程束内纠缠（entanglement），在某些情况下会影响性能。

**提交。** 提交操作被合并：所有收敛（converged）并调用提交操作的线程，其流水线的序列只递增一次，它们提交的操作被批量放在一起。如果线程束完全收敛，序列递增 1，所有提交的操作会被批量放入流水线的同一个阶段；如果线程束完全分化（diverged），序列递增 32，所有提交的操作会被分散到不同的阶段。

- 设 PB 为线程束共享流水线的实际操作序列：`PB = {BP0, BP1, BP2, …, BPL}`。
- 设 TB 为某线程感知到的操作序列，仿佛序列只因该线程调用提交操作而递增：`TB = {BT0, BT1, BT2, …, BTL}`。`pipeline::producer_commit()` 的返回值来自该线程感知到的批次序列。
- 线程感知序列中的索引总是对齐到线程束共享实际序列中相等或更大的索引。只有当所有提交操作都由完全收敛的线程发起时，两个序列才相等：`BTn ≡ BPm`，其中 `n <= m`。

例如，当线程束完全分化时：

- 线程束共享流水线的实际序列为：`PB = {0, 1, 2, 3, ..., 31}`（PL=31）。
- 该线程束每个线程感知到的序列为：
  - 线程 0：`TB = {0}`（TL=0）
  - 线程 1：`TB = {0}`（TL=0）
  - ……
  - 线程 31：`TB = {0}`（TL=0）

**等待。** CUDA 线程调用 `pipeline::consumer_wait()` 或 `pipeline_consumer_wait_prior<N>()` 来等待感知序列 TB 中的批次完成。注意 `pipeline::consumer_wait()` 等价于 `N = PL` 时的 `pipeline_consumer_wait_prior<N>()`。

等待先前（wait prior）变体会等待实际序列中至少到 `PL-N`（含）的批次。由于 `TL <= PL`，等待到 `PL-N`（含）的批次就包含了等待到 `TL-N` 的批次。因此当 `TL < PL` 时，线程会无意中等待更多、更新的批次。在上面完全分化的极端例子中，每个线程可能要等全部 32 个批次。

> **注意**
>
> 建议提交调用由收敛的线程发起，使各线程感知到的批次序列与实际序列保持对齐，从而避免过度等待。当这些操作之前的代码使线程分化时，应在调用提交操作之前用 `__syncwarp` 让线程束重新收敛。

## 4.11.5 提前退出

当参与流水线的线程必须提前退出时，该线程必须在退出前用 `cuda::pipeline::quit()` 显式退出参与。其余参与线程可以正常继续后续操作。

## 4.11.6 跟踪异步内存操作

下面的例子展示如何用流水线跟踪拷贝操作，把数据用异步内存拷贝从全局内存集体拷贝到共享内存。每个线程用自己的流水线独立提交内存拷贝，再等待它们完成并消费数据。异步数据拷贝的更多细节见 3.2.5 节。

**CUDA C++ `cuda::pipeline`**

```cpp
#include <cuda/pipeline>

__global__ void example_kernel(const float *in)
{
    constexpr int block_size = 128;
    __shared__ __align__(sizeof(float)) float buffer[4 * block_size];

    // 为每个线程创建一个统一流水线
    cuda::pipeline<cuda::thread_scope_thread> pipeline = cuda::make_pipeline();

    // 第一阶段内存拷贝
    pipeline.producer_acquire();
    // 每个线程取第一块的一个元素
    cuda::memcpy_async(buffer, in, sizeof(float), pipeline);
    pipeline.producer_commit();

    // 第二阶段内存拷贝
    pipeline.producer_acquire();
    // 每个线程取第二块和第三块的一个元素
    cuda::memcpy_async(buffer + block_size, in + block_size, sizeof(float), pipeline);
    cuda::memcpy_async(buffer + 2 * block_size, in + 2 * block_size, sizeof(float), pipeline);
    pipeline.producer_commit();

    // 第三阶段内存拷贝
    pipeline.producer_acquire();
    // 每个线程取最后一块的一个元素
    cuda::memcpy_async(buffer + 3 * block_size, in + 3 * block_size, sizeof(float), pipeline);
    pipeline.producer_commit();

    // 等待最旧阶段（等待第一阶段）
    pipeline.consumer_wait();
    pipeline.consumer_release();

    // __syncthreads();
    // 使用第一阶段的数据

    // 等待最旧阶段（等待第二阶段）
    pipeline.consumer_wait();
    pipeline.consumer_release();

    // __syncthreads();
    // 使用第二阶段的数据

    // 等待最旧阶段（等待第三阶段）
    pipeline.consumer_wait();
    pipeline.consumer_release();

    // __syncthreads();
    // 使用第三阶段的数据
}
```

**CUDA C 原语**

```c
#include <cuda_pipeline.h>

__global__ void example_kernel(const float *in)
{
    constexpr int block_size = 128;
    __shared__ __align__(sizeof(float)) float buffer[4 * block_size];

    // 第一批内存拷贝
    // 每个线程取第一块的一个元素
    __pipeline_memcpy_async(buffer, in, sizeof(float));
    __pipeline_commit();

    // 第二批内存拷贝
    // 每个线程取第二块和第三块的一个元素
    __pipeline_memcpy_async(buffer + block_size, in + block_size, sizeof(float));
    __pipeline_memcpy_async(buffer + 2 * block_size, in + 2 * block_size, sizeof(float));
    __pipeline_commit();

    // 第三批内存拷贝
    // 每个线程取最后一块的一个元素
    __pipeline_memcpy_async(buffer + 3 * block_size, in + 3 * block_size, sizeof(float));
    __pipeline_commit();

    // 等待除最后两批之外的所有批次（等待第一批）
    __pipeline_wait_prior(2);

    // __syncthreads();
    // 使用第一批的数据

    // 等待除最后一批之外的所有批次（等待第二批）
    __pipeline_wait_prior(1);

    // __syncthreads();
    // 使用第二批的数据

    // 等待所有批次（等待第三批）
    __pipeline_wait_prior(0);

    // __syncthreads();
    // 使用最后一批的数据
}
```

## 4.11.7 用流水线实现生产者–消费者模式

在 4.10.7 节中，我们展示了如何把一个线程块在空间上划分、用异步屏障实现生产者–消费者模式。用 `cuda::pipeline`，可以用一个分区流水线（每个数据缓冲一个阶段）简化实现，替代每个缓冲用两个异步屏障。

**CUDA C++ `cuda::pipeline`**

```cpp
#include <cuda/pipeline>
#include <cooperative_groups.h>

#pragma nv_diag_suppress static_var_with_dynamic_init

using pipeline = cuda::pipeline<cuda::thread_scope_block>;

__device__ void produce(pipeline &pipe, int num_stages, int stage, int num_batches, int batch, float *buffer, int buffer_len, float *in, int N)
{
   if (batch < num_batches)
   {
     pipe.producer_acquire();
     /* 用异步内存拷贝把数据从 in(batch) 拷贝到 buffer(stage) */

     pipe.producer_commit();
   }
}

__device__ void consume(pipeline &pipe, int num_stages, int stage, int num_batches, int batch, float *buffer, int buffer_len, float *out, int N)
{
   pipe.consumer_wait();
   /* 消费 buffer(stage) 并更新 out(batch) */
   pipe.consumer_release();
}

__global__ void producer_consumer_pattern(float *in, float *out, int N, int buffer_len)
{
   auto block = cooperative_groups::this_thread_block();

   /* 下面声明的共享内存缓冲大小为 2 * buffer_len，
      因此可以在两个缓冲之间交替工作。
      buffer_0 = buffer，buffer_1 = buffer + buffer_len */
   __shared__ extern float buffer[];

   const int num_batches = N / buffer_len;

   // 创建一个 2 阶段的分区流水线，一半线程是生产者，另一半是消费者。
   constexpr auto scope = cuda::thread_scope_block;
   constexpr int num_stages = 2;
   cuda::std::size_t producer_count = block.size() / 2;
   __shared__ cuda::pipeline_shared_state<scope, num_stages> shared_state;
   pipeline pipe = cuda::make_pipeline(block, &shared_state, producer_count);

   // 填充流水线
   if (block.thread_rank() < producer_count)
   {
     for (int s = 0; s < num_stages; ++s)
     {
        produce(pipe, num_stages, s, num_batches, s, buffer, buffer_len, in, N);
     }
   }
}
```

本例中，线程块中一半线程做生产者，另一半做消费者。首先需要创建一个 `cuda::pipeline` 对象。由于一部分线程是生产者、一部分是消费者，需要用 `cuda::thread_scope_block` 的分区流水线。分区流水线需要一个 `cuda::pipeline_shared_state` 来协调参与的线程。我们为线程块作用域的 2 阶段流水线初始化状态，然后调用 `cuda::make_pipeline()`。接着，生产者线程用异步拷贝把数据从 `in` 提交到 `buffer`，填充流水线。此时所有数据拷贝都在进行中。最后在主循环中遍历各批次数据，根据线程是生产者还是消费者，为未来批次再提交一次异步拷贝，或消费当前批次。
