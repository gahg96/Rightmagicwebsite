# 4.9 错误日志管理

错误日志管理（error log management）让 CUDA API 错误能以通俗英语报告，相比单纯的 API 返回值，提供更多关于错误原因的信息。

## 4.9.1 背景

传统上，失败的 CUDA API 调用唯一的提示是一个非零返回码。许多 CUDA 错误码只描述了一类失败，没有指明是哪个参数或哪项要求导致了失败。错误日志管理用描述性消息补充这些返回码，帮助开发者诊断 API 用法错误。

## 4.9.2 激活

把 `CUDA_LOG_FILE` 环境变量设为 `stdout`、`stderr`，或设为一个可写文件的路径。CUDA 把每条生成的日志消息写入选定的目标。

CUDA 还在内部缓冲区中保存最近的消息。应用程序可以用错误日志管理 API 注册回调或转储该缓冲区，即使应用程序启动前没有设置 `CUDA_LOG_FILE` 也一样。没有错误的执行可能不产生任何消息。

## 4.9.3 输出

写入 `CUDA_LOG_FILE` 或由转储 API 返回的消息使用以下格式：

```
[Time][TID][Source][Severity] Message
```

例如，用空缓冲区调用 `cuLogsDumpToMemory` 可能产生类似如下的消息：

```
[22:21:32.099][25642][CUDA][E] buffer cannot be NULL
[22:21:32.099][25642][CUDA][E] Returning 1 (CUDA_ERROR_INVALID_VALUE) from cuLogsDumpToMemory
```

没有错误日志管理时，该调用返回 `CUDA_ERROR_INVALID_VALUE`。调用 `cuGetErrorString` 会得到通用描述 "invalid argument"，但说不清是哪个参数无效。

## 4.9.4 API 说明

错误日志管理同时通过 CUDA 驱动 API 和运行时 API 提供。运行时接口处理运行时 API 和驱动 API 生成的消息；两种接口使用同一个底层日志缓冲区。

### 4.9.4.1 回调注册

驱动 API 的回调类型和注册函数如下：

```c
typedef void (CUDA_CB *CUlogsCallback)(
    void *data, CUlogLevel logLevel, char *message, size_t length);

CUresult CUDAAPI cuLogsRegisterCallback(
    CUlogsCallback callbackFunc,
    void *userData,
    CUlogsCallbackHandle *callback_out);

CUresult CUDAAPI cuLogsUnregisterCallback(
    CUlogsCallbackHandle callback);
```

对应的运行时 API 回调类型和函数如下：

```c
typedef void (CUDART_CB *cudaLogsCallback_t)(
    void *data, cudaLogLevel logLevel, char *message, size_t length);

cudaError_t CUDARTAPI cudaLogsRegisterCallback(
    cudaLogsCallback_t callbackFunc,
    void *userData,
    cudaLogsCallbackHandle *callback_out);

cudaError_t CUDARTAPI cudaLogsUnregisterCallback(
    cudaLogsCallbackHandle callback);
```

驱动回调把错误报告为 `CU_LOG_LEVEL_ERROR`，警告报告为 `CU_LOG_LEVEL_WARNING`。对应的运行时值为 `cudaLogLevelError` 和 `cudaLogLevelWarning`。格式化输出中这些级别分别表示为 `E` 和 `W`。

CUDA 把 `userData` 原样传给回调。`callback_out` 参数可选，但如果应用程序打算注销回调，就必须保留返回的句柄。回调收到消息文本和显式字节长度。消息不包含格式化文件和转储输出中附加的时间戳、线程 ID、来源或严重性前缀。除非 API 参考明确保证，否则应用程序不应依赖特定的回调线程或调用时机。

### 4.9.4.2 迭代器与日志转储

日志迭代器标识内部缓冲区中的一个位置。调用 `cuLogsCurrent` 或 `cudaLogsCurrent` 把迭代器设为缓冲区的当前末尾，这样之后用该迭代器转储只返回随后生成的消息。

驱动 API 函数如下：

```c
CUresult CUDAAPI cuLogsCurrent(
    CUlogIterator *iterator_out, unsigned int flags);

CUresult CUDAAPI cuLogsDumpToFile(
    CUlogIterator *iterator,
    const char *pathToFile,
    unsigned int flags);

CUresult CUDAAPI cuLogsDumpToMemory(
    CUlogIterator *iterator,
    char *buffer,
    size_t *size,
    unsigned int flags);
```

对应的运行时 API 函数如下：

```c
cudaError_t CUDARTAPI cudaLogsCurrent(
    cudaLogIterator *iterator_out, unsigned int flags);

cudaError_t CUDARTAPI cudaLogsDumpToFile(
    cudaLogIterator *iterator,
    const char *pathToFile,
    unsigned int flags);

cudaError_t CUDARTAPI cudaLogsDumpToMemory(
    cudaLogIterator *iterator,
    char *buffer,
    size_t *size,
    unsigned int flags);
```

所有 current 和 dump 函数的 `flags` 参数保留供将来使用，必须为零。下面的运行时 API 示例标记日志的当前末尾，稍后只转储该点之后生成的消息：

```c
#include <cstdio>
#include <cuda_runtime_api.h>

cudaError_t printNewCudaLogs()
{
    cudaLogIterator iterator;
    cudaError_t status = cudaLogsCurrent(&iterator, 0);
    if (status != cudaSuccess) {
        return status;
    }

    int deviceCount;
    status = cudaGetDeviceCount(&deviceCount);
    cudaError_t deviceCountStatus = status;

    char buffer[25600];
    size_t size = sizeof(buffer);
    status = cudaLogsDumpToMemory(&iterator, buffer, &size, 0);
    if (status != cudaSuccess) {
        return status;
    }
    if (size != 0) {
        std::fwrite(buffer, 1, size, stderr);
    }
    return deviceCountStatus;
}
```

中间的 CUDA 调用仍需按常规处理返回码。本例展示迭代器如何选取日志消息的一个窗口；并不需要故意发起一次无效的 CUDA 调用。定长数组使用了文档记载的最大转储容量 25,600 字节。

### 4.9.4.3 转储行为

如果 `iterator` 为空，转储请求内部缓冲区当前保留的所有条目。如果提供了迭代器，转储从该位置开始。转储成功后，CUDA 把提供的迭代器推进到日志的当前末尾。

内部缓冲区至多保留 100 条。如果请求的消息已被覆盖、不再保留，CUDA 会添加一条截断提示，并返回仍可用的条目。

`cuLogsDumpToMemory` 和 `cudaLogsDumpToMemory` 还有以下要求：

1. `size` 初始指定 `buffer` 的容量。
2. CUDA 会给缓冲区加 null 终止符。各条目之间用换行符而不是 null 字符分隔。
3. 25,600 字节的输出缓冲区足以容纳所有保留的日志数据。
4. 成功时，`size` 包含写入的字节数，不含终止的 null 字符。
5. 如果没有可转储的消息，函数成功并把 `size` 设为零。
6. 如果缓冲区能容纳部分但不是全部请求的消息，CUDA 会在前面加上截断提示，省略装不下的最旧消息，并在输出中保留最新的消息。
7. 如果缓冲区一条消息也装不下，函数返回 `CUDA_ERROR_INVALID_VALUE` 或 `cudaErrorInvalidValue`，并把 `size` 设为零。

## 4.9.5 限制与已知问题

1. 达到 100 条上限时，CUDA 替换最旧的条目。
2. 并非所有 CUDA API 都会生成描述性消息。覆盖范围还在持续扩大。
3. 在生成消息之前，CUDA 不验证 `CUDA_LOG_FILE` 的目标。
4. 日志消息不做本地化；CUDA 以美式英语提供。
