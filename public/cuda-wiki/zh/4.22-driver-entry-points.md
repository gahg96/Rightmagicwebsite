# 4.22 驱动程序入口点访问

## 4.22.1 介绍

驱动程序入口点访问 API 提供了一种获取 CUDA 驱动函数地址的方法。从 CUDA 11.3 起，用户可以通过这些 API 获得的函数指针，调用可用的 CUDA 驱动 API。

这些 API 的功能类似于 POSIX 平台上的 `dlsym` 和 Windows 上的 `GetProcAddress`。提供的 API 使用户能够：

- 使用 CUDA 驱动 API 获取驱动函数的地址；
- 使用 CUDA 运行时 API 获取驱动函数的地址；
- 请求 CUDA 驱动函数的按线程默认流（per-thread default stream）版本。详情见“获取按线程默认流版本”；
- 在较旧的工具包上、配合较新的驱动程序，访问新的 CUDA 特性。

## 4.22.2 驱动函数类型定义

为了帮助获取 CUDA 驱动 API 的入口点，CUDA 工具包提供了一组头文件，其中包含所有 CUDA 驱动 API 的函数指针定义。这些头文件随 CUDA 工具包安装，位于工具包的 `include/` 目录下。下表汇总了每个 CUDA API 头文件对应的类型定义头文件。

表 27：CUDA 驱动 API 的类型定义头文件

| API 头文件 | API 类型定义头文件 |
|---|---|
| cuda.h | cudaTypedefs.h |
| cudaGL.h | cudaGLTypedefs.h |
| cudaProfiler.h | cudaProfilerTypedefs.h |
| cudaVDPAU.h | cudaVDPAUTypedefs.h |
| cudaEGL.h | cudaEGLTypedefs.h |
| cudaD3D9.h | cudaD3D9Typedefs.h |
| cudaD3D10.h | cudaD3D10Typedefs.h |
| cudaD3D11.h | cudaD3D11Typedefs.h |

上述头文件并不定义实际的函数指针本身，而是定义函数指针的类型定义。例如，`cudaTypedefs.h` 中有驱动 API `cuMemAlloc` 的以下类型定义：

```cuda
typedef CUresult (CUDAAPI *PFN_cuMemAlloc_v3020)(CUdeviceptr_v2 *dptr, size_t bytesize);
typedef CUresult (CUDAAPI *PFN_cuMemAlloc_v2000)(CUdeviceptr_v1 *dptr, unsigned int bytesize);
```

CUDA 驱动符号采用基于版本的命名方案，名称中带有 `_v*` 后缀，第一个版本除外。当某个 CUDA 驱动 API 的签名或语义发生变化时，对应的驱动符号版本号会递增。以 `cuMemAlloc` 驱动 API 为例，第一个驱动符号名是 `cuMemAlloc`，下一个符号名是 `cuMemAlloc_v2`。第一个版本在 CUDA 2.0（2000）中引入，其类型定义是 `PFN_cuMemAlloc_v2000`；下一个版本在 CUDA 3.2（3020）中引入，其类型定义是 `PFN_cuMemAlloc_v3020`。在代码中可以用这些类型定义更方便地定义适当类型的函数指针：

```cuda
PFN_cuMemAlloc_v3020 pfn_cuMemAlloc_v2;
PFN_cuMemAlloc_v2000 pfn_cuMemAlloc_v1;
```

## 4.22.3 驱动函数获取

使用驱动程序入口点访问 API 和适当的类型定义，可以获得任意 CUDA 驱动 API 的函数指针。

### 4.22.3.1 使用驱动 API

驱动 API 需要传入 CUDA 版本作为参数，以获取请求驱动符号的 ABI 兼容版本。CUDA 驱动 API 的每个函数都有用 `_v*` 后缀表示的 ABI 版本。例如，考虑 `cuStreamBeginCapture` 的各版本及其在 `cudaTypedefs.h` 中的对应类型定义：

```cuda
// cuda.h
CUresult CUDAAPI cuStreamBeginCapture(CUstream hStream);
CUresult CUDAAPI cuStreamBeginCapture_v2(CUstream hStream, CUstreamCaptureMode mode);

// cudaTypedefs.h
typedef CUresult (CUDAAPI *PFN_cuStreamBeginCapture_v10000)(CUstream hStream);
typedef CUresult (CUDAAPI *PFN_cuStreamBeginCapture_v10010)(CUstream hStream, CUstreamCaptureMode mode);
```

从代码片段中的上述类型定义可以看出，版本后缀 `_v10000` 和 `_v10010` 表示上述 API 分别在 CUDA 10.0 和 CUDA 10.1 中引入。

```cuda
#include <cudaTypedefs.h>

// 声明 cuStreamBeginCapture 的入口点
PFN_cuStreamBeginCapture_v10000 pfn_cuStreamBeginCapture_v1;
PFN_cuStreamBeginCapture_v10010 pfn_cuStreamBeginCapture_v2;

// 获取 cuStreamBeginCapture 驱动符号的函数指针
cuGetProcAddress("cuStreamBeginCapture", &pfn_cuStreamBeginCapture_v1, 10000,
                 CU_GET_PROC_ADDRESS_DEFAULT, &driverStatus);

// 获取 cuStreamBeginCapture_v2 驱动符号的函数指针
cuGetProcAddress("cuStreamBeginCapture", &pfn_cuStreamBeginCapture_v2, 10010,
                 CU_GET_PROC_ADDRESS_DEFAULT, &driverStatus);
```

参照上面的代码片段：要获取驱动 API `cuStreamBeginCapture` 的 `_v1` 版本地址，CUDA 版本参数应恰好为 10.0（10000）。同样，获取该 API 的 `_v2` 版本地址时，CUDA 版本应为 10.1（10010）。为获取驱动 API 的特定版本而指定更高的 CUDA 版本，并不总是可移植的。例如，这里传入 11030 仍会返回 `_v2` 符号，但如果 CUDA 11.3 发布了假设的 `_v3` 版本，`cuGetProcAddress` API 在配合 CUDA 11.3 驱动时就会改为返回新的 `_v3` 符号。由于 `_v2` 和 `_v3` 符号的 ABI 与函数签名可能不同，用为 `_v2` 符号准备的 `_v10010` 类型定义去调用 `_v3` 函数会导致未定义行为。

注意，用无效的 CUDA 版本请求驱动 API 会返回 `CUDA_ERROR_NOT_FOUND` 错误。在上面的代码示例中，传入小于 10000（CUDA 10.0）的版本都是无效的。
### 4.22.3.2 使用运行时 API

运行时 API `cudaGetDriverEntryPointByVersion` 用提供的 CUDA 版本获取请求驱动符号的 ABI 兼容版本，方式与 `cuGetProcAddress` 相同。在下面的代码片段中，所需的最低 CUDA 版本是 CUDA 11.2，因为 `cuMemAllocAsync` 在那时引入。

```cuda
#include <cudaTypedefs.h>

int cudaVersion;
// 确保已安装 CUDA 驱动 >= 11.2，否则 cuGetProcAddress 会报错
status = cuDriverGetVersion(&cudaVersion);
if (cudaVersion >= 11020) {
    // 声明入口点
    PFN_cuMemAllocAsync_v11020 pfn_cuMemAllocAsync;

    // 初始化入口点
    cudaGetDriverEntryPointByVersion("cuMemAllocAsync", &pfn_cuMemAllocAsync,
                                     11020, cudaEnableDefault, &driverStatus);

    // 调用入口点
    if (driverStatus == cudaDriverEntryPointSuccess && pfn_cuMemAllocAsync) {
        pfn_cuMemAllocAsync(...);
    }
}
```

### 4.22.3.3 获取按线程默认流版本

有些 CUDA 驱动 API 可以配置为具有默认流或按线程默认流语义。具有按线程默认流语义的驱动 API 其名称带有 `_ptsz` 或 `_ptds` 后缀。例如，`cuLaunchKernel` 的按线程默认流变体名为 `cuLaunchKernel_ptsz`。使用驱动程序入口点访问 API，用户可以请求驱动 API `cuLaunchKernel` 的按线程默认流版本，而不是默认流版本。为 CUDA 驱动 API 配置默认流或按线程默认流语义会影响同步行为。更多详情见此处。

可以通过以下任一方式获得驱动 API 的默认流或按线程默认流版本：

- 使用编译标志 `--default-stream per-thread`，或定义宏 `CUDA_API_PER_THREAD_DEFAULT_STREAM`，以获得按线程默认流行为；
- 分别使用标志 `CU_GET_PROC_ADDRESS_LEGACY_STREAM`/`cudaEnableLegacyStream` 或 `CU_GET_PROC_ADDRESS_PER_THREAD_DEFAULT_STREAM`/`cudaEnablePerThreadDefaultStream`，强制使用默认流或按线程默认流行为。

### 4.22.3.4 访问新的 CUDA 特性

要访问新的 CUDA 驱动特性，始终建议安装最新的 CUDA 工具包；但如果用户由于某种原因不想更新或无法获取最新工具包，可以只用更新后的 CUDA 驱动来访问新的 CUDA 特性。举例说明：假设用户使用 CUDA 12.3，想使用 CUDA 12.5 驱动中的新驱动 API `cuFoo`。下面的代码片段说明了这个用例：

```cuda
int main()
{
    // 手动定义原型，因为 CUDA 12.3 的 cudaTypedefs.h 中没有 cuFoo 的类型定义
    typedef CUresult (CUDAAPI *PFN_cuFoo_v12050)(...);
    PFN_cuFoo_v12050 pfn_cuFoo = NULL;
    CUdriverProcAddressQueryResult driverStatus;
    int cudaVersion;

    // 确保已安装 CUDA 驱动 >= 12.5，否则 cuGetProcAddress 会报错
    CUresult status = cuDriverGetVersion(&cudaVersion);
    if (cudaVersion >= 12050) {
        // 用 cuGetProcAddress 获取 cuFoo API 的地址。CUDA 版本指定为
        // 12050，因为 cuFoo 在该版本引入
        CUresult status = cuGetProcAddress("cuFoo", &pfn_cuFoo, 12050,
                                           CU_GET_PROC_ADDRESS_DEFAULT,
                                           &driverStatus);

        if (status == CUDA_SUCCESS && pfn_cuFoo) {
            pfn_cuFoo(...);
        }
        else {
            printf("Cannot retrieve the address to cuFoo - driverStatus = %d\n", driverStatus);
            assert(0);
        }
    }

    // 其余代码
}
```

下一个示例讨论如何获取在 CUDA 工具包的小版本中发布的新版本 API。注意，`cuda.h` 头文件中直到大版本边界才会增加把 `cuDeviceGetUuid` 升级到 `_v2` 的版本宏。因此在 11.4 及以上版本期间，下面的示例说明如何获取 `_v2` 版本。

注意，这里原始（非 `_v2` 版本）的类型定义如下：

```cuda
typedef CUresult (CUDAAPI *PFN_cuDeviceGetUuid_v9020)(CUuuid *uuid, CUdevice_v1 dev);
```

而 `_v2` 版本的类型定义如下：

```cuda
typedef CUresult (CUDAAPI *PFN_cuDeviceGetUuid_v11040)(CUuuid *uuid, CUdevice_v1 dev);
```

```cuda
#include <cudaTypedefs.h>

CUuuid uuid;
CUdevice dev;
CUresult status;
int cudaVersion;
CUdriverProcAddressQueryResult driverStatus;

status = cuDeviceGet(&dev, 0); // 获取设备 0
// 处理 status

// 确保已安装 CUDA 驱动 >= 11.4，否则 cuGetProcAddress 会报错
status = cuDriverGetVersion(&cudaVersion);
if (cudaVersion >= 11040) {
    PFN_cuDeviceGetUuid_v11040 pfn_cuDeviceGetUuid;
    status = cuGetProcAddress("cuDeviceGetUuid", &pfn_cuDeviceGetUuid, 11040,
                              CU_GET_PROC_ADDRESS_DEFAULT, &driverStatus);
    if (CUDA_SUCCESS == status && pfn_cuDeviceGetUuid) {
        pfn_cuDeviceGetUuid(&uuid, dev);
    }
}
```

## 4.22.4 cuGetProcAddress 使用指南

使用 `cuGetProcAddress` 时应牢记以下指南：

- 传入 `cuGetProcAddress` 的 CUDA 版本要与类型定义版本匹配（不要使用 `CUDA_VERSION` 之类的编译期常量，也不要使用 `cuDriverGetVersion` 返回的动态版本）；
- 调用 `cuGetProcAddress` 之前，先检查当前驱动版本（如通过 `cuDriverGetVersion` 获取）是否足够，否则预期会报错或返回意外的符号。

### 4.22.4.1 运行时 API 使用指南

除非另有说明，CUDA 运行时 API `cudaGetDriverEntryPointByVersion` 遵循与驱动入口点 `cuGetProcAddress` 类似的指南，因为它同样允许用户请求特定 CUDA 驱动版本。

## 4.22.5 确定 cuGetProcAddress 的失败原因

`cuGetProcAddress` 有两类错误：一是 API/用法错误，二是找不到请求的驱动 API。第一类错误通过 API 的 `CUresult` 返回值返回错误码，例如 `pfn` 变量传 NULL 或传入无效标志。

第二类错误编码在 `CUdriverProcAddressQueryResult *symbolStatus` 中，可用于帮助区分驱动程序找不到所请求符号的潜在问题。看下面的示例：

```cuda
// cuDeviceGetExecAffinitySupport 在 CUDA 11.4 中引入
#include <cuda.h>
CUdriverProcAddressQueryResult driverStatus;
cudaVersion = ...;
status = cuGetProcAddress("cuDeviceGetExecAffinitySupport", &pfn, cudaVersion,
                          0, &driverStatus);

if (CUDA_SUCCESS == status) {
    if (CU_GET_PROC_ADDRESS_VERSION_NOT_SUFFICIENT == driverStatus) {
        printf("We can use the new feature when you upgrade cudaVersion to 11.4, but CUDA driver is good to go!\n");
        // 表示 cudaVersion < 11.4，但运行时的 CUDA 驱动 >= 11.4
    }
    else if (CU_GET_PROC_ADDRESS_SYMBOL_NOT_FOUND == driverStatus) {
        printf("Please update both CUDA driver and cudaVersion to at least 11.4 to use the new feature!\n");
        // 表示驱动 < 11.4，因为没找到该字符串，此时 cudaVersion 是多少都无所谓
    }
    else if (CU_GET_PROC_ADDRESS_SUCCESS == driverStatus && pfn) {
        printf("You're using cudaVersion and CUDA driver >= 11.4, using new feature!\n");
        pfn();
    }
}
```

第一种情况，返回码 `CU_GET_PROC_ADDRESS_VERSION_NOT_SUFFICIENT` 表示在 CUDA 驱动中找到了该符号，但它是在所提供的 `cudaVersion` 之后才加入的。在上面的示例中，把 `cudaVersion` 指定为 11030 或更小，同时运行在 CUDA 驱动 >= CUDA 11.4 的环境下，就会得到这个结果，因为 `cuDeviceGetExecAffinitySupport` 是在 CUDA 11.4（11040）中加入的。

第二种情况，返回码 `CU_GET_PROC_ADDRESS_SYMBOL_NOT_FOUND` 表示在 CUDA 驱动中没有找到该符号。原因可能有几个，例如驱动太旧不支持该 CUDA 函数，或者只是拼写错误。后一种情况：与上例类似，如果用户把符号写成 `CUDeviceGetExecAffinitySupport`——注意字符串开头是大写的 CU——`cuGetProcAddress` 就找不到该 API，因为字符串不匹配。前一种情况：开发者在支持新 API 的 CUDA 驱动上开发应用，但部署到更旧的 CUDA 驱动上。用上例来说，开发者在 CUDA 11.4 或更新版本上开发时 `cuGetProcAddress` 可能成功，但把应用部署到 CUDA 11.3 驱动上运行时，该调用就会失效，并在 `driverStatus` 中返回 `CU_GET_PROC_ADDRESS_SYMBOL_NOT_FOUND`。
