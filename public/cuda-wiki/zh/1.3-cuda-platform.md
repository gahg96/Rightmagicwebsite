# 1.3 CUDA 平台

NVIDIA CUDA 平台由许多软硬件部件以及为异构系统计算开发的重要技术组成。本章介绍应用程序开发者需要理解的一些基本概念与 CUDA 平台组件。本章与编程模型一章一样，与具体编程语言无关，适用于一切使用 CUDA 平台的场景。

## 1.3.1 计算能力与流多处理器（SM）版本

每块 NVIDIA GPU 都有一个计算能力（Compute Capability，CC）编号，它表示该 GPU 支持哪些功能，并指定该 GPU 的一些硬件参数。这些规格记录在 5.1 节附录中。CUDA GPU 计算能力页面维护了所有 NVIDIA GPU 及其计算能力的列表。

计算能力以主版本号和次版本号的形式表示，格式为 X.Y，其中 X 是主版本号，Y 是次版本号。例如，CC 12.0 的主版本号为 12，次版本号为 0。计算能力直接对应 SM 的版本号。例如，CC 12.0 GPU 中的 SM 的 SM 版本为 sm_120。这个版本用于标记二进制文件。

5.1.1 节介绍如何查询和确定系统中 GPU 的计算能力。

## 1.3.2 CUDA Toolkit 与 NVIDIA 驱动

NVIDIA 驱动可以看作 GPU 的操作系统。NVIDIA 驱动是必须安装在主机端系统操作系统上的软件组件，是包括显示与图形功能在内的所有 GPU 用途所必需的。NVIDIA 驱动是 CUDA 平台的基础。除了 CUDA 之外，NVIDIA 驱动还提供了使用 GPU 的所有其他方式，例如 Vulkan 和 Direct3D。NVIDIA 驱动有 r580 这样的版本号。

CUDA Toolkit 是用于编写、构建和分析利用 GPU 计算的软件的一组库、头文件和工具。CUDA Toolkit 与 NVIDIA 驱动是独立的软件产品。

CUDA 运行时（CUDA runtime）是 CUDA Toolkit 所提供库中的一种特殊情况。CUDA 运行时提供 API 和一些语言扩展，用于处理分配内存、在 GPU 与其他 GPU 或 CPU 之间复制数据、启动核函数等常见任务。CUDA 运行时的 API 部分称为 CUDA 运行时 API。

CUDA 兼容性文档详细说明了不同 GPU、NVIDIA 驱动与 CUDA Toolkit 版本之间的兼容关系。

### 1.3.2.1 CUDA 运行时 API 与 CUDA 驱动 API

CUDA 运行时 API 实现在一个更底层的 API 之上，称为 CUDA 驱动 API，它是 NVIDIA 驱动暴露的 API。本指南重点介绍 CUDA 运行时 API 暴露的 API。如果需要，只用驱动 API 也能实现同样的功能。有些功能只能通过驱动 API 使用。应用程序可以使用任意一种 API，也可以两种混用。CUDA 驱动 API 一节介绍了运行时 API 与驱动 API 的互操作。

CUDA 运行时 API 函数的完整 API 参考见 CUDA 运行时 API 文档。

CUDA 驱动 API 的完整 API 参考见 CUDA 驱动 API 文档。

## 1.3.3 并行线程执行（PTX）

CUDA 平台中一个基础但有时不可见的层次是并行线程执行（Parallel Thread Execution，PTX）虚拟指令集架构（ISA）。PTX 是 NVIDIA GPU 的高级汇编语言。PTX 在真实 GPU 硬件的物理 ISA 之上提供了一层抽象。与其他平台一样，应用程序可以直接用这种汇编语言编写，但这样做会给软件开发带来不必要的复杂性。

领域专用语言和高级语言编译器可以生成 PTX 代码作为中间表示（IR），然后使用 NVIDIA 的离线或即时（JIT）编译工具生成可执行的 GPU 二进制代码。这样，CUDA 平台不仅能用 NVIDIA 提供的工具（如 NVIDIA CUDA 编译器 NVCC）支持的语言编程，还能用其他语言编程。

由于 GPU 能力随时间不断发展，PTX 虚拟 ISA 规范是有版本的。PTX 版本与 SM 版本一样，对应一个计算能力。例如，支持计算能力 8.0 全部特性的 PTX 称为 compute_80。

PTX 的完整文档见 PTX ISA。

## 1.3.4 Cubin 与 Fatbin

CUDA 应用程序和库通常用 C++ 等高级语言编写。高级语言先编译为 PTX，再由 PTX 编译成真实 GPU 的二进制代码，称为 CUDA 二进制文件，简称 cubin。cubin 是针对特定 SM 版本（如 sm_120）的特定二进制格式。

使用 GPU 计算的可执行文件和库二进制文件同时包含 CPU 代码与 GPU 代码。GPU 代码存放在一个称为 fatbin 的容器中。fatbin 可以包含面向多个不同目标的 cubin 和 PTX。例如，一个应用程序可以用多个不同 GPU 架构（即不同 SM 版本）的二进制构建。应用程序运行时，其 GPU 代码被加载到特定的 GPU 上，使用 fatbin 中为该 GPU 最合适的二进制。

fatbin 还可以包含一个或多个 PTX 版本的 GPU 代码，其用途在 PTX 兼容性一节中介绍。图 10 展示了一个应用程序或库二进制的例子，其中包含多个 cubin 版本的 GPU 代码和一个版本的 PTX 代码。

### 1.3.4.1 二进制兼容性

NVIDIA GPU 在某些情况下保证二进制兼容。具体来说，在同一个计算能力主版本内，次版本号大于或等于 cubin 目标版本的 GPU 可以加载并执行该 cubin。例如，如果一个应用程序包含为计算能力 8.6 编译的 cubin，该 cubin 可以在计算能力 8.6 或 8.9 的 GPU 上加载和执行。但它不能在计算能力 8.0 的 GPU 上加载，因为该 GPU 的 CC 次版本号 0 低于代码的次版本号 6。

不同计算能力主版本之间，NVIDIA GPU 不保证二进制兼容。也就是说，为计算能力 8.6 编译的 cubin 代码不能在计算能力 9.0 的 GPU 上加载。

讨论二进制代码时，二进制代码常被描述为具有 sm_86 这样的版本，与上例相同，即表示该二进制是为计算能力 8.6 构建的。这种简写很常用，因为这是开发者向 NVIDIA CUDA 编译器 nvcc 指定二进制构建目标的方式。

> **注意**
>
> 二进制兼容性仅承诺给 NVIDIA 工具（如 nvcc）生成的二进制。手动编辑或生成 NVIDIA GPU 二进制代码不受支持。二进制一旦被以任何方式修改，兼容性承诺即失效。

### 1.3.4.2 PTX 兼容性

如 cubin 与 fatbin 一节所述，GPU 代码可以以二进制或 PTX 形式存储在可执行文件中。当应用程序存储了 GPU 代码的 PTX 版本时，该 PTX 可以在应用程序运行时为等于或高于 PTX 计算能力的任何计算能力做 JIT 编译。例如，如果应用程序包含 compute_80 的 PTX，该 PTX 代码可以在应用程序运行时 JIT 编译到更新的 SM 版本，如 sm_120。这样无需重建应用程序或库，就能向前兼容未来的 GPU。

### 1.3.4.3 即时编译

应用程序在运行时加载的 PTX 代码由设备驱动编译为二进制代码，这称为即时（just-in-time，JIT）编译。即时编译增加了应用程序的加载时间，但让应用程序能受益于每个新设备驱动带来的编译器改进。它还使应用程序能在编译时不存在的设备上运行。

设备驱动为应用程序即时编译 PTX 代码时，会自动缓存生成的二进制代码副本，避免应用程序后续调用时重复编译。这个缓存称为计算缓存（compute cache），在设备驱动升级时会自动失效，以便应用程序能受益于新设备驱动中即时编译器的改进。

相比 CUDA 早期版本，PTX 在运行时何时、以何种方式做 JIT 编译已经放宽，允许更灵活地决定何时、是否为部分或全部核函数做 JIT 编译。懒加载（Lazy Loading）一节介绍了可用选项及如何控制 JIT 行为。还有一些环境变量控制即时编译行为，见 CUDA 环境变量。

除了用 nvcc 编译 CUDA C++ 设备端代码，还可以用 NVRTC 在运行时把 CUDA C++ 设备端代码编译为 PTX。NVRTC 是 CUDA C++ 的运行时编译库，更多信息见 NVRTC 用户指南。

### 1.3.4.4 二进制终定

从计算能力 10.0 开始，族内（intra-family）二进制兼容性由 NVIDIA 驱动以软件方式管理。CC 10.0 及更新架构的 cubin 使用扩展的二进制格式，扩展了二进制表示以提供族内二进制兼容性。为特定目标架构生成（终定，finalized）的二进制可以直接在目标架构上执行，也可以在运行时重新终定到族内任何保证二进制兼容的 GPU 上。计算能力 9.x 及更早的 cubin 不支持运行时重新终定。

当为 CC 10.0 或更高版本、为一个目标架构生成的 cubin，被加载到同一 GPU 家族中不同但兼容的架构上时，驱动执行即时终定，把该 cubin 绑定到目标 GPU 的架构上。这个过程称为异目标终定（off-target finalization）。异目标终定支持异目标执行：为一个架构终定的 cubin 可以在同一 GPU 家族中另一个兼容的架构上运行。当 cubin 被加载到为其生成的架构上时，执行被视为在目标（on-target）执行，无需进一步终定。

异目标执行的即时终定不应与 PTX 即时编译混淆。PTX JIT 编译把 PTX 代码编译为已经为目标架构终定的 GPU 二进制代码；而 cubin 的异目标终定是把已有的 cubin 为另一个兼容架构重新终定。异目标终定的开销远小于 PTX JIT 编译，但相比在目标执行，仍可能增加模块加载时间。

异目标终定的开销取决于终定的代码量、模块加载期间可用的主机端 CPU 资源，以及源架构与目标架构之间的关系。加载大型模块或大量模块的应用程序，在 cubin 被异目标终定时，可能会观察到启动时间增加。

与 PTX JIT 编译一样，NVIDIA 驱动可能缓存 cubin 异目标终定的结果，避免应用程序后续调用时重复终定工作。该缓存由 5.2.2 节描述的 CUDA 缓存环境变量控制。
