# 4.4 协作组（Cooperative Groups）

## 4.4.1 简介

协作组是 CUDA 编程模型的扩展，用于组织协作的线程组。协作组允许开发者控制线程协作的粒度，帮助他们表达更丰富、更高效的并行分解。协作组还提供了常见并行原语（如扫描和并行归约）的实现。

历史上，CUDA 编程模型只提供了一种简单的结构来同步协作的线程：使用 `__syncthreads()` 内建函数在线程块的所有线程之间设置屏障。为了表达更广泛的并行交互模式，许多注重性能的程序员不得不编写自己临时拼凑的、不安全的原语，来同步单个线程束（warp）内的线程，或运行在单个 GPU 上的多组线程块。这种做法取得的性能提升往往很有价值，但也导致脆弱代码越积越多，编写、调优和长期维护的成本越来越高，且难以跨 GPU 代际延续。协作组提供了一种安全且面向未来的机制来编写高性能代码。

完整的协作组 API 见《协作组 API》（Cooperative Groups API）。

## 4.4.2 协作组句柄与成员函数

协作组通过协作组句柄（Cooperative Group Handle）管理。协作组句柄允许参与的线程获知自己在组中的位置、组的大小以及其他组信息。下表展示了部分组成员函数。

**表 10：部分成员函数**

| 访问器 | 返回 |
|---|---|
| `thread_rank()` | 调用线程的序号。 |
| `num_threads()` | 组中线程的总数。 |
| `thread_index()` | 线程在已启动线程块内的三维索引。 |
| `dim_threads()` | 已启动线程块以线程为单位的三维尺寸。 |

完整的成员函数列表见《协作组 API》。

## 4.4.3 默认行为/无组执行

表示网格和线程块的组会根据核函数启动配置隐式创建。这些"隐式"组为开发者提供了一个起点，可以将其显式分解为更细粒度的组。可以用以下方法访问隐式组：

**表 11：CUDA 运行时隐式创建的协作组**

| 访问器 | 组范围 |
|---|---|
| `this_thread_block()` | 返回包含当前线程块中所有线程的组的句柄。 |
| `this_grid()` | 返回包含网格中所有线程的组的句柄。 |
| `coalesced_threads()`¹ | 返回线程束中当前活动线程的组的句柄。 |
| `this_cluster()`² | 返回当前集群中线程的组的句柄。 |

更多信息见《协作组 API》。

¹ `coalesced_threads()` 操作符返回该时刻的活动线程集合，不保证返回哪些线程（只要它们是活动的），也不保证它们在执行过程中始终保持合并。

² `this_cluster()` 在启动非集群网格时假设为 1x1x1 集群。需要计算能力 9.0 或更高。

### 4.4.3.1 尽早创建隐式组句柄

为了获得最佳性能，建议尽早（任何分支发生之前）为隐式组创建句柄，并在整个核函数中使用该句柄。

### 4.4.3.2 只通过引用传递组句柄

建议在将组句柄传入函数时通过引用传递。组句柄必须在声明时初始化，因为它没有默认构造函数。不鼓励拷贝构造组句柄。

## 4.4.4 创建协作组

组通过将父组划分为子组来创建。划分组时，会创建一个组句柄来管理生成的子组。开发者可以使用以下划分操作：

**表 12：协作组划分操作**

| 分区类型 | 说明 |
|---|---|
| `tiled_partition` | 将父组划分为一系列固定大小的子组，按一维行优先格式排列。 |
| `labeled_partition` | 基于条件标签将父组划分为一维子组，标签可以是任意整数类型。 |
| `binary_partition` | 标记分区的特殊形式，标签只能是 "0" 或 "1"。 |

以下示例展示如何创建平铺分区（tiled partition）：

```cpp
namespace cg = cooperative_groups;
// 获取当前线程的协作组
cg::thread_block my_group = cg::this_thread_block();

// 将协作组划分为大小为 8 的平铺
cg::thread_block_tile<8> my_subgroup = cg::tiled_partition<8>(my_group);

// 以 my_subgroup 的身份执行工作
```

使用哪种划分策略最好取决于上下文。更多信息见《协作组 API》。

### 4.4.4.1 避免组创建风险

划分组是一个集合操作，组中的所有线程都必须参与。如果组是在并非所有线程都能到达的条件分支中创建的，可能导致死锁或数据损坏。

## 4.4.5 同步

在协作组引入之前，CUDA 编程模型只允许在核函数完成边界处同步线程块。协作组允许开发者以不同的粒度同步协作的线程组。

### 4.4.5.1 Sync

可以通过调用集合函数 `sync()` 来同步组。与 `__syncthreads()` 一样，`sync()` 函数提供以下保证：

- 在同步点之前组中线程进行的所有内存访问（如读写）在同步点之后对组中所有线程可见。
- 组中所有线程到达同步点后，才允许任何线程继续越过该点。

以下示例展示了与 `__syncthreads()` 等价的 `cooperative_groups::sync()`。

```cpp
namespace cg = cooperative_groups;

cg::thread_block my_group = cg::this_thread_block();

// 同步线程块中的线程
cg::sync(my_group);
```

协作组可用于同步整个网格。自 CUDA 13 起，协作组不再可用于多设备同步。详情参见"大规模组"一节。

更多同步信息见《协作组 API》。

### 4.4.5.2 屏障（Barriers）

协作组提供了类似 `cuda::barrier` 的屏障 API，可用于更高级的同步。协作组屏障 API 与 `cuda::barrier` 有几个关键区别：

- 协作组屏障自动初始化
- 组中所有线程在每个阶段必须到达屏障并等待一次。
- `barrier_arrive` 返回一个 `arrival_token` 对象，必须将其传入相应的 `barrier_wait`，在其中被消耗且不能再次使用。

程序员使用协作组屏障时必须注意避免风险：

- 在调用 `barrier_arrive` 之后、调用 `barrier_wait` 之前，组不能使用任何集合操作。
- `barrier_wait` 只保证组中所有线程都已调用 `barrier_arrive`。`barrier_wait` 不保证所有线程都已调用 `barrier_wait`。

```cpp
namespace cg = cooperative_groups;

cg::thread_block my_group = this_block();
cg::cluster_group cluster = this_cluster();

auto token = cluster.barrier_arrive();

// 可选：执行一些本地处理以隐藏同步延迟
local_processing(my_group);

// 确保集群中的其他线程块都在运行，且已初始化共享数据，
// 然后再访问 dsmem
cluster.barrier_wait(std::move(token));
```

## 4.4.6 集合操作

协作组包含一组可由线程组执行的集合操作。

这些操作需要指定组中的所有线程参与才能完成操作。

除非《协作组 API》中明确允许不同值，否则组中所有线程必须在每次集合调用中为相应参数传入相同的值。否则该调用的行为未定义。

### 4.4.6.1 归约（Reduce）

`reduce` 函数用于对指定组中每个线程提供的数据执行并行归约。必须通过提供下表所示的操作符之一来指定归约类型。

**表 13：协作组归约操作符**

| 操作符 | 返回 |
|---|---|
| `plus` | 组中所有值的总和 |
| `less` | 最小值 |
| `greater` | 最大值 |
| `bit_and` | 按位与归约 |
| `bit_or` | 按位或归约 |
| `bit_xor` | 按位异或归约 |

硬件加速用于归约（需要计算能力 8.0 或更高）。对于没有硬件加速的旧硬件，有软件回退方案。只有 4 字节类型被硬件加速。

更多归约信息见《协作组 API》。

以下示例展示如何使用 `cooperative_groups::reduce()` 执行线程块范围的求和归约。

```cpp
namespace cg = cooperative_groups;

cg::thread_block my_group = cg::this_thread_block();

int val = data[threadIdx.x];

int sum = cg::reduce(my_group, val, cg::plus<int>());

// 存储归约结果
if (my_group.thread_rank() == 0) {
   result[blockIdx.x] = sum;
}
```

### 4.4.6.2 扫描（Scans）

协作组包含 `inclusive_scan` 和 `exclusive_scan` 的实现，可用于任意大小的组。这些函数对指定组中每个命名线程提供的数据执行扫描操作。

程序员可以选择指定归约操作符，如上表"归约操作符"所列。

```cpp
namespace cg = cooperative_groups;

cg::thread_block my_group = cg::this_thread_block();

int val = data[my_group.thread_rank()];

int exclusive_sum = cg::exclusive_scan(my_group, val, cg::plus<int>());

result[my_group.thread_rank()] = exclusive_sum;
```

更多扫描信息见《协作组扫描 API》（Cooperative Groups Scan API）。

### 4.4.6.3 Invoke One

协作组提供 `invoke_one` 函数，用于当单个线程必须代表组执行串行部分工作时。

- `invoke_one` 从调用组中选择单个任意线程，用该线程调用提供的可调用函数并传入提供的参数。
- `invoke_one_broadcast` 与 `invoke_one` 相同，只是调用结果还会广播到组中的所有线程。

线程选择机制不保证是确定性的。

以下示例展示基本的 `invoke_one` 用法。

```cpp
namespace cg = cooperative_groups;
cg::thread_block my_group = cg::this_thread_block();

// 确保线程块中只有一个线程打印消息
cg::invoke_one(my_group, []() {
    printf("Hello from one thread in the block!");
});

// 同步，确保所有线程等待消息打印完成
cg::sync(my_group);
```

在可调用函数内部不允许调用组内的通信或同步。允许与调用组之外的线程通信。

## 4.4.7 异步数据移动

CUDA 中的协作组 `memcpy_async` 功能提供了一种在全局内存与共享内存之间执行异步内存拷贝的方法。`memcpy_async` 特别适合优化内存传输，以及将计算与数据传输重叠以提升性能。

`memcpy_async` 函数用于启动从全局内存到共享内存的异步加载。`memcpy_async` 旨在用作"预取"：在需要数据之前先加载数据。

`wait` 函数强制组中的所有线程等待异步内存传输完成。在共享内存中的数据可被访问之前，组中的所有线程都必须调用 `wait`。

以下示例展示如何使用 `memcpy_async` 和 `wait` 预取数据。

```cpp
namespace cg = cooperative_groups;

cg::thread_group my_group = cg::this_thread_block();

__shared__ int shared_data[];

// 执行从全局内存到共享内存的异步拷贝
cg::memcpy_async(my_group, shared_data + my_group.rank(), input + my_group.rank(), sizeof(int));

// 在此执行工作以隐藏延迟。不能使用 shared_data

// 等待异步拷贝完成
cg::wait(my_group);

// 预取的数据现在可用
```

更多信息见《协作组 API》。

### 4.4.7.1 Memcpy Async 对齐要求

仅当源是全局内存、目标是共享内存且两者都至少 4 字节对齐时，`memcpy_async` 才是异步的。为获得最佳性能：建议共享内存和全局内存的对齐均为 16 字节。

## 4.4.8 大规模组

协作组支持跨越整个网格的大组。之前描述的所有协作组功能都适用于这些大组，但有一个显著例外：同步整个网格需要使用 `cudaLaunchCooperativeKernel` 运行时启动 API。

自 CUDA 13 起，多设备启动 API 及协作组的相关引用已被移除。

### 4.4.8.1 何时使用 cudaLaunchCooperativeKernel

`cudaLaunchCooperativeKernel` 是一个 CUDA 运行时 API 函数，用于启动使用协作组的单设备核函数，专门用于执行需要线程块间同步的核函数。该函数确保核函数中的所有线程可以在整个网格范围内同步和协作，而传统 CUDA 核函数只允许在单个线程块内同步。`cudaLaunchCooperativeKernel` 确保核函数启动是原子的，即如果 API 调用成功，则指定数量的线程块将在指定设备上启动。

一个好的做法是先通过查询设备属性 `cudaDevAttrCooperativeLaunch` 来确保设备支持协作启动：

```cpp
int dev = 0;
int supportsCoopLaunch = 0;
cudaDeviceGetAttribute(&supportsCoopLaunch, cudaDevAttrCooperativeLaunch, dev);
```

如果设备 0 支持该属性，将把 `supportsCoopLaunch` 置为 1。只有计算能力 6.0 及更高的设备受支持。此外，需要运行在以下任一环境中：

- 无 MPS 的 Linux 平台
- 带 MPS 且设备计算能力 7.0 或更高的 Linux 平台
- 最新的 Windows 平台
