# 5.1 计算能力

计算设备的通用规格与特性取决于其计算能力（Compute Capability）（参见"计算能力与流多处理器版本"）。表 29、表 30 和表 31 列出了当前支持的各计算能力对应的特性与技术规格。

所有 NVIDIA GPU 架构均采用小端序（little-endian）表示。

## 5.1.1 获取 GPU 计算能力

CUDA GPU 计算能力页面提供了从 NVIDIA GPU 型号到其计算能力的完整映射。

也可以使用 NVIDIA 驱动自带的 `nvidia-smi` 工具获取 GPU 的计算能力。例如，以下命令将输出系统上可用 GPU 的名称和计算能力：

```
nvidia-smi --query-gpu=name,compute_cap
```

在运行时，可以使用 CUDA Runtime API 的 `cudaDeviceGetAttribute()`、CUDA Driver API 的 `cuDeviceGetAttribute()` 或 NVML API 的 `nvmlDeviceGetCudaComputeCapability()` 获取计算能力：

```c
#include <cuda_runtime_api.h>

int computeCapabilityMajor, computeCapabilityMinor;
cudaDeviceGetAttribute(&computeCapabilityMajor, cudaDevAttrComputeCapabilityMajor, device_id);
cudaDeviceGetAttribute(&computeCapabilityMinor, cudaDevAttrComputeCapabilityMinor, device_id);
```

```c
#include <cuda.h>

int computeCapabilityMajor, computeCapabilityMinor;
cuDeviceGetAttribute(&computeCapabilityMajor, CU_DEVICE_ATTRIBUTE_COMPUTE_CAPABILITY_MAJOR, device_id);
cuDeviceGetAttribute(&computeCapabilityMinor, CU_DEVICE_ATTRIBUTE_COMPUTE_CAPABILITY_MINOR, device_id);
```

```c
#include <nvml.h> // 需要链接 -lnvidia-ml

int computeCapabilityMajor, computeCapabilityMinor;
nvmlDeviceGetCudaComputeCapability(nvmlDevice, &computeCapabilityMajor, &computeCapabilityMinor);
```

## 5.1.2 特性可用性

随某一计算架构引入的大多数计算特性，预期在其之后的所有架构上均可用。表 29 中，某特性在其引入版本之后的计算能力列标注"是"，即体现了这一点。

### 5.1.2.1 架构专属特性

从计算能力 9.0 的设备开始，随架构引入的专用计算特性可能无法保证在其之后的所有计算能力上均可用。这类特性称为架构专属特性（architecture-specific features），用于加速专用操作，例如 Tensor Core 操作；这些操作并非面向所有类别的计算能力，或在未来代际中可能发生显著变化。必须使用架构专属编译目标（参见"特性集编译目标"）编译代码，才能启用架构专属特性。使用架构专属编译目标编译的代码，只能运行在与其编译目标完全相同的计算能力上。

### 5.1.2.2 系列专属特性

从计算能力 10.0 的设备开始，一些架构专属特性为多个计算能力的设备所共有。包含这些特性的设备属于同一系列，这些特性也可称为系列专属特性（family-specific features）。系列专属特性保证在同一系列的所有设备上可用。启用系列专属特性需要使用系列专属编译目标，参见 5.1.2.3 节。为系列专属目标编译的代码，只能运行在该系列成员的 GPU 上。

### 5.1.2.3 特性集编译目标

编译器可以面向三类计算特性集：

基线特性集（Baseline Feature Set）：主要的计算特性集合，引入时即预期在后续计算架构上可用。这些特性及其可用性汇总于表 29。

架构专属特性集（Architecture-Specific Feature Set）：一小部分高度专用的特性，称为架构专属特性，用于加速专用操作；在后续计算架构上不保证可用，也可能发生显著变化。这些特性汇总于各自的"计算能力 #.#"小节。架构专属特性集是系列专属特性集的超集。架构专属编译目标随计算能力 9.0 设备引入，通过在编译目标中使用后缀 `a` 来选择，例如将 `compute_100a` 或 `compute_120a` 指定为计算目标。

系列专属特性集（Family-Specific Feature Set）：一些架构专属特性为多个计算能力的 GPU 所共有。这些特性汇总于各自的"计算能力 #.#"小节。除少数例外外，主版本号相同的计算能力中，较新一代的设备属于同一系列。表 28 列出了系列专属目标与设备计算能力的兼容关系，包括例外情况。系列专属特性集是基线特性集的超集。系列专属编译目标随计算能力 10.0 设备引入，通过在编译目标中使用后缀 `f` 来选择，例如将 `compute_100f` 或 `compute_120f` 指定为计算目标。

从计算能力 9.0 开始的所有设备都有一组架构专属特性。要在特定 GPU 上使用这组特性的完整集合，必须使用带后缀 `a` 的架构专属编译目标。此外，从计算能力 10.0 开始，存在一些特性集出现在多个次版本号不同的设备上。这些指令集称为系列专属特性，共享这些特性的设备被视为属于同一系列。系列专属特性是架构专属特性中、该 GPU 系列所有成员共有的子集。带后缀 `f` 的系列专属编译目标允许编译器生成使用这一共有子集的代码。

例如：

- `compute_100` 编译目标不允许使用架构专属特性。该目标与计算能力 10.0 及之后的所有设备兼容。
- `compute_100f` 系列专属编译目标允许使用该 GPU 系列共有的架构专属特性子集。该目标仅与该 GPU 系列成员的设备兼容。在本例中，它与计算能力 10.0、10.3 和 10.7 的设备兼容。系列专属 `compute_100f` 目标中可用的特性是基线 `compute_100` 目标中可用特性的超集。
- `compute_100a` 架构专属编译目标允许使用计算能力 10.0 设备中架构专属特性的完整集合。该目标仅与计算能力 10.0 的设备兼容，不兼容其他设备。`compute_100a` 目标中可用的特性构成 `compute_100f` 目标中可用特性的超集。

**表 28：系列专属兼容性**

| 编译目标 | 兼容的计算能力 |
|---|---|
| `compute_100f` | 10.0、10.3、10.7 |
| `compute_103f` | 10.3、10.7 |
| `compute_107f` | 10.7¹ |
| `compute_110f` | 11.0¹ |
| `compute_120f` | 12.0、12.1 |
| `compute_121f` | 12.1 |

¹ 有些系列在创建时仅包含单个成员，未来可能会扩展以纳入更多设备。
