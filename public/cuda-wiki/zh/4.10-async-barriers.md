# 4.10 异步屏障

异步屏障（在"高级同步原语"中引入）将 CUDA 同步扩展到 `__syncthreads()` 和 `__syncwarp()` 之外，支持细粒度、非阻塞的协作，以及通信与计算之间更好的重叠。本节主要通过 `cuda::barrier` API 详细介绍异步屏障的使用方法（在适用处也会指向 `cuda::ptx` 和原语）。

## 4.10.1 初始化

初始化必须在任何线程开始参与屏障之前完成。

**CUDA C++ `cuda::barrier`**

```cpp
#include <cuda/barrier>
#include <cooperative_groups.h>

__global__ void init_barrier()
{
  __shared__ cuda::barrier<cuda::thread_scope_block> bar;
  auto block = cooperative_groups::this_thread_block();

     if (block.thread_rank() == 0)
     {
       // 一个线程初始化总预期到达计数。
       init(&bar, block.size());
     }
     block.sync();
}
```

**CUDA C++ `cuda::ptx`**

```cpp
#include <cuda/ptx>
#include <cooperative_groups.h>

__global__ void init_barrier()
{
  __shared__ uint64_t bar;
  auto block = cooperative_groups::this_thread_block();

    if (block.thread_rank() == 0)
    {
      // 一个线程初始化总预期到达计数。
      cuda::ptx::mbarrier_init(&bar, block.size());
    }
    block.sync();
}
```

**CUDA C 原语**

```cpp
#include <cuda_awbarrier_primitives.h>
#include <cooperative_groups.h>

__global__ void init_barrier()
{
  __shared__ uint64_t bar;
  auto block = cooperative_groups::this_thread_block();

    if (block.thread_rank() == 0)
    {
      // 一个线程初始化总预期到达计数。
      __mbarrier_init(&bar, block.size());
    }
    block.sync();
}
```

在任何线程参与屏障之前，必须使用 `cuda::barrier::init()` 友元函数初始化屏障。这必须发生在任何线程抵达（arrive）屏障之前。这就带来了一个自举难题：线程必须在参与屏障之前先同步，而它们创建屏障的目的正是为了同步。在本例中，参与的线程属于一个协作组（cooperative group），使用 `block.sync()` 来引导初始化。由于参与屏障的是整个线程块，也可以使用 `__syncthreads()`。

`init()` 的第二个参数是预期到达计数，即在参与线程从 `bar.wait(std::move(token))` 调用中被解除阻塞之前，参与线程调用 `bar.arrive()` 的总次数。在这些例子中，屏障用线程块中的线程数（即 `cooperative_groups::this_thread_block().size()`）初始化，以便线程块内的所有线程都能参与屏障。

异步屏障在指定线程如何参与（分离的 arrive/wait）以及哪些线程参与方面都很灵活。相比之下，`this_thread_block.sync()` 或 `__syncthreads()` 适用于整个线程块，`__syncwarp(mask)` 适用于线程束的指定子集。不过，如果用户的目的是同步整个线程块或整个线程束，建议分别使用 `__syncthreads()` 和 `__syncwarp()` 以获得更好的性能。

## 4.10.2 屏障的阶段：抵达、倒计数、完成与重置

随着参与线程调用 `bar.arrive()`，异步屏障从预期到达计数倒计数到零。当倒计数到达零时，屏障在当前阶段完成。当最后一次调用 `bar.arrive()` 使倒计数到达零时，倒计数会自动以原子方式重置。重置将倒计数设为预期到达计数，并将屏障推进到下一阶段。

`cuda::barrier::arrival_token` 类的令牌对象（由 `token=bar.arrive()` 返回）与屏障的当前阶段相关联。调用 `bar.wait(std::move(token))` 会在屏障处于当前阶段时阻塞调用线程，也就是说，只要令牌关联的阶段与屏障的阶段相匹配。如果在调用 `bar.wait(std::move(token))` 之前阶段已经推进（因为倒计数到达零），线程不会阻塞；如果线程阻塞在 `bar.wait(std::move(token))` 中时阶段推进，线程将被解除阻塞。了解重置何时可能发生、何时不会发生非常重要，尤其是在复杂的 arrive/wait 同步模式中。

- ▶ 线程对 `token=bar.arrive()` 和 `bar.wait(std::move(token))` 的调用必须有序：`token=bar.arrive()` 发生在屏障的当前阶段，`bar.wait(std::move(token))` 发生在同一阶段或下一阶段。
- ▶ 线程调用 `bar.arrive()` 必须发生在屏障计数器非零时。屏障初始化之后，如果线程调用 `bar.arrive()` 使倒计数到达零，则在屏障可被复用于后续的 `bar.arrive()` 调用之前，必须先发生一次 `bar.wait(std::move(token))` 调用。
- ▶ `bar.wait()` 只能使用当前阶段或紧前一阶段的令牌对象调用。对令牌对象的其他值，行为未定义。

对于简单的 arrive/wait 同步模式，遵守这些使用规则是直接的。

### 4.10.2.1 线程束纠缠

线程束分支分化会影响 arrive-on 操作更新屏障的次数。如果调用线程束完全收敛，屏障只更新一次；如果调用线程束完全分化，则会对屏障施加 32 次独立更新。

> **注：** 建议由收敛的线程调用 arrive-on(bar)，以最小化对屏障对象的更新。如果这些操作之前的代码导致线程分化，则应在调用 arrive-on 操作之前通过 `__syncwarp` 重新收敛线程束。

## 4.10.3 显式阶段跟踪

异步屏障可以有多个阶段，具体取决于它被用于同步线程和内存操作的次数。除了使用令牌来跟踪屏障阶段翻转，我们还可以通过 `cuda::ptx` 和原语 API 提供的 `mbarrier_try_wait_parity()` 函数族直接跟踪阶段。

在最简单的形式中，`cuda::ptx::mbarrier_try_wait_parity(uint64_t* bar, const uint32_t& phaseParity)` 函数等待具有特定奇偶性（parity）的阶段。`phaseParity` 操作数是屏障对象当前阶段或紧前一阶段的整数奇偶性。偶数阶段的整数奇偶性为 0，奇数阶段为 1。初始化屏障时，其阶段的奇偶性为 0。因此 `phaseParity` 的有效值为 0 和 1。显式阶段跟踪在跟踪异步内存操作时很有用：它允许只有一个线程抵达屏障并设置事务计数，而其他线程只需等待基于奇偶性的阶段翻转。这比让所有线程都抵达屏障并使用令牌更高效。该功能仅适用于线程块和簇（cluster）作用域的共享内存屏障。

**CUDA C++ `cuda::barrier`**

```cpp
#include <cuda/ptx>
#include <cooperative_groups.h>

__device__ void compute(float *data, int iteration);

__global__ void split_arrive_wait(int iteration_count, float *data)
{
  using barrier_t = cuda::barrier<cuda::thread_scope_block>;
  __shared__ barrier_t bar;
  int parity = 0; // 初始阶段奇偶性为 0。
  auto block = cooperative_groups::this_thread_block();

     if (block.thread_rank() == 0)
     {
       // 用预期到达计数初始化屏障。
       init(&bar, block.size());
     }
     block.sync();

     for (int i = 0; i < iteration_count; ++i)
     {
       /* arrive 之前的代码 */

       // 该线程抵达。抵达不会阻塞线程。
       // 获取原生屏障句柄以供 cuda::ptx API 使用。
       (void)cuda::ptx::mbarrier_arrive(cuda::device::barrier_native_handle(bar));

       compute(data, i);

       // 等待参与屏障的所有线程完成 mbarrier_arrive()。
       // 获取原生屏障句柄以供 cuda::ptx API 使用。
       while (!cuda::ptx::mbarrier_try_wait_parity(cuda::device::barrier_native_handle(bar), parity)) {}

       // 翻转奇偶性。
       parity ^= 1;

       /* wait 之后的代码 */
     }
}
```


```cpp

```

## 4.10.4 提前退出

当参与一连串同步的线程必须提前退出该序列时，该线程在退出前必须显式地退出参与。其余参与线程可以正常继续后续的 arrive 和 wait 操作。

**CUDA C++ `cuda::barrier`**

```cpp
#include <cuda/barrier>
#include <cooperative_groups.h>

__device__ bool condition_check();

__global__ void early_exit_kernel(int N)
{
  __shared__ cuda::barrier<cuda::thread_scope_block> bar;
  auto block = cooperative_groups::this_thread_block();

    if (block.thread_rank() == 0)
    {
      init(&bar, block.size());
    }
    block.sync();

    for (int i = 0; i < N; ++i)
    {
      if (condition_check())
      {
        bar.arrive_and_drop();
        return;
      }
      // 其他线程可以正常继续。
      auto token = bar.arrive();

        /* arrive 和 wait 之间的代码 */

        // 等待所有线程抵达。
        bar.wait(std::move(token));

        /* wait 之后的代码 */
    }
}
```

**CUDA C 原语**

```cpp
#include <cuda_awbarrier_primitives.h>
#include <cooperative_groups.h>

__device__ bool condition_check();

__global__ void early_exit_kernel(int N)
{
  __shared__ __mbarrier_t bar;
  auto block = cooperative_groups::this_thread_block();

    if (block.thread_rank() == 0)
    {
      __mbarrier_init(&bar, block.size());
    }
    block.sync();

    for (int i = 0; i < N; ++i)
    {
      if (condition_check())
      {
        __mbarrier_token_t token = __mbarrier_arrive_and_drop(&bar);
        return;
      }
      // 其他线程可以正常继续。
      __mbarrier_token_t token = __mbarrier_arrive(&bar);

        /* arrive 和 wait 之间的代码 */

        // 等待所有线程抵达。
        while (!__mbarrier_try_wait(&bar, token, 1000)) {}

        /* wait 之后的代码 */
    }
}
```

`bar.arrive_and_drop()` 操作抵达屏障，履行参与线程在当前阶段的到达义务，然后将下一阶段的预期到达计数减一，使该线程不再被期望抵达屏障。

## 4.10.5 完成函数

`cuda::barrier` API 支持可选的完成函数。`cuda::barrier<Scope, CompletionFunction>` 的 `CompletionFunction` 每个阶段执行一次，在最后一个线程到达之后、任何线程从等待中被解除阻塞之前执行。该阶段抵达屏障的线程所执行的内存操作对执行 `CompletionFunction` 的线程可见；而 `CompletionFunction` 中执行的所有内存操作，在屏障等待的线程被解除阻塞后对所有这些线程可见。

**CUDA C++ `cuda::barrier`**

```cpp
#include <cuda/barrier>
#include <cooperative_groups.h>
#include <functional>
namespace cg = cooperative_groups;

__device__ int divergent_compute(int *, int);
__device__ int independent_computation(int *, int);

__global__ void psum(int *data, int n, int *acc)
{
  auto block = cg::this_thread_block();

  constexpr int BlockSize = 128;
  __shared__ int smem[BlockSize];
  assert(BlockSize == block.size());
  assert(n % BlockSize == 0);

  auto completion_fn = [&]
  {
     int sum = 0;
     for (int i = 0; i < BlockSize; ++i)
     {
       sum += smem[i];
     }
     *acc += sum;
  };

  /* 屏障存储。
     注意：由于捕获，completion_fn 不是默认可构造的，
           因此屏障也不是默认可构造的。*/
  using completion_fn_t = decltype(completion_fn);
  using barrier_t = cuda::barrier<cuda::thread_scope_block,
                                   completion_fn_t>;
  __shared__ std::aligned_storage<sizeof(barrier_t),
                                   alignof(barrier_t)>
      bar_storage;

  // 初始化屏障。
  barrier_t *bar = (barrier_t *)&bar_storage;
  if (block.thread_rank() == 0)
  {
    assert(*acc == 0);
    assert(blockDim.x == blockDim.y == blockDim.y == 1);
    new (bar) barrier_t{block.size(), completion_fn};
    /* 等价于：init(bar, block.size(), completion_fn); */
  }
  block.sync();

   // 主循环。
   for (int i = 0; i < n; i += block.size())
   {
      smem[block.thread_rank()] = data[i] + *acc;
      auto token = bar->arrive();
      // 可以在这里做独立计算。
      bar->wait(std::move(token));
   }
}
```

## 4.10.6 跟踪异步内存操作

异步屏障可用于跟踪异步内存拷贝。当一个异步拷贝操作绑定到屏障时，该拷贝操作在发起时自动将当前屏障阶段的预期计数加一，在完成时将其减一。该机制保证屏障的 `wait()` 操作会阻塞，直到所有关联的异步内存拷贝全部完成，从而为同步多个并发内存操作提供了一种便捷的方式。

从计算能力 9.0 开始，线程块或簇作用域的共享内存异步屏障可以显式跟踪异步内存操作。我们称这些屏障为异步事务屏障。除了预期到达计数，屏障对象还可以接受一个事务计数，用于跟踪异步事务的完成情况。事务计数跟踪尚未完成的异步事务数量，单位由异步内存操作指定（通常为字节）。当前阶段要跟踪的事务计数可以在到达时通过 `cuda::device::barrier_arrive_tx()` 设置，或直接通过 `cuda::device::barrier_expect_tx()` 设置。当屏障使用事务计数时，它会在 wait 操作处阻塞线程，直到所有生产者线程都执行了 arrive，且所有事务计数之和达到预期值。

**CUDA C++ `cuda::barrier`**

```cpp
#include <cuda/barrier>
#include <cooperative_groups.h>

__global__ void track_kernel()
{
  __shared__ cuda::barrier<cuda::thread_scope_block> bar;
  auto block = cooperative_groups::this_thread_block();

    if (block.thread_rank() == 0)
    {
      init(&bar, block.size());
    }
    block.sync();

    auto token = cuda::device::barrier_arrive_tx(bar, 1, 0);

    bar.wait(cuda::std::move(token));
}
```

**CUDA C++ `cuda::ptx`**

```cpp
#include <cuda/ptx>
#include <cooperative_groups.h>

__global__ void track_kernel()
{
  __shared__ uint64_t bar;
  auto block = cooperative_groups::this_thread_block();

      if (block.thread_rank() == 0)
      {
        cuda::ptx::mbarrier_init(&bar, block.size());
      }
      block.sync();

      uint64_t token = cuda::ptx::mbarrier_arrive_expect_tx(cuda::ptx::sem_release,
                                                             cuda::ptx::scope_cluster,
                                                             cuda::ptx::space_shared,
                                                             &bar, 1, 0);

      while (!cuda::ptx::mbarrier_try_wait(&bar, token)) {}
}
```

在本例中，`cuda::device::barrier_arrive_tx()` 操作构造一个与当前阶段的阶段同步点关联的到达令牌对象；然后将到达计数减 1，将预期事务计数加 0。由于事务计数增量为 0，屏障并未跟踪任何事务。后续"使用 Tensor 内存加速器（TMA）"一节中有跟踪异步内存操作的示例。

## 4.10.7 使用屏障的生产者-消费者模式

一个线程块可以在空间上划分，让不同的线程执行独立的操作。最常见的做法是把线程块内不同线程束的线程分配给特定任务。这种技术称为线程束特化（warp specialization）。

本节展示生产者-消费者模式中的空间划分示例：一个线程子集生产数据，另一个不相交的线程子集并发地消费这些数据。生产者-消费者空间划分模式需要两次单向同步，来管理生产者与消费者之间的数据缓冲区。

| 生产者 | 消费者 |
|---|---|
| 等待缓冲区准备好被填充 | 发信号表明缓冲区已准备好被填充 |
| 生产数据并填充缓冲区 | |
| 发信号表明缓冲区已填充 | 等待缓冲区被填充 |
| | 消费已填充缓冲区中的数据 |

生产者线程等待消费者线程发信号表明缓冲区已准备好被填充；但消费者线程不会等待这一信号。消费者线程等待生产者线程发信号表明缓冲区已填充；但生产者线程不会等待这一信号。要实现完整的生产者/消费者并发，该模式使用（至少）双缓冲，每个缓冲区需要两个屏障。

**CUDA C++ `cuda::barrier`**

```cpp
#include <cuda/barrier>

using barrier_t = cuda::barrier<cuda::thread_scope_block>;

__device__ void produce(barrier_t ready[], barrier_t filled[], float *buffer, int buffer_len, float *in, int N)
{
   for (int i = 0; i < N / buffer_len; ++i)
   {
     ready[i % 2].arrive_and_wait(); /* 等待 buffer_(i%2) 准备好被填充 */

     /* 生产，即填充 buffer_(i%2) */
     barrier_t::arrival_token token = filled[i % 2].arrive(); /* buffer_(i%2) 已填充 */
   }
}

__device__ void consume(barrier_t ready[], barrier_t filled[], float *buffer, int buffer_len, float *out, int N)
{
   barrier_t::arrival_token token1 = ready[0].arrive(); /* buffer_0 已准备好初次填充 */

   barrier_t::arrival_token token2 = ready[1].arrive(); /* buffer_1 已准备好初次填充 */

   for (int i = 0; i < N / buffer_len; ++i)
   {
     filled[i % 2].arrive_and_wait(); /* 等待 buffer_(i%2) 被填充 */
     /* 消费 buffer_(i%2) */
     barrier_t::arrival_token token3 = ready[i % 2].arrive(); /* buffer_(i%2) 已准备好再次填充 */
   }
}

__global__ void producer_consumer_pattern(int N, float *in, float *out, int buffer_len)
{
   constexpr int warpSize = 32;

      /* 下面声明的共享内存缓冲区大小为 2 * buffer_len，
         以便可以在两个缓冲区之间交替工作。
         buffer_0 = buffer，buffer_1 = buffer + buffer_len */
      __shared__ extern float buffer[];

   /* bar[0] 和 bar[1] 跟踪缓冲区 buffer_0 和 buffer_1 是否已准备好被填充，
      而 bar[2] 和 bar[3] 分别跟踪缓冲区 buffer_0 和 buffer_1 是否已填充 */

   #pragma nv_diag_suppress static_var_with_dynamic_init
   __shared__ barrier_t bar[4];

   if (threadIdx.x < 4)
   {
      init(bar + threadIdx.x, blockDim.x);
   }
   __syncthreads();
}
```

**CUDA C++ `cuda::ptx`**

```cpp
#include <cuda/ptx>

__device__ void produce(barrier ready[], barrier filled[], float *buffer, int buffer_len, float *in, int N)
{
   for (int i = 0; i < N / buffer_len; ++i)
   {
     uint64_t token1 = cuda::ptx::mbarrier_arrive(&ready[i % 2]);
     while(!cuda::ptx::mbarrier_try_wait(&ready[i % 2], token1)) {} /* 等待 buffer_(i%2) 准备好被填充 */

     /* 生产，即填充 buffer_(i%2) */
     uint64_t token2 = cuda::ptx::mbarrier_arrive(&filled[i % 2]); /* buffer_(i%2) 已填充 */
   }
}

__device__ void consume(barrier ready[], barrier filled[], float *buffer, int buffer_len, float *out, int N)
{
   uint64_t token1 = cuda::ptx::mbarrier_arrive(&ready[0]); /* buffer_0 已准备好初次填充 */

   uint64_t token2 = cuda::ptx::mbarrier_arrive(&ready[1]); /* buffer_1 已准备好初次填充 */

   for (int i = 0; i < N / buffer_len; ++i)
   {
     uint64_t token3 = cuda::ptx::mbarrier_arrive(&filled[i % 2]);
     while(!cuda::ptx::mbarrier_try_wait(&filled[i % 2], token3)) {} /* 等待 buffer_(i%2) 被填充 */

     /* 消费 buffer_(i%2) */
     uint64_t token4 = cuda::ptx::mbarrier_arrive(&ready[i % 2]); /* buffer_(i%2) 已准备好再次填充 */
   }
}

{
   constexpr int warpSize = 32;

      /* 下面声明的共享内存缓冲区大小为 2 * buffer_len，

         buffer_0 = buffer，buffer_1 = buffer + buffer_len */

   /* bar[0] 和 bar[1] 跟踪缓冲区 buffer_0 和 buffer_1 是否已准备好被填充，

   #pragma nv_diag_suppress static_var_with_dynamic_init
   __shared__ uint64_t bar[4];

      cuda::ptx::mbarrier_init(bar + block.thread_rank(), block.size());
```

**CUDA C 原语**

```cpp
#include <cuda_awbarrier_primitives.h>

__device__ void produce(__mbarrier_t ready[], __mbarrier_t filled[], float *buffer, int buffer_len, float *in, int N)
{
   for (int i = 0; i < N / buffer_len; ++i)
   {
     __mbarrier_token_t token1 = __mbarrier_arrive(&ready[i % 2]); /* 等待 buffer_(i%2) 准备好被填充 */

     while(!__mbarrier_try_wait(&ready[i % 2], token1, 1000)) {}
     /* 生产，即填充 buffer_(i%2) */
     __mbarrier_token_t token2 = __mbarrier_arrive(filled[i % 2]); /* buffer_(i%2) 已填充 */
   }
}

__device__ void consume(__mbarrier_t ready[], __mbarrier_t filled[], float *buffer, int buffer_len, float *out, int N)
{
   __mbarrier_token_t token1 = __mbarrier_arrive(&ready[0]); /* buffer_0 已准备好初次填充 */

   __mbarrier_token_t token2 = __mbarrier_arrive(&ready[1]); /* buffer_1 已准备好初次填充 */

   for (int i = 0; i < N / buffer_len; ++i)
   {
     __mbarrier_token_t token3 = __mbarrier_arrive(&filled[i % 2]);
     while(!__mbarrier_try_wait(&filled[i % 2], token3, 1000)) {}
     /* 消费 buffer_(i%2) */
     __mbarrier_token_t token4 = __mbarrier_arrive(&ready[i % 2]); /* buffer_(i%2) 已准备好再次填充 */
   }
}

__global__ void producer_consumer_pattern(int N, float *in, float *out, int buffer_len)
{
   constexpr int warpSize = 32;

      /* 下面声明的共享内存缓冲区大小为 2 * buffer_len，
         以便可以在两个缓冲区之间交替工作。
         buffer_0 = buffer，buffer_1 = buffer + buffer_len */
      __shared__ extern float buffer[];

   /* bar[0] 和 bar[1] 跟踪缓冲区 buffer_0 和 buffer_1 是否已准备好被填充，
      而 bar[2] 和 bar[3] 分别跟踪缓冲区 buffer_0 和 buffer_1 是否已填充 */

   #pragma nv_diag_suppress static_var_with_dynamic_init
   __shared__ __mbarrier_t bar[4];

   if (threadIdx.x < 4)
   {
      __mbarrier_init(bar + threadIdx.x, blockDim.x);
   }
   __syncthreads();
}
```

在本例中，第一个线程束特化为生产者，其余线程束特化为消费者。所有生产者和消费者线程都参与（调用 `bar.arrive()` 或 `bar.arrive_and_wait()`）四个屏障中的每一个，因此预期到达计数都等于 `block.size()`。

生产者线程等待消费者线程发信号表明共享内存缓冲区可以填充。要等待一个屏障，生产者线程必须先在该屏障上抵达——`ready[i%2].arrive()` 以获取令牌，然后用该令牌调用 `ready[i%2].wait(token)`。为简便起见，`ready[i%2].arrive_and_wait()` 将这两个操作合二为一。

```cpp
bar.arrive_and_wait();
/* 等价于 */
bar.wait(bar.arrive());
```

生产者线程计算并填充已就绪的缓冲区，然后通过抵达 filled 屏障（`filled[i%2].arrive()`）发信号表明缓冲区已填充。生产者线程此时并不等待，而是在下一次迭代中等待缓冲区（双缓冲）准备好被填充。

消费者线程首先发信号表明两个缓冲区都已准备好被填充。消费者线程此时并不等待，而是等待本次迭代的缓冲区被填充（`filled[i%2].arrive_and_wait()`）。消费者线程消费完缓冲区后，发信号表明缓冲区可以再次填充（`ready[i%2].arrive()`），然后等待下一次迭代的缓冲区被填充。
