# 4.14 L2 缓存控制

当 CUDA 核函数反复访问全局内存中的某个数据区域时，这类数据访问可被视为持久的（persisting）。反之，如果数据只被访问一次，这类数据访问可被视为流式的（streaming）。

计算能力 8.0 及以上设备有能力影响 L2 缓存中数据的持久性，从而可能实现更高带宽、更低延迟的全局内存访问。该功能通过两个主要 API 暴露：

- CUDA 运行时 API（自 CUDA 11.0 起）提供对 L2 缓存持久性的编程控制。
- libcu++ 库中的 `cuda::annotated_ptr` API（自 CUDA 11.5 起）在 CUDA 核函数中用内存访问属性标注指针，以达到类似的效果。

下面几节聚焦 CUDA 运行时 API。关于 `cuda::annotated_ptr` 方法的详细信息，请参阅 libcu++ 文档。

## 4.14.1 为持久性访问预留 L2 缓存

一部分 L2 缓存可被预留出来，供全局内存的持久性数据访问使用。持久性访问优先使用这部分预留的 L2 缓存，而全局内存的普通或流式访问只能在该部分未被持久性访问占用时使用。

为持久性访问预留的 L2 缓存大小可在限制范围内调整：

```c
cudaGetDeviceProperties(&prop, device_id);
size_t size = min(int(prop.l2CacheSize * 0.75), prop.persistingL2CacheMaxSize);

cudaDeviceSetLimit(cudaLimitPersistingL2CacheSize, size); /* 将 L2 缓存的 3/4 预留给持久性访问，或取允许的最大值 */
```

当 GPU 配置为多实例 GPU（MIG）模式时，L2 缓存预留功能被禁用。

使用多进程服务（MPS）时，L2 缓存预留大小不能通过 `cudaDeviceSetLimit` 更改。相反，预留大小只能在 MPS 服务端启动时通过环境变量 `CUDA_DEVICE_DEFAULT_PERSISTING_L2_CACHE_PERCENTAGE_LIMIT` 指定。

## 4.14.2 持久性访问的 L2 策略

访问策略窗口指定全局内存的一段连续区域，以及该区域内访问在 L2 缓存中的持久性属性。

下面的代码示例展示了如何使用 CUDA 流设置 L2 持久性访问窗口。

CUDA 流示例：

```c
cudaStreamAttrValue stream_attribute; // 流级属性数据结构

stream_attribute.accessPolicyWindow.base_ptr = reinterpret_cast<void*>(ptr); // 全局内存数据指针

stream_attribute.accessPolicyWindow.num_bytes = num_bytes; // 持久性访问的字节数
                                                          //（必须小于 cudaDeviceProp::accessPolicyMaxWindowSize）

stream_attribute.accessPolicyWindow.hitRatio = 0.6; // 缓存命中率提示

stream_attribute.accessPolicyWindow.hitProp = cudaAccessPropertyPersisting; // 缓存命中时的访问属性类型

stream_attribute.accessPolicyWindow.missProp = cudaAccessPropertyStreaming; // 缓存未命中时的访问属性类型

// 将该属性设置到类型为 cudaStream_t 的 CUDA 流上
cudaStreamSetAttribute(stream, cudaStreamAttributeAccessPolicyWindow, &stream_attribute);
```

当核函数随后在该 CUDA 流中执行时，全局内存范围 `[ptr..ptr+num_bytes)` 内的内存访问比对其他全局内存位置的访问更有可能驻留在 L2 缓存中。

L2 持久性也可以为 CUDA 图核函数节点设置，如下面的示例所示：

CUDA 图核函数节点示例：

```c
cudaKernelNodeAttrValue node_attribute; // 核函数级属性数据结构

node_attribute.accessPolicyWindow.base_ptr = reinterpret_cast<void*>(ptr); // 全局内存数据指针

node_attribute.accessPolicyWindow.num_bytes = num_bytes; // 持久性访问的字节数
                                                         //（必须小于 cudaDeviceProp::accessPolicyMaxWindowSize）

node_attribute.accessPolicyWindow.hitRatio = 0.6; // 缓存命中率提示

node_attribute.accessPolicyWindow.hitProp = cudaAccessPropertyPersisting; // 缓存命中时的访问属性类型

node_attribute.accessPolicyWindow.missProp = cudaAccessPropertyStreaming; // 缓存未命中时的访问属性类型

// 将该属性设置到类型为 cudaGraphNode_t 的 CUDA 图核函数节点上
cudaGraphKernelNodeSetAttribute(node, cudaKernelNodeAttributeAccessPolicyWindow, &node_attribute);
```

`hitRatio` 参数可用于指定获得 `hitProp` 属性的访问所占的比例。在上面两个示例中，全局内存区域 `[ptr..ptr+num_bytes)` 中 60% 的内存访问具有持久性属性，40% 的内存访问具有流式属性。哪些具体内存访问被归类为持久性（`hitProp`）是随机的，概率近似为 `hitRatio`；概率分布取决于硬件架构和内存范围。

例如，如果 L2 预留缓存大小为 16KB，而 `accessPolicyWindow` 中的 `num_bytes` 为 32KB：

- 当 `hitRatio` 为 0.5 时，硬件会随机选择 32KB 窗口中的 16KB 指定为持久性，并缓存在预留的 L2 缓存区域中。
- 当 `hitRatio` 为 1.0 时，硬件会尝试把整个 32KB 窗口缓存在预留的 L2 缓存区域中。由于预留区域小于窗口，缓存行会被逐出，以使预留 L2 缓存中保留 32KB 数据里最近使用的 16KB。

因此，`hitRatio` 可用于避免缓存行颠簸，并总体减少进出 L2 缓存的数据量。

小于 1.0 的 `hitRatio` 可用于手动控制并发 CUDA 流中不同 `accessPolicyWindow` 能在 L2 中缓存的数据量。例如，设 L2 预留缓存大小为 16KB；两个并发核函数在两个不同的 CUDA 流中运行，各自的 `accessPolicyWindow` 均为 16KB 且 `hitRatio` 均为 1.0，则二者在竞争共享 L2 资源时可能互相逐出对方的缓存行。但如果两个 `accessPolicyWindow` 的 `hitRatio` 均为 0.5，则它们逐出自己或对方持久性缓存行的可能性就会降低。

## 4.14.3 L2 访问属性

为不同的全局内存数据访问定义了三种访问属性：

1. `cudaAccessPropertyStreaming`：具有流式属性的内存访问更不容易驻留在 L2 缓存中，因为这类访问会被优先逐出。
2. `cudaAccessPropertyPersisting`：具有持久性属性的内存访问更有可能驻留在 L2 缓存中，因为这类访问被优先保留在 L2 缓存的预留部分中。
3. `cudaAccessPropertyNormal`：该访问属性将此前施加的持久性访问属性强制重置为普通状态。先前 CUDA 核函数具有持久性属性的内存访问可能在其用途结束后仍长时间保留在 L2 缓存中。这种"使用后持久"会减少后续不使用持久性属性的核函数可用的 L2 缓存。用 `cudaAccessPropertyNormal` 属性重置访问属性窗口，可移除此前访问的持久性（优先保留）状态，就像此前访问未带访问属性一样。

## 4.14.4 L2 持久性示例

以下示例展示了如何为持久性访问预留 L2 缓存、通过 CUDA 流在 CUDA 核函数中使用预留的 L2 缓存，然后重置 L2 缓存。

```c
cudaStream_t stream;
cudaStreamCreate(&stream); // 创建 CUDA 流

cudaDeviceProp prop; // CUDA 设备属性变量
cudaGetDeviceProperties(&prop, device_id); // 查询 GPU 属性
size_t size = min(int(prop.l2CacheSize * 0.75), prop.persistingL2CacheMaxSize);

cudaDeviceSetLimit(cudaLimitPersistingL2CacheSize, size); // 将 L2 缓存的 3/4 预留给持久性访问，或取允许的最大值

size_t window_size = min(prop.accessPolicyMaxWindowSize, num_bytes); // 取用户定义的 num_bytes 与最大窗口大小的最小值

cudaStreamAttrValue stream_attribute; // 流级属性数据结构
stream_attribute.accessPolicyWindow.base_ptr = reinterpret_cast<void*>(data1); // 全局内存数据指针
stream_attribute.accessPolicyWindow.num_bytes = window_size; // 持久性访问的字节数
stream_attribute.accessPolicyWindow.hitRatio = 0.6; // 缓存命中率提示
stream_attribute.accessPolicyWindow.hitProp = cudaAccessPropertyPersisting; // 持久性属性
stream_attribute.accessPolicyWindow.missProp = cudaAccessPropertyStreaming; // 缓存未命中时的访问属性类型

cudaStreamSetAttribute(stream, cudaStreamAttributeAccessPolicyWindow, &stream_attribute); // 将该属性设置到 CUDA 流上

for (int i = 0; i < 10; i++) {
    cuda_kernelA<<<grid_size, block_size, 0, stream>>>(data1); // data1 被核函数多次使用，[data1 + num_bytes) 范围受益于 L2 持久性
}
cuda_kernelB<<<grid_size, block_size, 0, stream>>>(data1); // 同一流中的另一个不同核函数也能受益于 data1 的持久性

stream_attribute.accessPolicyWindow.num_bytes = 0; // 将窗口大小设为 0 会禁用它
cudaStreamSetAttribute(stream, cudaStreamAttributeAccessPolicyWindow, &stream_attribute); // 用新的访问策略属性覆盖该 CUDA 流
cudaCtxResetPersistingL2Cache(); // 移除 L2 中的所有持久性缓存行

cuda_kernelC<<<grid_size, block_size, 0, stream>>>(data2); // data2 现在可以在普通模式下受益于完整的 L2
```

## 4.14.5 将 L2 访问重置为普通状态

先前 CUDA 核函数的持久性 L2 缓存行可能在其用途结束后仍长时间驻留在 L2 中。因此，将 L2 缓存重置为普通状态很重要，这样流式或普通内存访问才能以普通优先级利用 L2 缓存。有三种方法可将持久性访问重置为普通状态：

1. 用访问属性 `cudaAccessPropertyNormal` 重置先前的持久性内存区域。
2. 调用 `cudaCtxResetPersistingL2Cache()` 将所有持久性 L2 缓存行重置为普通状态。
3. 久未触碰的缓存行最终会被自动重置为普通状态。强烈不建议依赖自动重置，因为自动重置发生前所需的时间不确定。

## 4.14.6 管理 L2 预留缓存的利用率

在不同 CUDA 流中并发执行的多个 CUDA 核函数可能为各自的流指定了不同的访问策略窗口。但 L2 预留缓存部分由所有这些并发 CUDA 核函数共享。因此，该预留缓存部分的净利用率是所有并发核函数各自用量的总和。当持久性访问的数据量超过预留 L2 缓存容量时，将内存访问指定为持久性所带来的收益就会递减。

为管理预留 L2 缓存部分的利用率，应用程序必须考虑以下因素：

- L2 预留缓存的大小。
- 可能并发执行的 CUDA 核函数。
- 所有可能并发执行的 CUDA 核函数的访问策略窗口。
- 何时以及如何需要重置 L2，以便普通或流式访问能以同等优先级利用先前预留的 L2 缓存。

## 4.14.7 查询 L2 缓存属性

与 L2 缓存相关的属性是 `cudaDeviceProp` 结构的一部分，可使用 CUDA 运行时 API `cudaGetDeviceProperties` 查询。

CUDA 设备属性包括：

- `l2CacheSize`：GPU 上可用的 L2 缓存量。
- `persistingL2CacheMaxSize`：可预留给持久性内存访问的最大 L2 缓存量。
- `accessPolicyMaxWindowSize`：访问策略窗口的最大大小。

## 4.14.8 控制为持久性内存访问预留的 L2 缓存大小

为持久性内存访问预留的 L2 缓存大小使用 CUDA 运行时 API `cudaDeviceGetLimit` 查询，并使用 CUDA 运行时 API `cudaDeviceSetLimit` 以 `cudaLimit` 形式设置。该限制的最大值为 `cudaDeviceProp::persistingL2CacheMaxSize`。

```c
enum cudaLimit {
    /* 其他字段未列出 */
    cudaLimitPersistingL2CacheSize
};
```
