# 4.8 延迟加载

## 4.8.1 简介

延迟加载（lazy loading）通过等到需要时才加载 CUDA 模块，来缩短程序的初始化时间。对于只使用所包含核函数中一小部分的程序（使用库时很常见），延迟加载特别有效。只要遵循 CUDA 编程模型，延迟加载设计上对用户是透明的。"潜在风险"一节会详细说明。从 CUDA 12.3 起，延迟加载在所有平台上默认启用，但可通过 `CUDA_MODULE_LOADING` 环境变量控制。

## 4.8.2 变更历史

| CUDA 版本 | 变更 |
|---|---|
| 12.3 | 延迟加载性能提升。Windows 上默认启用。 |
| 12.2 | Linux 上默认启用延迟加载。 |
| 11.7 | 首次引入延迟加载，默认禁用。 |

表 17：按 CUDA 版本划分的部分延迟加载变更

## 4.8.3 延迟加载的要求

延迟加载是 CUDA 运行时和驱动的联合功能。只有满足运行时和驱动的版本要求时才可用。

### 4.8.3.1 CUDA 运行时版本要求

延迟加载自 CUDA 运行时 11.7 起可用。由于 CUDA 运行时通常静态链接进程序和库，只有使用 CUDA 11.7+ 工具包编译的程序和库才能受益于延迟加载。用更旧的 CUDA 运行时版本编译的库会急切地加载所有模块。

### 4.8.3.2 CUDA 驱动版本要求

延迟加载要求 515 或更新的驱动。驱动版本低于 515 时不可用，即使使用 CUDA 11.7 或更新的工具包也一样。

### 4.8.3.3 编译器要求

延迟加载不需要编译器支持。用 11.7 之前的编译器编译的 SASS 和 PTX 都可以在启用延迟加载时加载，并完整享受该功能带来的好处。但仍需要 11.7+ 的 CUDA 运行时，如上所述。

### 4.8.3.4 核函数要求

延迟加载不影响包含托管变量的模块，这类模块仍会急切加载。

## 4.8.4 用法

### 4.8.4.1 启用与禁用

把 `CUDA_MODULE_LOADING` 环境变量设为 `LAZY` 即启用延迟加载；设为 `EAGER` 即禁用。从 CUDA 12.3 起，延迟加载在所有平台上默认启用。

### 4.8.4.2 在运行时检查延迟加载是否启用

CUDA 驱动 API 的 `cuModuleGetLoadingMode` API 可用于判断延迟加载是否启用。注意运行该函数前必须先初始化 CUDA。示例如下：

```c
#include "<cuda.h>"
#include "<assert.h>"
#include "<iostream>"

int main() {
    CUmoduleLoadingMode mode;

    assert(CUDA_SUCCESS == cuInit(0));
    assert(CUDA_SUCCESS == cuModuleGetLoadingMode(&mode));

    std::cout << "CUDA Module Loading Mode is " << ((mode == CU_MODULE_LAZY_LOADING) ? "lazy" : "eager") << std::endl;

    return 0;
}
```

### 4.8.4.3 在运行时强制急切加载模块

核函数和变量的加载是自动的，无需显式加载。也可以在不执行的情况下显式加载核函数，方法如下：

- `cuModuleGetFunction()` 函数会把模块加载到设备端内存中。
- `cudaFuncGetAttributes()` 函数会把核函数加载到设备端内存中。

> **注意**
>
> `cuModuleLoad()` 不保证模块会立即加载。

## 4.8.5 潜在风险

延迟加载的设计目标是使用它不需要修改应用程序。但仍有一些注意事项，特别是在应用程序不完全符合 CUDA 编程模型时，如下所述。

### 4.8.5.1 对并发核函数执行的影响

有些程序错误地假设并发核函数执行是有保证的。如果需要跨核函数同步，而核函数执行已被串行化，就可能发生死锁。为尽量减小延迟加载对并发核函数执行的影响，请做到：

- 在启动之前预加载希望并发执行的所有核函数，或
- 用 `CUDA_MODULE_LOADING = EAGER` 运行程序，强制急切加载数据，而不必逐个强制每个函数急切加载。

### 4.8.5.2 大内存分配

延迟加载把 CUDA 模块的内存分配从程序初始化推迟到更接近执行时。如果应用程序在启动时分配掉全部显存，CUDA 在运行时可能无法为模块分配内存。可行的解决办法：

- 用 `cudaMallocAsync()` 代替在启动时分配全部显存的分配器；
- 预留一些缓冲，以补偿核函数的延迟加载；
- 在初始化分配器之前，预加载程序将使用的所有核函数。

### 4.8.5.3 对性能测量的影响

延迟加载可能把 CUDA 模块初始化移入被测的执行窗口，从而扭曲性能测量结果。为避免这种情况：

- 测量前至少做一次预热迭代；
- 在启动被测核函数之前先预加载它。
