# 5.3 C++ 语言支持

nvcc 按以下规范处理 CUDA 代码和设备端代码：

- C++03（ISO/IEC 14882:2003），`--std=c++03` 标志。
- C++11（ISO/IEC 14882:2011），`--std=c++11` 标志。
- C++14（ISO/IEC 14882:2014），`--std=c++14` 标志。
- C++17（ISO/IEC 14882:2017），`--std=c++17` 标志。
- C++20（ISO/IEC 14882:2020），`--std=c++20` 标志。
- C++23（ISO/IEC 14882:2024），`--std=c++23` 标志。

向 nvcc 传递 `-std=c++<version>` 标志会开启与指定版本相关的全部 C++ 特性，并且会以对应的 C++ 方言选项调用主机端预处理器、编译器和链接器。编译器支持所支持标准的全部语言特性，但须遵守后续各节中列出的限制。

### 5.3.6 CUDA C++ 标准库

CUDA 提供 C++ 标准库（STL）的一个实现，称为 libcu++。该库具有以下优点：

- 功能在主机端和设备端均可用。
- 与 CUDA Toolkit 支持的所有 Linux 和 Windows 平台兼容。
- 与最近两个 CUDA Toolkit 大版本所支持的所有 GPU 架构兼容。
- 与当前大版本及前一大版本的所有 CUDA Toolkit 兼容。
- 提供 C++17 向后移植的 C++ 标准库特性，这些特性来自较新的标准版本，包括 C++20、C++23 和 C++26。
- 支持扩展数据类型，如 128 位整数（`__int128`）、半精度浮点数（`__half`）、Bfloat16（`__nv_bfloat16`）和四精度浮点数（`__float128`）。
- 针对设备端代码高度优化。

此外，libcu++ 还提供 C++ 标准库中没有的扩展功能，以提高生产力和应用程序性能。这类功能包括数学函数、内存操作、同步原语、容器扩展、CUDA 内联函数的更高层抽象、C++ PTX 包装器等。

libcu++ 是 CUDA Toolkit 的组成部分，同时也是开源 CCCL 仓库的一部分。

### 5.3.7 C 标准库函数

#### 5.3.7.1 clock() 与 clock64()

```cpp
__host__ __device__ clock_t   clock();
__device__          long long clock64();
```

在设备端代码中执行时，它返回一个每 SM 计数器的值，该计数器每个时钟周期递增一次。在核函数开始和结束时对该计数器采样、将两个值相减，并为每个线程记录结果，可以估算出设备执行该线程所花费的时钟周期数。但该值并不代表设备实际执行该线程指令所花费的时钟周期数。前者大于后者，因为线程是分时复用的。

> **提示**
>
> - 相应的 CUDA C++ 函数 `cuda::std::clock()` 在 `<cuda/std/ctime>` 头文件中提供。
> - 在 `<cuda/std/chrono>` 头文件中还提供了一个可移植的 C++ `<chrono>` 实现，用于类似目的。

#### 5.3.7.2 printf()

```cpp
__host__ __device__ __tile__ int printf(const char* format[, arg, ...]);
```

该函数将格式化输出从核函数打印到主机端的输出流。

核函数内的 `printf()` 函数行为类似于标准 C 库 `printf()` 函数。用户应查阅主机系统的手册页，以了解 `printf()` 行为的完整描述。本质上，传入的 format 字符串会被输出到主机上的一个流。

`printf()` 命令像其他设备端函数一样执行：按线程执行，且在调用线程的上下文中执行。在多线程核函数中，直接调用 `printf()` 将由每个线程使用该线程指定的数据执行。因此，输出字符串会有多个版本出现在主机流中，每个版本对应一个遇到 `printf()` 的线程。

与返回打印字符数的 C 标准 `printf()` 不同，CUDA 的 `printf()` 返回解析的参数个数。如果 format 字符串后没有参数，返回 0。如果 format 字符串为 NULL，返回 -1。如果发生内部错误，返回 -2。

在内部，`printf()` 使用一个共享数据结构，因此调用 `printf()` 可能会改变线程的执行顺序。具体来说，调用 `printf()` 的线程可能比不调用 `printf()` 的线程走更长的执行路径，且路径长度取决于 `printf()` 的参数。但请注意，CUDA 除了在显式的 `__syncthreads()` 屏障处之外，不对线程执行顺序做任何保证。因此，无法判断执行顺序是被 `printf()` 改变了，还是硬件的其他调度行为所致。

`printf()` 函数在 tile 代码中的行为与在 SIMT 设备端代码中不同。在 tile 代码中：

- 参数除了标量外还可以是 tile。传入 tile 参数时，tile 的每个元素按对应的格式说明符打印。
- 返回值始终为提供的参数个数，即使 format 字符串为 NULL 或发生内部错误。
- format 字符串必须是字面量。
- 如果参数个数与格式说明符个数不匹配，会报错。在 SIMT 设备端代码中，这种情形只会产生警告。

**格式说明符**

与标准 `printf()` 一样，format 说明符的形式为：`%[flags][width][.precision][size]type`

支持以下字段。有关所有行为的完整描述，请参阅广泛可用的文档。

- 标志（Flags）：`#`、`' '`、`0`、`+`、`-`
- 宽度（Width）：`*`、`0-9`
- 精度（Precision）：`0-9`
- 大小（Size）：`h`、`l`、`ll`
- 类型（Type）：`%cdiouxXpeEfgGaAs`

**限制**

`printf()` 输出的最终格式化在主机系统上完成。这意味着 format 字符串必须能被主机系统的编译器和 C 库理解。尽管已尽力确保 CUDA 的 `printf()` 函数支持的格式说明符是大多数常见主机编译器所支持格式说明符的通用子集，但具体行为仍取决于主机操作系统。

`printf()` 接受标志与类型的所有有效组合。这是因为它无法判断在最终输出被格式化的主机系统上哪些组合有效、哪些无效。因此，如果程序发出的 format 字符串包含无效组合，输出可能未定义。

`printf()` 函数除 format 字符串外最多可接受 32 个参数。多出的参数会被忽略，格式说明符将原样输出。

由于 Windows 平台（32 位）与 Linux 平台（64 位）上 long 类型的大小不同，在 Linux 机器上编译的核函数放到 Windows 机器上运行，对所有包含 `%ld` 的格式字符串都会产生损坏的输出。为确保安全，建议编译平台与执行平台一致。

**主机端缓冲区**

`printf()` 的输出缓冲区在核函数启动前被设为固定大小。该缓冲区是循环的，因此如果核函数执行期间产生的输出超过缓冲区容量，较早的输出会被覆盖。仅当执行以下任一操作时才会刷新缓冲区：

- 经由 `<<< >>>` 或 `cuLaunchKernel()` 启动核函数：在启动开始时刷新；若 `CUDA_LAUNCH_BLOCKING` 环境变量设为 1，在启动结束时也刷新。
- 经由 `cudaDeviceSynchronize()`、`cuCtxSynchronize()`、`cudaStreamSynchronize()`、`cuStreamSynchronize()`、`cudaEventSynchronize()` 或 `cuEventSynchronize()` 同步。
- 经由任意阻塞版本的 `cudaMemcpy*()` 或 `cuMemcpy*()` 进行内存复制。
- 经由 `cuModuleLoad()` 或 `cuModuleUnload()` 加载/卸载模块。
- 经由 `cudaDeviceReset()` 或 `cuCtxDestroy()` 销毁上下文。
- 在执行经由 `cudaLaunchHostFunc()` 或 `cuLaunchHostFunc()` 添加的流回调之前。

请注意，程序退出时不会自动刷新缓冲区。

以下 API 函数设置和获取用于将 `printf()` 参数及内部元数据传输到主机端的缓冲区大小。默认大小为 1 MB。

- `cudaDeviceGetLimit(size_t* size, cudaLimitPrintfFifoSize)`
- `cudaDeviceSetLimit(cudaLimitPrintfFifoSize, size_t size)`

**示例**

以下代码示例：

```cpp
#include <stdio.h>

__global__ void helloCUDA(float value) {
    printf("Hello thread %d, value=%f\n", threadIdx.x, value);
}

int main() {
    helloCUDA<<<1, 5>>>(1.2345f);
    cudaDeviceSynchronize();
    return 0;
}
```

将输出：

```

Hello thread 1, value=1.2345
Hello thread 4, value=1.2345
Hello thread 0, value=1.2345
Hello thread 3, value=1.2345
```

注意，每个线程都会遇到 `printf()` 命令。因此，输出行数与网格中的线程数相同。

#### 5.3.7.4 malloc() 与 free()

```cpp
__host__ __device__ void* malloc(size_t size);
// 或 <cuda/std/cstdlib> 头文件中的 cuda::std::malloc()、cuda::std::calloc()
```

函数 `malloc()`（设备端）、`cuda::std::malloc()` 和 `cuda::std::calloc()` 从设备堆中分配至少 size 个字节，并返回指向所分配内存的指针。如果内存不足以满足请求，则返回 NULL。返回的指针保证按 16 字节边界对齐。

```cpp
__device__ void* __nv_aligned_device_malloc(size_t size, size_t align);
// 或 <cuda/std/cstdlib> 头文件中的 cuda::std::aligned_alloc()
```

函数 `__nv_aligned_device_malloc()` 和 C++ 的 `cuda::std::aligned_alloc()` 从设备堆中分配至少 size 个字节，并返回指向所分配内存的指针。如果内存不足以满足请求的大小或对齐要求，则返回 NULL。所分配内存的地址是 align 的整数倍。align 必须为非零的 2 的幂。

```cpp
__host__ __device__ void free(void* ptr);
// 或 <cuda/std/cstdlib> 头文件中的 cuda::std::free()
```

设备端函数 `free()` 和 `cuda::std::free()` 释放 ptr 指向的内存，ptr 必须是由之前调用 `malloc()`、`cuda::std::malloc()`、`cuda::std::calloc()`、`__nv_aligned_device_malloc()` 或 `cuda::std::aligned_alloc()` 返回的。如果 ptr 为 NULL，则忽略对 `free()` 或 `cuda::std::free()` 的调用。用同一个 ptr 重复调用 `free()` 或 `cuda::std::free()` 的行为未定义。

某个 CUDA 线程经由 `malloc()`、`cuda::std::malloc()`、`cuda::std::calloc()`、`__nv_aligned_device_malloc()` 或 `cuda::std::aligned_alloc()` 分配的内存，在 CUDA 上下文的整个生命周期内保持分配状态，除非被显式调用 `free()` 或 `cuda::std::free()` 释放。其他 CUDA 线程可以使用这些内存，包括后续核函数启动中的线程。任何 CUDA 线程都可以释放另一个线程分配的内存；但须注意确保同一个指针不会被释放多次。

**堆内存 API**

任何在设备端代码中分配或释放内存的程序（包括 new 和 delete 关键字）都必须事先指定设备内存堆的大小。如果任何程序使用设备内存堆而未显式指定堆大小，则分配一个默认 8 MB 的堆。

以下 API 函数获取和设置堆大小：

- `cudaDeviceGetLimit(size_t* size, cudaLimitMallocHeapSize)`
- `cudaDeviceSetLimit(cudaLimitMallocHeapSize, size_t size)`

授予的堆大小至少为 size 个字节。`cuCtxGetLimit()` 和 `cudaDeviceGetLimit()` 返回当前请求的堆大小。

堆的实际内存分配发生在模块被加载到上下文时——经由 CUDA 驱动 API（参见 Module）显式加载，或经由 CUDA 运行时 API 隐式加载。如果内存分配失败，模块加载会产生 `CUDA_ERROR_SHARED_OBJECT_INIT_FAILED` 错误。

模块加载后不能更改堆大小，且堆不会根据需要动态调整大小。

为设备堆预留的内存，是在主机端 CUDA API 调用（如 `cudaMalloc()`）分配的内存之外另行分配的。

**与主机端内存 API 的互操作性**

经由设备端函数 `malloc()`、`cuda::std::malloc()`、`cuda::std::calloc()`、`__nv_aligned_device_malloc()`、`cuda::std::aligned_alloc()` 或 new 关键字分配的内存，不能与 `cudaMalloc`、`cudaMemcpy` 或 `cudaMemset` 等运行时或驱动 API 调用一起使用或释放。同样，经由主机端运行时 API 分配的内存，也不能使用设备端函数 `free()`、`cuda::std::free()` 或 delete 关键字释放。

每线程分配示例：

```cpp
#include <stdlib.h>
#include <stdio.h>

__global__ void single_thread_allocation_kernel() {
    size_t size = 123;
    char* ptr = (char*) malloc(size);
    memset(ptr, 0, size);
    printf("Thread %d got pointer: %p\n", threadIdx.x, ptr);
    free(ptr);
}

int main() {
    // 设置 128 MB 的堆大小。
    // 注意，这必须在启动任何核函数之前完成。
    cudaDeviceSetLimit(cudaLimitMallocHeapSize, 128 * 1024 * 1024);
    single_thread_allocation_kernel<<<1, 5>>>();
    cudaDeviceSynchronize();
    return 0;
}
```

将输出：

```
Thread 0 got pointer: 0x20d5ffe20
Thread 1 got pointer: 0x20d5ffec0
Thread 2 got pointer: 0x20d5fff60
Thread 3 got pointer: 0x20d5f97c0
Thread 4 got pointer: 0x20d5f9720
```

注意每个线程都会遇到 `malloc()` 和 `memset()` 命令，因此各自获得并初始化自己的分配。

每线程块分配示例：

```cpp
#include <stdlib.h>

__global__ void block_level_allocation_kernel() {
     __shared__ int* data;
     // 块中第一个线程执行分配，并通过共享内存
     // 与所有其他线程共享指针，以便合并访存。

     if (threadIdx.x == 0) {
         size_t size = blockDim.x * 64; // 每个线程分配 64 字节。
         data = (int*) malloc(size);
     }
     __syncthreads();
     // 检查是否失败
    if (data == nullptr)
        return;

    // 线程对内存编制索引，保证合并
    for (int i = 0; i < 64; ++i)
        data[i * blockDim.x + threadIdx.x] = threadIdx.x;
    // 确保所有线程完成后再释放
    __syncthreads();

    // 只能有一个线程释放内存！
    if (threadIdx.x == 0)
        free(data);
}

int main() {
    cudaDeviceSetLimit(cudaLimitMallocHeapSize, 128 * 1024 * 1024);
    block_level_allocation_kernel<<<10, 128>>>();
    cudaDeviceSynchronize();
    return 0;
}
```

在多次核函数启动之间保持分配的示例：

```cpp
#include <stdlib.h>
#include <stdio.h>

const int NUM_BLOCKS = 20;

__device__ int* data_ptrs[NUM_BLOCKS]; // 每块一个指针

__global__ void allocate_memory_kernel() {
    // 块中只有第一个线程执行分配，
    // 因为每块只需要一次分配。
    if (threadIdx.x == 0)
        data_ptrs[blockIdx.x] = (int*) malloc(blockDim.x * 4);
    __syncthreads();
    // 检查是否失败
    if (data_ptrs[blockIdx.x] == nullptr)
        return;
    // 所有线程并行清零数据
    data_ptrs[blockIdx.x][threadIdx.x] = 0;
}

// 简单示例：将线程 ID 存入每个元素
__global__ void use_memory_kernel() {
    int* ptr = data_ptrs[blockIdx.x];
    if (ptr != nullptr)
        ptr[threadIdx.x] += threadIdx.x;
}

// 释放前打印缓冲区内容
__global__ void free_memory_kernel() {
    int* ptr = data_ptrs[blockIdx.x];
    if (ptr != nullptr)
        printf("Block %d, Thread %d: final value = %d\n",
            blockIdx.x, threadIdx.x, ptr[threadIdx.x]);
    // 只能由一个线程释放！
    if (threadIdx.x == 0)
        free(ptr);
}

int main() {
    cudaDeviceSetLimit(cudaLimitMallocHeapSize, 128*1024*1024);
    // 分配内存
    allocate_memory_kernel<<<NUM_BLOCKS, 10>>>();

       // 使用内存
       use_memory_kernel<<<NUM_BLOCKS, 10>>>();
       use_memory_kernel<<<NUM_BLOCKS, 10>>>();
       use_memory_kernel<<<NUM_BLOCKS, 10>>>();

       // 释放内存
       free_memory_kernel<<<NUM_BLOCKS, 10>>>();
       cudaDeviceSynchronize();
       return 0;
}
```

### 5.3.8 lambda 表达式

编译器通过将其与最内层封闭函数作用域的执行空间关联，来确定 lambda 表达式或闭包类型（C++11）的执行空间。如果没有封闭函数作用域，执行空间被指定为 `__host__`。

也可以使用扩展 lambda 语法显式指定执行空间。

示例：

```cpp
auto global_lambda = [](){ return 0; }; // __host__

void host_function() {
   auto lambda1 = [](){ return 1; };             // __host__
   [](){ return 3; };                            // __host__，闭包类型（lambda 表达式的函数体）

}

__device__ void device_function() {
  auto lambda2 = [](){ return 2; };              // __device__
}

__global__ void kernel_function(void) {
  auto lambda3 = [](){ return 3; };   // __device__
}

__host__ __device__ void host_device_function() {
  auto lambda4 = [](){ return 4; };   // __host__ __device__
}

__tile__ void tile_function() {
  auto lambda5 = [](){ return 5; };              // __tile__
}

__tile__ __device__ void tile_device_function() {
  auto lambda6 = [](){ return 6; };   // __tile__ __device__
}

using function_ptr_t = int (*)();

__device__ void device_function(float          value,
                                function_ptr_t ptr = [](){ return 4; } /* __host__ */) {}
```

#### 5.3.8.1 lambda 表达式与 `__global__` 函数形参

只有当 lambda 表达式或闭包类型的执行空间为 `__device__` 或 `__host__ __device__` 时，才能将其用作 `__global__` 函数的实参。全局或命名空间作用域的 lambda 表达式不能用作 `__global__` 函数的实参。

示例：

```cpp
template <typename T>
 __global__ void kernel(T input) {}

 __device__ void device_function() {
     // 设备端核函数调用需要单独编译（-rdc=true 标志）
     kernel<<<1, 1>>>([](){});
     kernel<<<1, 1>>>([] __device__() {});           // 扩展 lambda
     kernel<<<1, 1>>>([] __host__ __device__() {}); // 扩展 lambda
 }

 auto global_lambda = [] __host__ __device__() {};

 void host_function() {
     kernel<<<1, 1>>>([] __device__() {});          // 正确，扩展 lambda

     kernel<<<1, 1>>>([] __host__ __device__() {}); // 正确，扩展 lambda

 // kernel<<<1, 1>>>([](){});                      // 错误，闭包类型具有主机端执行空间

 // kernel<<<1, 1>>>(global_lambda);               // 错误，扩展 lambda，但位于全局作用域

 }
```

#### 5.3.8.2 扩展 lambda

nvcc 标志 `--extended-lambda` 允许在 lambda 表达式中显式注解执行空间。这些注解应出现在 lambda 引导符之后、可选的 lambda 声明符之前。

指定 `--extended-lambda` 标志时，nvcc 定义宏 `__CUDACC_EXTENDED_LAMBDA__`。

- 扩展 lambda 定义在 `__host__` 或 `__host__ __device__` 函数的直接或嵌套块作用域内。
- 扩展设备端 lambda 是用 `__device__` 关键字注解的 lambda 表达式。
- 扩展主机设备端 lambda 是用 `__host__ __device__` 关键字注解的 lambda 表达式。

与标准 lambda 表达式不同，扩展 lambda 可以用作 `__global__` 函数的类型实参。

示例：

```cpp
void host_function() {
    auto lambda1 = [] {};                                 // 不是扩展 lambda：没有显式的执行空间注解
       auto lambda2 = [] __device__ {};                       // 扩展 lambda
       auto lambda3 = [] __host__ __device__ {};              // 扩展 lambda
       auto lambda4 = [] __host__ {};                         // 不是扩展 lambda
}

__host__ __device__ void host_device_function() {
     auto lambda1 = [] {};                     // 不是扩展 lambda：没有显式的执行空间注解

     auto lambda2 = [] __device__ {};          // 扩展 lambda
     auto lambda3 = [] __host__ __device__ {}; // 扩展 lambda
     auto lambda4 = [] __host__ {};            // 不是扩展 lambda
}

__device__ void device_function() {
     // 此函数内的 lambda 都不是扩展 lambda，
     // 因为封闭函数不是 __host__ 或 __host__ __device__ 函数。

     auto lambda1 = [] {};
     auto lambda2 = [] __device__ {};
     auto lambda3 = [] __host__ __device__ {};
     auto lambda4 = [] __host__ {};
}

auto global_lambda = [] __host__ __device__ { }; // 不是扩展 lambda，因为它不是定义在
                                                 // __host__ 或 __host__ __device__ 函数内
```

#### 5.3.8.3 扩展 lambda 类型特性

编译器提供类型特性，用于在编译时检测扩展 lambda 的闭包类型。

```cpp
bool __nv_is_extended_device_lambda_closure_type(type);
```

如果 type 是为扩展 `__device__` lambda 创建的闭包类，该函数返回 true，否则返回 false。

```cpp
bool __nv_is_extended_device_lambda_with_preserved_return_type(type);
```

如果 type 是为扩展 `__device__` lambda 创建的闭包类且该 lambda 用尾置返回类型定义，该函数返回 true，否则返回 false。如果尾置返回类型定义引用了任一 lambda 形参名，则返回类型不被保留。

```cpp
bool __nv_is_extended_host_device_lambda_closure_type(type);
```

如果 type 是为扩展 `__host__ __device__` lambda 创建的闭包类，该函数返回 true，否则返回 false。

lambda 类型特性可用于所有编译模式，无论是否启用 lambda 或扩展 lambda。若扩展 lambda 模式未激活，这些特性始终返回 false。

示例：

```cpp
auto lambda0 = [] __host__ __device__ { };

void host_function() {
    auto lambda1 = [] { };
    auto lambda2 = [] __device__ { };
    auto lambda3 = [] __host__ __device__ { };
    auto lambda4 = [] __device__ () -> double { return 3.14; }
    auto lambda5 = [] __device__ (int x) -> decltype(&x) { return 0; }

      using lambda0_t = decltype(lambda0);
      using lambda1_t = decltype(lambda1);
      using lambda2_t = decltype(lambda2);
      using lambda3_t = decltype(lambda3);
      using lambda4_t = decltype(lambda4);
      using lambda5_t = decltype(lambda5);

    // 'lambda0' 不是扩展 lambda，因为它定义在函数作用域之外
    static_assert(!__nv_is_extended_device_lambda_closure_type(lambda0_t));
    static_assert(!__nv_is_extended_device_lambda_with_preserved_return_type(lambda0_t));

    static_assert(!__nv_is_extended_host_device_lambda_closure_type(lambda0_t));



    // 'lambda1' 不是扩展 lambda，因为它没有执行空间注解
    static_assert(!__nv_is_extended_device_lambda_closure_type(lambda1_t));
    static_assert(!__nv_is_extended_device_lambda_with_preserved_return_type(lambda1_t));

    static_assert(!__nv_is_extended_host_device_lambda_closure_type(lambda1_t));



    // 'lambda2' 是扩展设备端 lambda
    static_assert(__nv_is_extended_device_lambda_closure_type(lambda2_t));
    static_assert(!__nv_is_extended_device_lambda_with_preserved_return_type(lambda2_t));

    static_assert(!__nv_is_extended_host_device_lambda_closure_type(lambda2_t));



    // 'lambda3' 是扩展主机设备端 lambda
    static_assert(!__nv_is_extended_device_lambda_closure_type(lambda3_t));
    static_assert(!__nv_is_extended_device_lambda_with_preserved_return_type(lambda3_t));

    static_assert(__nv_is_extended_host_device_lambda_closure_type(lambda3_t));



    // 'lambda4' 是带保留返回类型的扩展设备端 lambda
    static_assert(__nv_is_extended_device_lambda_closure_type(lambda4_t));
    static_assert(__nv_is_extended_device_lambda_with_preserved_return_type(lambda4_t));

    static_assert(!__nv_is_extended_host_device_lambda_closure_type(lambda4_t));



     // 'lambda5' 不是带保留返回类型的扩展设备端 lambda，
     // 因为它在尾置返回类型中引用了 operator() 的形参类型。

     static_assert(__nv_is_extended_device_lambda_closure_type(lambda5_t));
     static_assert(!__nv_is_extended_device_lambda_with_preserved_return_type(lambda5_t));

     static_assert(!__nv_is_extended_host_device_lambda_closure_type(lambda5_t));

}
```

#### 5.3.8.4 扩展 lambda 限制

在调用主机端编译器之前，CUDA 编译器会将扩展 lambda 表达式替换为定义在命名空间作用域中的占位符类型的实例。该占位符类型的模板实参需要取封闭原始扩展 lambda 表达式的函数的地址。这对于正确执行模板实参涉及扩展 lambda 闭包类型的任何 `__global__` 函数模板是必要的。封闭函数的计算方式如下。

根据定义，扩展 lambda 出现在 `__host__` 或 `__host__ __device__` 函数的直接或嵌套块作用域内。

- 如果该函数不是 lambda 表达式的 operator()，则它被视为扩展 lambda 的封闭函数。
- 否则，扩展 lambda 定义在一个或多个封闭 lambda 表达式的 operator() 的直接或嵌套块作用域内。
  - 如果最外层 lambda 表达式定义在函数 F 的直接或嵌套块作用域内，则 F 是计算得到的封闭函数。
  - 否则，封闭函数不存在。

示例：

```cpp
void host_function() {
     auto lambda1 = [] __device__ { }; // lambda1 的封闭函数是 "host_function()"

     auto lambda2 = [] {
         auto lambda3 = [] {
             auto lambda4 = [] __host__ __device__ { }; // lambda4 的封闭函数是 "host_function"

         };
     };
}

auto global_lambda = [] {
     auto lambda5 = [] __host__ __device__ { }; // lambda5 的封闭函数不存在

};
```

**扩展 lambda 限制**

1. 扩展 lambda 不能定义在另一个扩展 lambda 表达式内部。示例：

```cpp
      void host_function() {
          auto lambda1 = [] __host__ __device__ {
               // 错误，扩展 lambda 定义在另一个扩展 lambda 内
              auto lambda2 = [] __host__ __device__ { };
          };
      }
```

2. 扩展 lambda 不能定义在泛型 lambda 表达式内部。示例：

```cpp
      void host_function() {
          auto lambda1 = [] (auto) {
               // 错误，扩展 lambda 定义在泛型 lambda 内
              auto lambda2 = [] __host__ __device__ { };
          };
      }
```

3. 如果扩展 lambda 定义在一个或多个嵌套 lambda 表达式的直接或嵌套块作用域内，则最外层 lambda 表达式必须定义在某个函数的直接或嵌套块作用域内。示例：

```cpp
      auto lambda1 = [] {
           // 错误，最外层封闭 lambda 不是定义在非 lambda operator() 函数内

           auto lambda2 = [] __host__ __device__ { };
      };
```

4. 扩展 lambda 的封闭函数必须具名，且其地址必须可访问。如果封闭函数是类成员，必须满足以下条件：

   - 封闭该成员函数的所有类都必须有名字。
   - 该成员函数在其父类中不得具有 private 或 protected 访问权限。
   - 所有封闭类在其各自父类中不得具有 private 或 protected 访问权限。

   示例：

```cpp
      void host_function() {
          auto lambda1 = [] __device__ { return 0; }; // 正确
          {
              auto lambda2 = [] __device__          { return 0; }; // 正确
              auto lambda3 = [] __device__ __host__ { return 0; }; // 正确
          }
      }

      struct MyStruct1 {
           MyStruct1() {
               auto lambda4 = [] __device__ { return 0; }; // 错误，封闭函数的地址不可访问

           }
      };

    class MyStruct2 {
         void foo() {
             auto temp1 = [] __device__ { return 10; }; // 错误，封闭函数在父类中为私有访问

         }

         struct MyStruct3 {
             void foo() {
                 auto temp1 = [] __device__ { return 10; }; // 错误，封闭类 MyStruct3 在其父类中为私有访问

             }
         };
    };
```

5. 在扩展 lambda 定义处，必须能够无歧义地取封闭例程的地址。但这并非总是可行，例如当别名声明用同名阴影遮蔽了模板类型实参时。示例：

```cpp
    template <typename T>
    struct A {
        using Bar = void;
        void test();
    };

    template<>
    struct A<void> { };

    template <typename Bar>
    void A<Bar>::test() {
         // 在发送给主机端编译器的代码中，nvcc 会在此注入一个取地址
         // 表达式，形式如下：

         //   (void (A< Bar> ::*)(void))(&A::test))
         // 但类别名 'Bar'（指向 void）遮蔽了模板实参 'Bar'，

         // 导致 A<int>::test 中的取地址表达式实际引用的是：

         //    (void (A< void> ::*)(void))(&A::test))
         // 这没有正确地取封闭例程 'A<int>::test' 的地址。

         auto lambda1 = [] __host__ __device__ { return 4; };
    }

    int main() {
        A<int> var;
        var.test();
    }
```

6. 扩展 lambda 不能定义在函数内局部类中。示例：

```cpp
    void host_function() {
        struct MyStruct {
            void bar() {
                       // 错误，bar() 是函数内局部类的成员
                       auto lambda2 = [] __host__ __device__ { return 0; };
                  }
             };
      }
```

7. 扩展 lambda 的封闭函数不能具有推导的返回类型。示例：

```cpp
      auto host_function() {
          // 错误，host_function() 的返回类型是推导的
          auto lambda3 = [] __host__ __device__ { return 0; };
      }
```

8. 主机设备端扩展 lambda 不能是泛型 lambda，即不能是带 auto 形参类型的 lambda。示例：

```cpp
      void host_function() {
           // 错误，__host__ __device__ 扩展 lambda 不能是泛型 lambda

           auto lambda1 = [] __host__ __device__ (auto i) { return i; };

             // 错误，主机设备端扩展 lambda 不能是泛型 lambda
             auto lambda2 = [] __host__ __device__ (auto... i) {
                 return sizeof...(i);
             };
      }
```

9. 如果封闭函数是函数或成员模板的实例化，或该函数是类模板的成员，则模板必须满足以下约束：

   - 模板最多只能有一个可变参数，且它必须列在模板形参列表的最后。
   - 模板形参必须具名。
   - 模板实例化实参类型不能涉及函数内局部类型（扩展 lambda 的闭包类型除外），也不能涉及 private 或 protected 类成员。

   示例 1：

```cpp
      template <template <typename...> class T,
                typename... P1,
                typename... P2>
      void bar1(const T<P1...>, const T<P2...>) {
          // 错误，封闭函数有多个参数包
          auto lambda = [] __device__ { return 10; };
      }

      template <template <typename...> class T,
                typename... P1,
                typename    T2>
      void bar2(const T<P1...>, T2) {
          // 错误，对于封闭函数，参数包不在模板形参列表的最后
            auto lambda = [] __device__ { return 10; };
     }

     template <typename T, T>
     void bar3() {
          // 错误，对于封闭函数，第二个模板形参未具名

          auto lambda = [] __device__ { return 10; };
     }
```

   示例 2：

```cpp
     template <typename T>
     void bar4() {
         auto lambda1 = [] __device__ { return 10; };
     }

     class MyStruct {
         struct MyNestedStruct {};

            friend int main();
     };

     int main() {
          struct MyLocalStruct {};
          // 错误，bar4() 中的设备端 lambda 的封闭函数
          // 用 main 的局部类型实例化

          bar4<MyLocalStruct>();

            // 错误，bar4 中的设备端 lambda 的封闭函数用
            // 是类的私有成员的类型实例化
            bar4<MyStruct::MyNestedStruct>();
     }
```

10. 对于 Microsoft Visual Studio 主机端编译器，封闭函数必须具有外部链接。此限制存在是因为主机端编译器不支持将非外部链接函数的地址用作模板实参。CUDA 编译器变换需要这些地址来支持扩展 lambda。

11. 对于 Microsoft Visual Studio 主机端编译器，扩展 lambda 不得定义在 `if constexpr` 块体内。

12. 扩展 lambda 对捕获变量有以下限制：

    - 在发送给主机端编译器的代码中，变量可能先按值传给一系列辅助函数，再被直接用于初始化表示扩展 lambda 闭包类型的类类型的字段。然而，C++ 标准规定，捕获变量应用于直接初始化闭包类型的字段。
    - 变量只能按值捕获。
    - 如果数组类型的变量的数组维度大于 7，则不能捕获该变量。
    - 对于数组类型变量，在发送给主机端编译器的代码中，闭包类型的数组字段先默认初始化，然后每个数组元素从被捕获数组变量的对应元素复制赋值。因此，数组元素类型在主机端代码中必须同时是默认可构造且可复制赋值的。
    - 作为可变参数包元素的函数形参不能被捕获。
    - 捕获变量的类型不能是函数内局部类型（扩展 lambda 闭包类型除外），也不能是 private 或 protected 类成员。
    - 主机设备端扩展 lambda 不支持初始化捕获（init-capture）。但设备端扩展 lambda 支持初始化捕获，除非初始化器是数组或 `std::initializer_list` 类型。
    - 扩展 lambda 的函数调用运算符不是 constexpr。扩展 lambda 的闭包类型不是字面量类型。声明扩展 lambda 时不能使用 constexpr 和 consteval 说明符。
    - 除非变量已在 if-constexpr 块之外被隐式捕获，或出现在扩展 lambda 的显式捕获列表中，否则不能在词法上嵌套于扩展 lambda 内的 if-constexpr 块中隐式捕获变量。

    示例：

```cpp
      void host_function() {
           // 正确，扩展设备端 lambda 允许初始化捕获

           auto lambda1 = [x = 1] __device__ () { return x; };

             // 错误，扩展主机设备端 lambda 不允许初始化捕获
             auto lambda2 = [x = 1] __host__ __device__ () { return x; };

          int a = 1;
          // 错误，扩展 __device__ lambda 不能按引用捕获变量

          auto lambda3 = [&a] __device__ () { return a; };

             // 错误，扩展设备端 lambda 不允许按引用捕获
             auto lambda4 = [&x = a] __device__ () { return x; };

          struct MyStruct {};
          MyStruct s1;
          // 错误，捕获变量的类型不能使用函数内局部类型

          auto lambda6 = [s1] __device__ () { };

             // 错误，初始化捕获不能是 std::initializer_list 类型
             auto lambda7 = [x = {11}] __device__ () { };

             std::initializer_list<int> b = {11,22,33};
             // 错误，初始化捕获不能是 std::initializer_list 类型
             auto lambda8 = [x = b] __device__ () { };

             int   var     = 4;
          auto lambda9 = [=] __device__ {
              int result = 0;
              if constexpr(false) {
                  // 错误，扩展设备端 lambda 不能在 if-constexpr 上下文中首次捕获 'var'

                  result += var;
              }
              return result;
          };

          auto lambda10 = [var] __device__ {
              int result = 0;
              if constexpr(false) {
                  // 正确，'var' 已列在扩展 lambda 的显式捕获列表中

                  result += var;
              }
              return result;
          };

          auto lambda11 = [=] __device__ {
              int result = var;
              if constexpr(false) {
                  // 正确，'var' 已在 'if-constexpr' 块之外被隐式捕获

                  result += var;
              }
              return result;
          };
     }
```

13. 解析函数时，CUDA 编译器为函数中的每个扩展 lambda 赋予一个计数器值。该计数器值用于传递给主机端编译器的替换命名类型中。因此，函数内扩展 lambda 的有无，不应依赖于 `__CUDA_ARCH__` 的特定取值，也不应依赖于 `__CUDA_ARCH__` 是否未定义。示例：

```cpp
     template <typename T>
     __global__ void kernel(T in) { in(); }

     __host__ __device__ void host_device_function() {
         // 错误，扩展 lambda 的数量和相对声明顺序
         // 依赖于 __CUDA_ARCH__
     #if defined(__CUDA_ARCH__)
         auto lambda1 = [] __device__ { return 0; };
         auto lambda2 = [] __host__ __device__ { return 10; };
     #endif
         auto lambda3 = [] __device__ { return 4; };
         kernel<<<1, 1>>>(lambda3);
     }
```

14. 如上所述，CUDA 编译器将主机端函数中定义的设备端扩展 lambda 替换为定义在命名空间作用域的占位符类型。除非特性 `__nv_is_extended_device_lambda_with_preserved_return_type()` 对该扩展 lambda 的闭包类型返回 true，否则该占位符类型不会定义与原始 lambda 声明等价的 operator() 函数。因此，在主机端代码中试图确定这种 lambda 的 operator() 函数的返回类型或形参类型可能不正确，因为主机端编译器处理的代码在语义上与 CUDA 编译器处理的输入代码不同。但在设备端代码内省 operator() 函数的返回类型或形参类型是可以接受的。注意，该限制不适用于主机端或设备端扩展 lambda——若特性 `__nv_is_extended_device_lambda_with_preserved_return_type()` 返回 true。示例：

```cpp
      #include <cuda/std/type_traits>

      const char& getRef(const char* p) { return *p; }

      void foo() {
          auto lambda1 = [] __device__ { return "10"; };

             // 错误，试图在主机端代码中提取设备端 lambda 的返回类型
             cuda::std::result_of<decltype(lambda1)()>::type xx1 = "abc";

             auto lambda2 = [] __host__ __device__ { return "10"; };

             // 正确，lambda2 表示主机设备端扩展 lambda
             cuda::std::result_of<decltype(lambda2)()>::type xx2 = "abc";

             auto lambda3 = [] __device__ () -> const char* { return "10"; };

          // 正确，lambda3 表示带保留返回类型的设备端扩展 lambda
          cuda::std::result_of<decltype(lambda3)()>::type xx2 = "abc";
          static_assert(cuda::std::is_same_v<cuda::std::result_of<decltype(lambda3)()>::type, const char*>);



           auto lambda4 = [] __device__ (char x) -> decltype(getRef(&x)) { return 0; };
           // lambda4 的返回类型未被保留，因为它在尾置返回类型中
           // 引用了 operator() 的形参类型。
           static_assert(!__nv_is_extended_device_lambda_with_preserved_return_type(decltype(lambda4)));

      }
```

15. 对于扩展设备端 lambda：

    - 仅在设备端代码中支持对 operator() 形参类型的内省。
    - 仅在设备端代码中支持对 operator() 返回类型的内省，除非特性函数 `__nv_is_extended_device_lambda_with_preserved_return_type()` 返回 true。

16. 如果扩展 lambda 作为 `__global__` 函数的实参从主机端传递到设备端代码，则 lambda 函数体中捕获变量的任何表达式必须保持不变，无论 `__CUDA_ARCH__` 宏是否定义、取何值。此限制存在是因为 lambda 闭包类的布局取决于编译器处理 lambda 表达式时遇到被捕获变量的顺序。如果闭包类布局在设备端与主机端编译之间不同，程序可能执行错误。示例：

```cpp
     __device__ int result;

     template <typename T>
     __global__ void kernel(T in) { result = in(); }

     void foo(void) {
         int x1 = 1;
         // 错误，"x1" 仅在定义了 __CUDA_ARCH__ 时才被捕获。
         auto lambda1 = [=] __host__ __device__ {
     #ifdef __CUDA_ARCH__
             return x1 + 1;
     #else
             return 10;
     #endif
         };
         kernel<<<1, 1>>>(lambda1);
     }
```

17. 如前所述，CUDA 编译器将扩展设备端 lambda 表达式替换为发送给主机端编译器的代码中的占位符类型实例。该占位符类型在主机端代码中不定义指针到函数的转换运算符；但在设备端代码中提供该转换运算符。注意，该限制不适用于主机设备端扩展 lambda。示例：

```cpp
     template <typename T>
     __global__ void kernel(T in) {
         int (*fp)(double) = in;
         fp(0); // 正确，设备端代码中的转换受支持
         auto lambda1 = [](double) { return 1; };
     }

     void foo() {
           auto lambda_device      = [] __device__ (double) { return 1; };
           auto lambda_host_device = [] __host__ __device__ (double) { return 1; };

           kernel<<<1, 1>>>(lambda_device);
           kernel<<<1, 1>>>(lambda_host_device);

             // 正确，主机端代码中支持 __host__ __device__ lambda 的转换
             int (*fp1)(double) = lambda_host_device;

             // 错误，主机端代码中不支持设备端 lambda 的转换
             int (*fp2)(double) = lambda_device;
     }
```

18. 如前所述，CUDA 编译器将扩展设备端或主机设备端 lambda 表达式替换为发送给主机端编译器的代码中的占位符类型实例。该占位符类型可能定义 C++ 特殊成员函数，如构造函数和析构函数。因此，某些标准 C++ 类型特性对扩展 lambda 闭包类型在 CUDA 前端编译器中的结果可能与在主机端编译器中的结果不同。受影响的类型特性有：`std::is_trivially_copyable`、`std::is_trivially_constructible`、`std::is_trivially_copy_constructible`、`std::is_trivially_move_constructible`、`std::is_trivially_destructible`。必须注意确保这些特性的结果不被用于实例化 `__global__`、`__device__`、`__constant__` 或 `__managed__` 函数或变量模板。示例：

```cpp
      #include <cstdio>
      #include <type_traits>

      template <bool b>
      void __global__ kernel() { printf("hi"); }

      template <typename T>
      void kernel_launch() {
           // 错误，此核函数启动可能失败，因为 CUDA 前端编译器
           // 和主机端编译器可能对扩展 lambda 闭包类型的
           // std::is_trivially_copyable_v 特性结果不一致
           kernel<std::is_trivially_copyable_v<T>><<<1,1>>>();
           cudaDeviceSynchronize();
      }

      int main() {
          int x        = 0;
          auto lambda1 = [=] __host__ __device__ () { return x; };
          kernel_launch<decltype(lambda1)>();
      }
```

CUDA 编译器将对第 1–12 项所述情形的子集生成编译器诊断；第 13–17 项不生成诊断，但主机端编译器可能无法编译生成的代码。

#### 5.3.8.5 主机设备端 lambda 优化说明

与设备端 lambda 不同，主机设备端 lambda 可以从主机端代码调用。如前所述，CUDA 编译器将主机端代码中定义的扩展 lambda 表达式替换为命名占位符类型的实例。扩展主机设备端 lambda 的占位符类型经由间接函数调用调用原始 lambda 的 operator()。若扩展 lambda 模式未激活，这些特性始终返回 false。

间接函数调用的存在可能导致主机端编译器对扩展主机设备端 lambda 的优化不如隐式或显式仅 `__host__` 的 lambda。在后一种情形下，主机端编译器可以轻松将 lambda 函数体内联到调用上下文中。但当遇到扩展主机设备端 lambda 时，主机端编译器可能无法轻松内联原始 lambda 函数体。

#### 5.3.8.6 *this 按值捕获

根据 C++11/C++14 规则，当 lambda 定义在非静态类成员函数内且 lambda 函数体引用类成员变量时，必须按值捕获该类的 this 指针，而不是被引用的成员变量。如果该 lambda 是在主机端函数中定义的扩展设备端或主机设备端 lambda 并在 GPU 上执行，当 this 指针指向主机端内存时，在 GPU 上访问被引用的成员变量会导致运行时错误。

示例：

```cpp
#include <cstdio>

template <typename T>
__global__ void foo(T in) { printf("value = %d\n", in()); }

struct MyStruct {
    int var;

     __host__ __device__ MyStruct() : var(10) {};

     void run() {
         auto lambda1 = [=] __device__ {
             // 对 "var" 的引用导致按值捕获 'this' 指针（MyStruct*）

             return var + 1;
         };
         // 核函数启动在运行时失败，因为 GPU 无法访问 'this->var'

         foo<<<1, 1>>>(lambda1);
         cudaDeviceSynchronize();
     }
};

int main() {
    MyStruct s1;
    s1.run();
}
```

C++17 通过引入新的 *this 捕获模式解决了这一问题。在该模式下，编译器复制 *this 所表示的对象，而不是按值捕获 this 指针。*this 捕获模式在 P0018R3 中有更详细的描述。

CUDA 编译器支持对定义在 `__device__` 和 `__global__` 函数内的 lambda，以及使用 `--extended-lambda` 标志时定义在主机端代码中的扩展设备端 lambda，使用 *this 捕获模式。

以下是将上述示例改为使用 *this 捕获模式的版本：

```cpp
#include <cstdio>

template <typename T>
__global__ void foo(T in) { printf("\n value = %d", in()); }

struct MyStruct {
    int var;
    __host__ __device__ MyStruct() : var(10) { };

     void run() {
         // 注意 "*this" 捕获说明
         auto lambda1 = [=, *this] __device__ {
               // 对 "var" 的引用导致按值捕获 '*this' 所表示的对象，
               // GPU 代码将访问 'copy_of_star_this->var'
               return var + 1;
           };
           // 核函数启动成功
           foo<<<1, 1>>>(lambda1);
           cudaDeviceSynchronize();
       }
};

int main() {
    MyStruct s1;
    s1.run();
}
```

除非所选语言方言启用了 *this 捕获，否则主机端代码中定义的未注解 lambda 或扩展主机设备端 lambda 不允许使用 *this 捕获模式。以下是支持与不支持用法的示例：

```cpp
struct MyStruct {
    int var;
    __host__ __device__ MyStruct() : var(10) { };

       void host_function() {
           // 正确，在扩展设备端 lambda 中使用
           auto lambda1 = [=, *this] __device__ { return var; };

           // 在扩展主机设备端 lambda 中使用
           // 若语言方言未启用 *this 捕获则报错
           auto lambda2 = [=, *this] __host__ __device__ { return var; };

           // 在主机端函数的未注解 lambda 中使用
           // 若语言方言未启用 *this 捕获则报错
           auto lambda3 = [=, *this] { return var; };
       }

       __device__ void device_function() {
           // 正确，在设备端函数中定义的 lambda 中使用
           auto lambda1 = [=, *this] __device__ { return var; };

           // 正确，在设备端函数中定义的 lambda 中使用
           auto lambda2 = [=, *this] __host__ __device__ { return var; };

           // 正确，在设备端函数中定义的 lambda 中使用
           auto lambda3 = [=, *this] { return var; };
       }

       __host__ __device__ void host_device_function() {
           // 正确，在扩展设备端 lambda 中使用
           auto lambda1 = [=, *this] __device__ { return var; };

           // 在扩展主机设备端 lambda 中使用
           // 若语言方言未启用 *this 捕获则报错
           auto lambda2 = [=, *this] __host__ __device__ { return var; };

           // 在主机设备端函数的未注解 lambda 中使用
           // 若语言方言未启用 *this 捕获则报错
           auto lambda3 = [=, *this] { return var; };
     }
};
```

### 5.3.9 多态函数包装器

nvfunctional 头文件提供了一个多态函数包装器类模板 `nvstd::function`。该类模板的实例可以存储、复制和调用任何可调用目标，例如 lambda 表达式。`nvstd::function` 可用于主机端和设备端代码。

示例：

```cpp
#include <nvfunctional>

__host__            int host_function()        { return 1; }
__device__          int device_function()      { return 2; }
__host__ __device__ int host_device_function() { return 3; }

__global__ void kernel(int* result) {
    nvstd::function<int()> fn1 = device_function;
    nvstd::function<int()> fn2 = host_device_function;
    nvstd::function<int()> fn3 = [](){ return 10; };
    *result                    = fn1() + fn2() + fn3();
}

__host__ __device__ void host_device_test(int* result) {
    nvstd::function<int()> fn1 = host_device_function;
    nvstd::function<int()> fn2 = [](){ return 10; };
    *result                    = fn1() + fn2();
}

__host__ void host_test(int* result) {
    nvstd::function<int()> fn1 = host_function;
    nvstd::function<int()> fn2 = host_device_function;
    nvstd::function<int()> fn3 = [](){ return 10; };
    *result                    = fn1() + fn2() + fn3();
}
```

非法情形：
- 主机端代码中的 `nvstd::function` 实例不能用 `__device__` 函数的地址初始化，也不能用其 `operator()` 为 `__device__` 函数的仿函数初始化。
- 同样，设备端代码中的 `nvstd::function` 实例不能用 `__host__` 函数的地址初始化，也不能用其 `operator()` 为 `__host__` 函数的仿函数初始化。
- `nvstd::function` 实例在运行时不能从主机端代码传到设备端代码（反之亦然）。
- 如果 `__global__` 函数是从主机端代码启动的，`nvstd::function` 不能用作该 `__global__` 函数的参数类型。

非法情形的示例：

```cpp
#include <nvfunctional>

__device__ int device_function() { return 1; }
__host__   int host_function() { return 3; }
auto       lambda_host = [] { return 0; };

__global__ void k() {
     nvstd::function<int()> fn1 = host_function; // ERROR，用 __host__ 函数的地址初始化

     nvstd::function<int()> fn2 = lambda_host;   // ERROR，用其 operator() 为
                                                 //        __host__ 函数的仿函数初始化
}

__global__ void kernel(nvstd::function<int()> f1) {}

void foo(void) {
    auto lambda_device = [=] __device__ { return 1; };

     nvstd::function<int()> fn1 = device_function; // ERROR，用 __device__ 函数的地址初始化
     nvstd::function<int()> fn2 = lambda_device;   // ERROR，用其 operator() 为
                                                   //        __device__ 函数的仿函数初始化

     kernel<<<1, 1>>>(fn2);                        // ERROR，从主机端向设备端传递
                                                   // nvstd::function
}
```

nvfunctional 头文件中 `nvstd::function` 的定义如下：

```cpp
namespace nvstd {

template <typename RetType, typename ...ArgTypes>
class function<RetType(ArgTypes...)> {
public:
    // 构造函数
    __device__ __host__ function() noexcept;
    __device__ __host__ function(nullptr_t) noexcept;
    __device__ __host__ function(const function&);
    __device__ __host__ function(function&&);

     template<typename F>
     __device__ __host__ function(F);

     // 析构函数
     __device__ __host__ ~function();

     // 赋值运算符
     __device__ __host__ function& operator=(const function&);
     __device__ __host__ function& operator=(function&&);
     __device__ __host__ function& operator=(nullptr_t);
     template<typename F>
     __device__ __host__ function& operator=(F&&);

     // swap
     __device__ __host__ void swap(function&) noexcept;

     // 函数容量
     __device__ __host__ explicit operator bool() const noexcept;

     // 函数调用
     __device__ RetType operator()(ArgTypes...) const;
};

// 空指针比较
template <typename R, typename... ArgTypes>
__device__ __host__
bool operator==(const function<R(ArgTypes...)>&, nullptr_t) noexcept;

template <typename R, typename... ArgTypes>
__device__ __host__
bool operator==(nullptr_t, const function<R(ArgTypes...)>&) noexcept;

template <typename R, typename... ArgTypes>
__device__ __host__
bool operator!=(const function<R(ArgTypes...)>&, nullptr_t) noexcept;

template <typename R, typename... ArgTypes>
__device__ __host__
bool operator!=(nullptr_t, const function<R(ArgTypes...)>&) noexcept;

// 特化算法
template <typename R, typename... ArgTypes>
__device__ __host__
void swap(function<R(ArgTypes...)>&, function<R(ArgTypes...)>&);

} // namespace nvstd
```

### 5.3.10 C/C++ 语言限制

#### 5.3.10.1 不支持的特性

- 设备端代码不支持运行时类型识别（RTTI）和异常：
  - `typeid` 关键字
  - `dynamic_cast` 关键字
  - `try`/`catch`/`throw` 关键字
- 设备端代码不支持 `long double`。
- 任何平台都不支持三字符序列（Trigraphs）。Windows 上不支持二字符序列（Digraphs）。
- 用户自定义的 `operator new`、`operator new[]`、`operator delete` 或 `operator delete[]` 不能用于替换编译器提供的对应内建函数，在主机端和设备端都被视为未定义行为。

#### 5.3.10.2 命名空间保留

除非另有说明，向顶层命名空间 `cuda::`、`nv::` 或 `cooperative_groups::`，或其内部的任何嵌套命名空间添加定义，均属于未定义行为。`cuda::` 允许用作子命名空间，如下所示：

示例：

```cpp
namespace cuda {         // 对 "nv" 和 "cooperative_groups" 命名空间同样适用

struct foo;              // ERROR，在 "cuda" 命名空间中声明类

void bar();              // ERROR，在 "cuda" 命名空间中声明函数

namespace utils {} // ERROR，在 "cuda" 命名空间中声明命名空间

} // namespace cuda

namespace utils {
namespace cuda {

// CORRECT，命名空间 "cuda" 可以嵌套在非保留命名空间内使用
void bar();

} // namespace cuda
} // namespace utils

// ERROR，等同于在全局作用域向命名空间 "cuda" 添加符号
using namespace utils;
```

#### 5.3.10.3 指针与内存地址

指针解引用（`*pointer`、`pointer->member`、`pointer[0]`）仅允许在与相关内存所处的同一执行空间中进行。以下情形将导致未定义行为，通常是段错误并终止应用程序。
- 在主机端解引用指向全局内存、共享内存或常量内存的指针。
- 在设备端代码中解引用指向主机端内存的指针。

以下限制适用于函数：
- 不允许在主机端代码中获取 `__device__` 函数的地址。
- 在主机端代码中获取的 `__global__` 函数的地址不能在设备端代码中使用。同样，在设备端代码中获取的 `__global__` 函数的地址不能在主机端代码中使用。

通过 `cudaGetSymbolAddress()` 获取的 `__device__` 或 `__constant__` 变量的地址（如内存空间说明符一节所述）只能在主机端代码中使用。

#### 5.3.10.4 变量

##### 5.3.10.4.1 局部变量

在主机端执行的函数内，对非 extern 变量声明不允许使用 `__device__`、`__tile__`、`__shared__`、`__managed__` 和 `__constant__` 内存空间说明符。

示例：

```cpp
__host__ void host_function() {
     int x;                   // CORRECT，__host__ 变量
     __device__    int y;     // ERROR，主机端函数内声明 __device__ 变量

     __tile__      int z;     // ERROR，主机端函数内声明 __tile__ 变量

     __shared__    int w;     // ERROR，主机端函数内声明 __shared__ 变量

     __managed__ int h;       // ERROR，主机端函数内声明 __managed__ 变量

     __constant__ int i;      // ERROR，主机端函数内声明 __constant__ 变量

     extern __device__ int j; // CORRECT，extern __device__ 变量
}
```

在设备端执行的函数内，对既非 extern 也非 static 的变量声明不允许使用 `__device__`、`__tile__`、`__constant__` 和 `__managed__` 内存空间说明符。

```cpp
__device__ void device_function() {
     int x;                   // CORRECT，__device__ 变量
     __constant__      int y; // ERROR，设备端函数内声明 __constant__ 变量

     __managed__       int z; // ERROR，设备端函数内声明 __managed__ 变量

     extern __device__ int k; // CORRECT，extern __device__ 变量
}
```

另见静态变量一节。

##### 5.3.10.4.2 const 限定的变量

在全局、命名空间或类作用域声明的、没有内存空间标注（`__device__`、`__tile__` 或 `__constant__`）的 const 限定变量被视为是主机端变量。设备端代码不能包含对该变量的引用，也不能获取其地址。

若满足以下条件，该变量可直接在设备端代码中使用：
- 在使用点之前已用常量表达式初始化，
- 类型没有 volatile 限定，且
- 类型为以下之一：
  - 内建整型，或
  - 内建浮点型（主机端编译器为 Microsoft Visual Studio 时除外）。

从 C++14 开始，建议使用 `constexpr` 或 `inline constexpr`（C++17）变量代替 const 限定的变量。constexpr 变量不受相同的类型限制，可直接在设备端代码中使用。

`__managed__` 变量不支持 const 限定类型。

示例：

```cpp
const            int   ConstVar          = 10;
const            float ConstFloatVar     = 5.0f;
inline constexpr float ConstexprFloatVar = 5.0f; // C++17

struct MyStruct {
     static const             int   ConstVar         = 20;
// static const               float ConstFloatVar    = 5.0f; // ERROR，static const
                                                             // 变量不能是 float 类型

     static inline constexpr float ConstexprFloatVar = 5.0f; // CORRECT
};

extern const int ExternVar;

__device__ void foo() {
    int array1[ConstVar];                                // CORRECT
    int array2[MyStruct::ConstVar];                      // CORRECT

     const     float var1 = ConstFloatVar;     // CORRECT，主机端编译器为
                                              // Microsoft Visual Studio 时除外
     constexpr float var2 = ConstexprFloatVar; // CORRECT
// int               var3 = ExternVar;         // ERROR，"ExternVar" 不是用常量表达式初始化的

// int&              var4 = ConstVar;          // ERROR，引用主机端变量

// int*              var5 = &ConstVar;         // ERROR，获取主机端变量的地址

}
```

请参阅 Compiler Explorer 上的示例。

##### 5.3.10.4.3 volatile 限定的变量

> 注：volatile 关键字被保留以保持与 ISO C++ 的兼容性。但其现存的未弃用用法中，几乎没有适用于 GPU 的。

对 volatile 限定对象的读写不是原子的，会被编译为一条或多条 volatile 指令，这些指令不保证：
- 内存操作的顺序，或
- 硬件执行的内存操作数量与 PTX 指令数量一致。

在 tile 代码中，volatile 关键字对内存访问的行为没有影响。

CUDA C++ 的 volatile **不适合**以下用途：

- 线程间同步：请改用 `cuda::atomic_ref`、`cuda::atomic` 或原子函数（Atomic Functions）。
  原子内存操作提供线程间同步保证，且性能优于 volatile 操作。而 CUDA C++ 的 volatile 操作不提供任何线程间同步保证，因此不适合此用途。下面的示例展示了如何使用原子操作在两个线程之间传递消息。

  cuda::atomic_ref

  ```cpp
  #include <cuda/atomic>

  __global__ void kernel(int* flag, int* data) {
       cuda::atomic_ref<int, cuda::thread_scope_device> atomic_ref{*flag};
       if (threadIdx.x == 0) {
           // 消费者：阻塞等待生产者设置 flag，然后读取 data
           while(atomic_ref.load(cuda::memory_order_acquire) == 0)
               ;
           if (*data != 42)
               __trap(); // 读取到错误数据则报错
       }
       else if (threadIdx.x == 1) {
           // 生产者：先写 data 再设置 flag
           *data = 42;
           atomic_ref.store(1, cuda::memory_order_release);
       }
  }
  ```

  cuda::atomic

  ```cpp
  #include <cuda/atomic>

  __global__ void kernel(cuda::atomic<int, cuda::thread_scope_device>* flag, int* data) {

       if (threadIdx.x == 0) {
           // 消费者：阻塞等待生产者设置 flag，然后读取 data
           while(flag->load(cuda::memory_order_acquire) == 0)
               ;
           if (*data != 42)
               __trap(); // 读取到错误数据则报错
       }
       else if (threadIdx.x == 1) {
           // 生产者：先写 data 再设置 flag
           *data = 42;
           flag->store(1, cuda::memory_order_release);
       }
  }
  ```

  原子函数（atomicAdd 和 atomicExch）

  ```cpp
  __global__ void kernel(int* flag, int* data) {
       if (threadIdx.x == 0) {
           // 消费者：阻塞等待生产者设置 flag，然后读取 data
           while(atomicAdd(flag, 0) == 0)
               ;                // 用宽松的读-改-写操作加载
           __threadfence();     // 顺序一致性栅栏
           if (*data != 42)
               __trap();        // 读取到错误数据则报错
       } else if (threadIdx.x == 1) {
           // 生产者：先写 data 再设置 flag
           *data = 42;
           __threadfence();     // 顺序一致性栅栏
           atomicExch(flag, 1); // 用宽松的读-改-写操作存储
       }
  }
  ```

- 内存映射 I/O（MMIO）：请改用内联 PTX 的 PTX MMIO 操作。
  PTX MMIO 操作严格保留实际执行的内存访问次数。而 CUDA C++ 的 volatile 操作不保留内存访问次数，可能以不确定的方式执行多于或少于请求的访问次数，因此不适合 MMIO。下面的示例展示了如何使用 PTX MMIO 操作读写寄存器。

  ```cpp
  __global__ void kernel(int* mmio_reg0, int* mmio_reg1) {
      // 写 MMIO 寄存器：
      int value = 13;
      asm volatile("st.relaxed.mmio.sys.u32 [%0], %1;"
          :
          : "l"(mmio_reg0), "r"(value) : "memory");

      // 读 MMIO 寄存器：
      asm volatile("ld.relaxed.mmio.sys.u32 %0, [%1];"
          : "=r"(value)
          : "l"(mmio_reg1) : "memory");

      if (value != 42)
          __trap(); // 读取到错误数据则报错
  }
  ```

##### 5.3.10.4.4 static 变量

设备端函数中允许使用静态局部变量。
对于包围函数的每个执行空间，使用不同的静态变量。例如：
- `__host__ __device__` 函数在主机端执行时有一份静态变量拷贝，在设备端执行时有另一份。
- `__tile__ __device__` 函数在 tile 执行时有一份，在 SIMT 执行时有另一份。

如果函数带有 `__host__` 执行空间说明符，则只有在定义了 `__CUDA_ARCH__` 时，才允许使用带显式内存空间说明符的静态变量，如 `static __device__`/`__tile__`/`__constant__`/`__shared__`/`__managed__`。

函数作用域静态变量的合法与非法用法示例如下：

```cpp
struct TrivialStruct {
    int x;
};

struct NonTrivialStruct {
    __device__ NonTrivialStruct(int x) {}
};

__device__ void device_function(int x) {
     static int v1;             // CORRECT，隐式 __device__ 内存空间说明符

     static int v2 = 11;        // CORRECT，隐式 __device__ 内存空间说明符

// static int v3 = x;           // ERROR，不允许动态初始化

      static __managed__ int v4; // CORRECT，显式
      static __device__   int v5; // CORRECT，显式
      static __constant__ int v6; // CORRECT，显式
      static __shared__   int v7; // CORRECT，显式

      static TrivialStruct          s1;        // CORRECT，隐式 __device__ 内存空间说明符
     static TrivialStruct   s2{22}; // CORRECT，隐式 __device__ 内存空间说明符

// static TrivialStruct    s3{x};   // ERROR，不允许动态初始化

// static NonTrivialStruct s4{3};   // ERROR，不允许动态初始化

}
```

请参阅 Compiler Explorer 上的示例。

```cpp
__host__ __device__ void host_device_function() {
     static            int v1; // CORRECT，隐式 __device__ 内存空间说明符

// static __device__ int v2; // ERROR，host-device 函数内的 __device__ 专用变量

#ifdef __CUDA_ARCH__
     static __device__ int v3; // CORRECT，该声明仅在设备端编译时可见

#else
     static int v4;            // CORRECT，该声明仅在主机端编译时可见

#endif
}
```

请参阅 Compiler Explorer 上的示例。

```cpp
#include <cassert>

__host__ __device__ int host_device_function() {
    static int v = 0;
    v++;
    return v;
}

__global__ void kernel() {
    int ret = host_device_function(); // v = 1
    assert(ret == 4);                 // FAIL
}

int main() {
    host_device_function();           // v = 1
    host_device_function();           // v = 2
    int ret = host_device_function(); // v = 3
    assert(ret == 3);                 // OK
    kernel<<<1, 1>>>();
    cudaDeviceSynchronize();
}
```

请参阅 Compiler Explorer 上的示例。

##### 5.3.10.4.5 extern 变量

在整程序编译模式下，不能用 `extern` 关键字以外部链接方式定义 `__device__`、`__tile__`、`__shared__`、`__managed__` 和 `__constant__` 变量。该限制在分开编译模式下同样适用于 `__tile__` 变量。唯一的例外是动态分配的 `__shared__` 变量，如共享内存动态分配一节所述。

```cpp
__device__        int x; // OK
extern __device__ int y; // ERROR，整程序编译模式下出错
extern __shared__ int z; // OK
```

#### 5.3.10.5 函数

##### 5.3.10.5.1 递归

`__global__`、`__tile_global__` 和 `__tile__` 函数不支持递归，而 `__device__` 和 `__host__ __device__` 函数没有此限制。

##### 5.3.10.5.2 外部链接

跨多个翻译单元的设备端变量或函数若带有外部链接，需要使用分开编译模式。
在分开编译模式下，如果某个 `__device__` 或 `__global__` 函数定义必须存在于某个特定翻译单元中，则该函数的参数和返回类型在该翻译单元中必须是完整类型。这个概念也称为单一定义规则使用（One Definition Rule-use，ODR-use）。

示例：

```cpp
//first.cu:
struct S;                   // 前向声明
__device__ void foo(S);     // ERROR，类型 'S' 是不完整类型
__device__ auto* ptr = foo; // ODR-use，取了地址

int main() {}

//second.cu:
struct S {};                       // struct 定义
__device__ void foo(S) {}          // 函数定义

# 编译器调用
$ nvcc -std=c++14 -rdc=true first.cu second.cu -o prog
nvlink error    : Prototype doesn't match for '_Z3foo1S' in '/tmp/tmpxft_00005c8c_00000000-18_second.o',
                  first defined in '/tmp/tmpxft_00005c8c_00000000-18_second.o'
nvlink fatal    : merge_elf failed
```

##### 5.3.10.5.3 形参

`__device__`、`__tile__`、`__shared__`、`__managed__` 和 `__constant__` 内存空间说明符不允许出现在形参上。

```cpp
void device_function1(__device__ int x) { } // ERROR，__device__ 参数
void device_function2(__shared__ int x) { } // ERROR，__shared__ 参数
```

##### 5.3.10.5.4 `__global__` 函数参数

`__global__` 或 `__tile_global__` 函数有以下限制：
- 不能有可变数量的参数，即 C 省略号语法 `...` 和 `va_list` 类型。C++11 可变参数模板允许使用，但受 `__global__` 可变参数模板一节所述限制的约束。
- 函数参数通过常量内存传递给设备端，其总大小限制为 32,764 字节。
- 函数参数不能是 `std::initializer_list` 类型。
- 多态类参数（带虚函数）被视为未定义行为。
- lambda 表达式和闭包类型允许使用，但受 Lambda 表达式与 `__global__` 函数参数一节所述限制的约束。
- 对于 `__tile_global__` 函数，函数参数不能是按值传递的类、结构体或联合体。

##### 5.3.10.5.5 `__global__` 函数参数传递

从设备端代码启动 `__global__` 函数时，每个参数都必须是可平凡复制（trivially copyable）且可平凡析构（trivially destructible）的。

从主机端代码启动 `__global__` 函数时，每个参数类型可以是不可平凡复制或不可平凡析构的。但是，这些类型的处理流程不遵循标准 C++ 模型，如下所述。用户代码必须确保该流程不影响程序正确性。该流程在两个方面偏离了标准 C++：

1. 原始内存复制而非调用复制构造函数
   CUDA 运行时通过复制原始内存内容（最终使用 `memcpy`）将核函数参数传递给 `__global__` 函数。如果参数是不可平凡复制的且提供了用户自定义的复制构造函数，则在从主机端向设备端的复制中会跳过该构造函数的调用及其副作用。

   示例：

   ```cpp
   #include <cassert>

   struct MyStruct {
       int value = 1;
       int* ptr;

        MyStruct() = default;

        __host__ __device__ MyStruct(const MyStruct&) { ptr = &value; }
   };

   __global__ void device_function(MyStruct my_struct) {
       // 该断言失败，因为 "my_struct" 是通过复制原始内存内容得到的，
       // 复制构造函数被跳过了。
       assert(my_struct.ptr == &my_struct.value); // FAIL
    }

    void host_function(MyStruct my_struct) {
        assert(my_struct.ptr == &my_struct.value); // CORRECT
    }

    int main() {
         MyStruct my_struct;
         host_function(my_struct);
         device_function<<<1, 1>>>(my_struct); // 复制构造函数仅在主机端调用

         cudaDeviceSynchronize();
    }
   ```

   请参阅 Compiler Explorer 上的示例。

2. 析构函数可能在 `__global__` 函数执行完之前被调用
   核函数启动与主机端执行是异步的。因此，如果 `__global__` 函数的参数有非平凡析构函数，该析构函数可能在主机端代码中、`__global__` 函数执行完之前就被执行。这可能会破坏析构函数有副作用的程序。

   示例：

   ```cpp
   #include <cassert>

   __managed__ int var = 0;

   struct MyStruct {
       __host__ __device__ ~MyStruct() { var = 3; }
   };

   __global__ void device_function(MyStruct my_struct) {
       assert(var == 0); // FAIL，MyStruct::~MyStruct() 将值设为 3
   }

   int main() {
       MyStruct my_struct;
       // GPU 核函数执行与主机端执行异步。
       // 因此，MyStruct::~MyStruct() 可能在核函数执行完之前被执行。
       device_function<<<1, 1>>>(my_struct);
       cudaDeviceSynchronize();
   }
   ```

   请参阅 Compiler Explorer 上的示例。

#### 5.3.10.6 类

##### 5.3.10.6.1 类类型变量

带 `__device__`、`__tile__`、`__constant__`、`__managed__` 或 `__shared__` 内存空间的变量定义，不能使用带有非空构造函数或非空析构函数的类类型。

如果在翻译单元的某个点满足以下任一条件，类类型的构造函数被视为是空的：该构造函数是平凡的，或者满足以下所有条件：
- 该构造函数已被定义。
- 该构造函数无参数、初始化列表为空、函数体为空复合语句。
- 其类没有虚函数、虚基类或非静态数据成员初始化器。
- 其所有基类的默认构造函数都可以被视为空。
- 对于该类所有类类型（或其数组）的非静态数据成员，其默认构造函数都可以被视为空。

如果在翻译单元的某个点满足以下任一条件，类的析构函数被视为是空的：该析构函数是平凡的，或者满足以下所有条件：
- 该析构函数已被定义。
- 该析构函数体为空复合语句。
- 其类没有虚函数或虚基类。
- 其所有基类的析构函数都可以被视为空。
- 对于该类所有类类型（或其数组）的非静态数据成员，其析构函数都可以被视为空。

##### 5.3.10.6.2 数据成员

`__device__`、`__tile__`、`__shared__`、`__managed__` 和 `__constant__` 内存空间说明符不允许出现在类、结构体和联合体的数据成员上。
只支持编译期求值的静态数据成员，例如 const 限定变量和 constexpr 变量。

```cpp
struct MyStruct {
   static inline constexpr int value1 = 10; // C++17
   static constexpr        int value2 = 10; // C++11
   static const            int value3 = 10;
// static                 int value4; // ERROR
};
```

##### 5.3.10.6.3 函数成员

`__global__` 和 `__tile_global__` 函数不能是结构体、类或联合体的成员。
`__global__` 或 `__tile_global__` 函数允许出现在友元声明中，但不能被定义。

示例：

```cpp
struct MyStruct {
    friend __global__ void f();                // CORRECT，仅友元声明

//     friend __global__ void g() {} // ERROR，友元定义
};
```

请参阅 Compiler Explorer 上的示例。

##### 5.3.10.6.4 隐式声明和非虚的显式默认函数

隐式声明的特殊成员函数是指用户未声明时编译器为类声明的函数；显式默认函数是指用户声明但用 `= default` 标记的函数。隐式声明或显式默认的特殊成员函数包括默认构造函数、复制构造函数、移动构造函数、复制赋值运算符、移动赋值运算符和析构函数。

设 F 表示一个非虚函数，它在其首次声明时是隐式声明的或显式默认的。F 的执行空间说明符是所有调用它的函数的执行空间说明符的并集。注意，在此分析中，`__global__` 调用者将被视为 `__device__` 调用者。例如：

```cpp
class Base {
    int x;
public:
    __host__ __device__ Base() : x(10) {}
};

class Derived : public Base {
    int y;
};

class Other: public Base {
    int z;
};

__device__ void foo() {
    Derived D1;
    Other D2;
}

__host__ void bar() {
    Other D3;
}
```

在本例中，隐式声明的构造函数 `Derived::Derived()` 将被视为 `__device__` 函数，因为它只被 `__device__` 函数 `foo()` 调用。隐式声明的构造函数 `Other::Other()` 将被视为 `__host__ __device__` 函数，因为它既被 `__device__` 函数 `foo()` 调用，也被 `__host__` 函数 `bar()` 调用。

此外，如果 F 是隐式声明的虚函数（例如虚析构函数），则对于被 F 覆盖的每个虚函数 D，如果 D 不是隐式声明的，D 的执行空间也会加入 F 的执行空间集合中。

例如：

```cpp
struct Base1 {
    virtual __host__ __device__ ~Base1() {}
};

struct Derived1 : Base1 {}; // 隐式声明的虚析构函数
                            // ~Derived1() 具有 __host__ __device__ 执行空间说明符

struct Base2 {
    virtual __device__ ~Base2() = default;
};

struct Derived2 : Base2 {}; // 隐式声明的虚析构函数
                            // ~Derived2() 具有 __device__ 执行空间说明符
```

##### 5.3.10.6.5 多态类

多态类，即带虚函数的类、派生自其他多态类的类，或带有多态数据成员的类，受以下限制：
- 从设备端向主机端或从主机端向设备端复制多态对象（包括 `__global__` 函数参数）是未定义行为。
- 被覆盖的虚函数的执行空间必须与基类中该函数的执行空间匹配。

示例：

```cpp
struct MyClass {
    virtual __host__ __device__ void f() {}
};

__global__ void kernel(MyClass my_class) {
    my_class.f(); // 未定义行为
}

int main() {
    MyClass my_class;
    kernel<<<1, 1>>>(my_class);
    cudaDeviceSynchronize();
}
```

请参阅 Compiler Explorer 上的示例。

```cpp
struct BaseClass {
    virtual __host__ __device__ void f() {}
};

struct DerivedClass : BaseClass {
    __device__ void f() override {} // ERROR
};
```

请参阅 Compiler Explorer 上的示例。

##### 5.3.10.6.6 Windows 特定的类布局

CUDA 编译器遵循 IA64 ABI 的类布局，而 Microsoft Visual Studio 则不遵循。这会导致下述特殊对象无法在主机端和设备端代码之间进行按位复制。
设 T 表示成员指针类型，或满足以下任一条件的类类型：
- T 是多态类；
- T 有多重继承，且有多于一个直接或间接的空基类；
- 所有直接和间接基类 B 都是空类，且 T 的第一个字段 F 的类型在其定义中使用了 B，使得 B 在 F 的定义中布局在偏移 0 处。

类型为 T 的类、以 T 为基类的类，或带有 T 类型数据成员的类，在使用 Microsoft Visual Studio 编译时，主机端和设备端的类布局和大小可能不同。
从设备端向主机端或从主机端向设备端复制这类对象（包括 `__global__` 函数参数）是未定义行为。

#### 5.3.10.7 模板

如果满足以下任一条件，某类型不能用作 `__global__` 函数或 `__device__`/`__constant__` 变量（C++14）的模板参数：
- 该类型定义在 `__host__` 或 `__host__ __device__` 函数作用域内。
- 该类型是未命名的，如匿名结构体或 lambda 表达式，除非该类型是 `__device__` 或 `__global__` 函数局部的。
- 该类型是访问权限为 private 或 protected 的类成员，除非该类是 `__device__` 或 `__global__` 函数局部的。
- 该类型由上述任一类型复合而成。

示例：

```cpp
template <typename T>
__global__ void kernel() {}

template <typename T>
__device__ int device_var; // C++14

struct {
    int v;
} unnamed_struct;

void host_function() {
     struct LocalStruct {};
// kernel<LocalStruct><<<1, 1>>>(); // ERROR，LocalStruct 定义在主机端函数内

     int data = 4;
// cudaMemcpyToSymbol(device_var<LocalStruct>, &data, sizeof(data)); // ERROR，同上

       auto lambda = [](){};
//     kernel<decltype(lambda)><<<1, 1>>>();         // ERROR，未命名类型
//     kernel<decltype(unnamed_struct)><<<1, 1>>>(); // ERROR，未命名类型
}

class MyClass {
private:
    struct PrivateStruct {};
public:
    static void launch() {
//           kernel<PrivateStruct><<<1, 1>>>(); // ERROR，私有类型
       }
};
```

请参阅 Compiler Explorer 上的示例。

#### 5.3.10.8 tile 代码中的限制

带有 `__tile__` 或 `__tile_global__` 注解的函数有以下附加限制：
- tile 代码中不支持以下语言构造：
  - do、while 或 for 循环内，或 switch 语句内的 return 语句。
  - switch 语句内的 continue 语句（当该 continue 未被 switch 下的循环包围时）。
  - switch 主体中嵌套 if 或循环块内的 case/default 标签。
  - 虚函数调用。
  - goto 语句。
  - 生成函数指针、函数引用、成员变量指针或成员函数指针的表达式。
  - 函数指针和成员函数指针调用。
  - 成员变量指针访问。
  - 128 位整数或浮点类型。
  - 包含位域的类型。
  - 大小超过 16 MB 的类型。
  - 带虚基类或虚函数的类型。
  - 用非 placement 的 operator new 或 delete 进行的动态内存分配或释放。
- `__tile__` 或 `__tile_global__` 函数必须在声明它的同一翻译单元中具有函数体。
- 不支持用 `__tile__` 注解虚函数。
- `__tile_global__` 或 `__tile__` 函数不允许使用 C 省略号语法 `...` 的可变数量参数。
- `__tile_global__` 或 `__tile__` 函数不允许直接或间接递归。
- 对于 `__tile_global__` 函数，函数参数不能是按值传递的类、结构体或联合体。
- tile 代码不能执行设备端核函数启动，tile 核函数也不能从设备端核函数调用中启动。
- tile 代码中不支持直接访问 `__half`、`__nv_bfloat16` 及相关扩展浮点类型的 `__x` 成员变量。

### 5.3.11 C++11 限制

#### 5.3.11.1 内联命名空间

当包围命名空间中定义了同名同类型签名的另一个实体时，不允许在内联命名空间内定义以下实体：
- `__global__` 或 `__tile_global__` 函数。
- `__device__`、`__tile__`、`__constant__`、`__managed__`、`__shared__` 变量。
- 表面（surface）或纹理（texture）类型的变量，如 `cudaSurfaceObject_t` 或 `cudaTextureObject_t`。

示例：

```cpp
__device__ int my_var; // 全局作用域

inline namespace NS {
__device__ int my_var; // 命名空间作用域

} // namespace NS
```

#### 5.3.11.2 内联未命名命名空间

以下实体不能在内联未命名命名空间的命名空间作用域内声明：
- `__global__` 或 `__tile_global__` 函数。
- `__device__`、`__tile__`、`__constant__`、`__managed__`、`__shared__` 变量。
- 表面或纹理类型的变量，如 `cudaSurfaceObject_t` 或 `cudaTextureObject_t`。

#### 5.3.11.3 constexpr 函数

`__global__` 函数不能声明为 constexpr。默认情况下，constexpr 函数不能从执行空间不兼容的函数中调用，与普通函数相同。在本节列出的示例代码中，UB 表示“未定义行为”。
- 在主机端编译阶段（`__CUDA_ARCH__` 宏未定义时），从主机端函数调用没有显式或隐式 `__host__` 注解的 constexpr 函数是未定义行为。示例：

  ```cpp
  constexpr __device__                    int   device_func() { return 0; }
  constexpr __tile__                      int   tile_func()   { return 0; }

  constexpr __device__ __host__          int host_device_func() { return 0; }

  int main() {
       constexpr int x1 = device_func(); // UB：从主机端代码调用仅 __device__ 的 constexpr 函数

       constexpr int x2 = tile_func();    // UB：从主机端代码调用仅 __tile__ 的 constexpr 函数

       constexpr int x3 = host_device_func(); // OK
  }
  ```

- 在设备端编译阶段（`__CUDA_ARCH__` 宏已定义时），从 `__device__` 或 `__global__` 函数调用没有显式或隐式 `__device__` 注解的 constexpr 函数是未定义行为。示例：

  ```cpp
  constexpr     int host_func() { return 0; }

  __device__ void dmain()
  {
       int x = host_func(); // UB：从设备端代码调用仅主机端的 constexpr 函数
  }
  ```

- 在设备端编译阶段（`__CUDA_ARCH__` 宏已定义时），从 `__tile__` 或 `__tile_global__` 函数调用没有显式或隐式 `__tile__` 注解的 constexpr 函数是未定义行为。示例：

  ```cpp
  constexpr     int host_func() { return 0; }

  __tile__ void dmain()
  {
       int x = host_func(); // UB：从 tile 代码调用仅主机端的 constexpr 函数
  }
  ```

注意，即使相应的模板函数带有 `constexpr` 关键字标记，函数模板特化也可能不是 constexpr 函数。

**宽松 constexpr 函数支持**

实验性 nvcc 标志 `--expt-relaxed-constexpr` 可用于按如下方式放宽此约束。nvcc 还会定义宏 `__CUDACC_RELAXED_CONSTEXPR__`。在本节列出的示例代码中，UB 表示“未定义行为”。

指定 `--expt-relaxed-constexpr` 标志后，编译器将按如下方式支持跨执行空间调用：
1. 如果跨执行空间调用 constexpr 函数发生在需要常量求值的上下文中，例如在 constexpr 变量的初始化器中，则该调用被支持。示例：

   ```cpp
   constexpr __host__ int host_func(int x) { return x + 1; };

   __global__ void doit() {
         constexpr int val = host_func(1); // OK：调用发生在需要常量求值的上下文中
   }

   __tile_global__ void tile_doit() {
         constexpr int val = host_func(1); // OK：调用发生在需要常量求值的上下文中
   }

   constexpr __device__ int device_func(int x) { return x + 1; }

   constexpr __tile__ int tile_func(int x) { return x + 2; }

   int main() {
   constexpr int val = device_func(1) + tile_func(1); // OK：调用发生在需要常量求值的上下文中
   }
   ```

2. 其他情况：
   a. 在语言规则要求常量折叠的上下文之外，不支持从 tile 代码对没有显式或隐式 `__tile__` 注解的 constexpr 函数进行跨执行空间调用。示例：

      ```cpp
      constexpr __host__ int host_func(int x) { return x + 1; }

      __tile__ int doit(int in) {
           in = host_func(in); // UB：调用发生在不需要常量求值的上下文之外

           constexpr int other = host_func(10); // 用 -expt-relaxed-constexpr 时 OK：
                                               // 调用要求在编译期求值
      }
      ```

   b. 在 SIMT 设备端代码生成期间，会为仅主机端的 constexpr 函数 `host_func` 的函数体生成设备端代码，除非 `host_func` 未被使用，或仅在常量求值上下文中被调用。示例：

      ```cpp
      // 注：因为 host_func 在非常量上下文中被设备端代码调用，
      // 所以 "host_func" 会出现在生成的设备端代码中
      constexpr __host__ int host_func(int x) { return x + 1; }

      __device__ int doit(int in) {
           in = host_func(in); // OK，即使参数不是常量表达式

           return in;
      }
      ```

   c. 适用于 `__device__` 函数的所有代码限制也适用于从 SIMT 设备端代码调用的仅主机端 constexpr 函数 H。但编译器可能不会对 H 的这些限制发出任何构建期诊断。原因是诊断通常在解析期间生成，而 H 可能在翻译单元中稍后遇到从设备端代码到 H 的调用之前就已经解析完了。

      例如，H 的函数体内不支持以下代码模式（如同任何 `__device__` 函数），但可能不会产生编译器诊断：
      - 对主机端变量或仅主机端的非 constexpr 函数进行 ODR-use。示例：

        ```cpp
        int host_var1, host_var2;

        constexpr __host__ int* host_func(bool b) { return b ? &host_var1 : &host_var2; };

        __device__ int doit(bool flag) {
             int *ptr;
             ptr = host_func(flag); // UB：host_func() 试图引用主机端变量
                                    // 'host_var1' 和 'host_var2'。
                                    // 代码可以编译，但执行不正确。

             return *ptr;
        }
        ```

      - 使用异常（throw/catch）和 RTTI（typeid、dynamic_cast）。示例：

        ```cpp
        struct Base { };
        struct Derived : public Base { };

        // 注："host_func" 会出现在生成的设备端代码中
        constexpr int host_func(bool b, Base *ptr) {
           if (b) {
             return 1;
           } else if (typeid(ptr) == typeid(Derived)) { // UB：在 GPU 上执行的代码中使用 typeid
             return 2;
           } else {
             throw int{4}; // UB：在 GPU 上执行的代码中使用 throw
           }
        }

        __device__ void doit(bool flag) {
             int val;
             Derived d;
             val = host_func(flag, &d); // UB：host_func() 试图使用 typeid 和 throw()，
                                        // 这些在 GPU 上执行的代码中不允许
        }
        ```

   d. 在主机端代码生成期间，非主机端的 constexpr 函数 F 的函数体被保留在发送给主机端编译器的代码中。如果 F 的函数体试图对命名空间作用域的设备端或 `__tile__` 变量，或非主机端的非 constexpr 函数进行 ODR-use，则从主机端代码调用 F 不被支持（代码可能不带编译器诊断地构建成功，但运行时行为不正确）。示例：

      ```cpp
      __device__ int device_var1, device_var2;

      constexpr __device__ int* device_func(bool b) { return b ? &device_var1 : &device_var2; };

      __tile__ int tile_var1, tile_var2;

      constexpr __tile__ int* tile_func(bool b) { return b ? &tile_var1 : &tile_var2; };

      int doit1(bool flag) {
           int *ptr;
           ptr = device_func(flag); // UB：device_func() 试图引用设备端变量
                                    // 'device_var1' 和 'device_var2'。
                                    // 代码可以编译，但执行不正确。
           return *ptr;
      }

      int doit2(bool flag) {
           int *ptr;
           ptr = tile_func(flag); // UB：tile_func() 试图引用 __tile__ 变量
                                  // 'tile_var1' 和 'tile_var2'。
                                  // 代码可以编译，但执行不正确。
           return *ptr;
      }
      ```

> 警告：由于上述限制，且编译器对错误用法缺乏诊断，建议避免从设备端代码调用标准 C++ 头文件 `std::` 中的函数。此类函数的实现因主机端平台而异。强烈建议改为调用 CUDA C++ 标准库 libcu++ 中 `cuda::std::` 命名空间下的等效功能。

#### 5.3.11.4 constexpr 变量

默认情况下，constexpr 变量不能用于执行空间不兼容的函数，与普通变量相同。
以下情形下，constexpr 变量可以直接用于设备端代码：
- C++ 标量类型，不包括指针和成员指针类型：
  - nullptr_t。
  - bool。
  - 整型：char、signed char、unsigned、long long 等。
  - 浮点型：float、double。
  - 枚举：enum 和 enum class。
- 类类型：带 constexpr 构造函数的 class、struct 和 union。
- 上述类型的原始数组，例如 `int[]`，仅当它们在 constexpr `__device__` 或 `__host__ __device__` 函数内部使用时。

不允许 `constexpr __managed__` 和 `constexpr __shared__` 变量。

示例：

```cpp
constexpr int ConstexprVar = 4; // 标量类型

struct MyStruct {
    static constexpr int ConstexprVar = 100;
};

constexpr MyStruct my_struct = MyStruct{}; // 类类型

constexpr int array[] = {1, 2, 3};

__device__ constexpr int get_value(int idx) {
    return array[idx];                      // CORRECT
}

__device__ void foo(int idx) {
     int        v1 = ConstexprVar;           // CORRECT
     int        v2 = MyStruct::ConstexprVar; // CORRECT
// const int &v3 = ConstexprVar1;           // ERROR，引用主机端 constexpr 变量

// const int *v4 = &ConstexprVar1;          // ERROR，获取主机端 constexpr 变量的地址

     int        v5 = get_value(2);           // CORRECT，'get_value(2)' 是常量表达式

// int          v6 = get_value(idx);        // ERROR，'get_value(idx)' 不是常量表达式

// int          v7 = array[2];              // ERROR，'array' 不是标量类型

     MyStruct   v8 = my_struct;              // CORRECT
}
```

请参阅 Compiler Explorer 上的示例。

#### 5.3.11.5 `__global__` 可变参数模板

可变 `__global__` 或 `__tile_global__` 函数模板有以下限制：
- 只允许单个参数包。
- 参数包必须是模板参数列表中的最后一个参数。

示例：

```cpp
template <typename... Pack>
__global__ void kernel1(); // CORRECT

// template <typename... Pack, template T>
// __global__ void kernel2(); // ERROR，参数包不是最后一个参数

template <typename... TArgs>
struct MyStruct {};

// template <typename... Pack1, typename... Pack2>
// __global__ void kernel3(MyStruct<Pack1...>, MyStruct<Pack2...>); // ERROR，多于一个参数包
```

请参阅 Compiler Explorer 上的示例。

#### 5.3.11.6 默认函数 = default

CUDA 编译器按“隐式声明和显式默认函数”一节所述推断显式默认成员函数的执行空间。
显式默认函数上的执行空间说明符会被编译器忽略，除非该函数是异地定义（out-of-line）或虚函数。

示例：

```cpp
struct MyStruct1 {
    MyStruct1() = default;
};

void host_function() {
    MyStruct1 my_struct; // __host__ __device__ 构造函数
}

__device__ void device_function() {
    MyStruct1 my_struct; // __host__ __device__ 构造函数
}

struct MyStruct2 {
     __device__ MyStruct2() = default; // WARNING：__device__ 注解被忽略
};

struct MyStruct3 {
    __host__ MyStruct3();
};
MyStruct3::MyStruct3() = default; // 异地定义，不忽略

__device__ void device_function2() {
// MyStruct3 my_struct; // ERROR，__host__ 构造函数
}

struct MyStruct4 {
     // MyStruct4::~MyStruct4 具有主机端执行空间，因为是虚函数所以不忽略
     virtual __host__ ~MyStruct4() = default;
};

__device__ void device_function3() {
    MyStruct4 my_struct4;
    // 对 'my_struct4' 的隐式析构函数调用：
    //    ERROR：从 __device__ 函数 'device_function3' 调用
    //    __host__ 函数 'MyStruct4::~MyStruct4'
}
```

请参阅 Compiler Explorer 上的示例。

#### 5.3.11.7 [cuda::]std::initializer_list

默认情况下，CUDA 编译器隐式认为 `[cuda::]std::initializer_list` 的成员函数具有 `__host__ __device__ __tile__` 执行空间说明符，因此它们可以直接从设备端代码调用。nvcc 标志 `--no-host-device-initializer-list` 禁用此行为；此时 `[cuda::]std::initializer_list` 的成员函数将被视为 `__host__` 函数，不能直接从设备端代码调用。

`__global__` 或 `__tile_global__` 函数不能有 `[cuda::]std::initializer_list` 类型的参数。

示例：

```cpp
#include <initializer_list>

__device__ void foo(std::initializer_list<int> in) {}

__device__ void bar() {
     foo({4,5,6}); // (a) 仅含常量表达式的初始化列表
     int i = 4;
     foo({i,5,6}); // (b) 含至少一个非常量元素的初始化列表。
                   // 该形式可能比 (a) 性能更好。
}
```

请参阅 Compiler Explorer 上的示例。

#### 5.3.11.8 [cuda::]std::move、[cuda::]std::forward

默认情况下，CUDA 编译器隐式认为 `std::move` 和 `std::forward` 函数模板具有 `__host__ __device__ __tile__` 执行空间说明符，因此它们可以直接从设备端代码调用。nvcc 标志 `--no-host-device-move-forward` 禁用此行为；此时 `std::move` 和 `std::forward` 将被视为 `__host__` 函数，不能直接从设备端代码调用。

> 提示：相反，`cuda::std::move` 和 `cuda::std::forward` 始终具有 `__host__ __device__` 执行空间。

### 5.3.12 C++14 限制

#### 5.3.12.1 推导返回类型的函数

`__global__` 或 `__tile_global__` 函数不能有推导的返回类型 `auto`。
主机端代码中不允许对带推导返回类型的 `__device__` 函数的返回类型进行内省（introspection）。

> 注：CUDA 前端编译器在调用主机端编译器之前，会将该函数声明改为 void 返回类型。这可能破坏主机端代码中对 `__device__` 函数推导返回类型的内省。因此，CUDA 编译器会对在设备端函数体之外引用此类推导返回类型的情况发出编译期错误。

示例：

```cpp
 __device__ auto device_function(int x) { // 推导返回类型
     return x;                            // decltype(auto) 行为相同
 }

    __global__ void kernel() {
        int x = sizeof(device_function(2));                    // CORRECT，设备端代码作用域
    }

    // const int size = sizeof(device_function(2)); // ERROR，在主机端推导返回类型

 void host_function() {
 // using T = decltype(device_function(2));                   // ERROR，在主机端推导返回类型
 }

void host_fn1() {
  // ERROR，在设备端函数体之外被引用
  int (*p1)(int) = fn1;

     struct S_local_t {
       // ERROR，在设备端函数体之外被引用
       decltype(fn2(10)) m1;

          S_local_t() : m1(10) { }
     };
}

// ERROR，在设备端函数体之外被引用
template <typename T = decltype(fn2)>
void host_fn2() { }

template<typename T> struct MyStruct { };

// ERROR，在设备端函数体之外被引用
struct S1_derived_t : MyStruct<decltype(fn1)> { };
```

#### 5.3.12.2 变量模板

使用 Microsoft 编译器时，`__device__`、`__tile__` 或 `__constant__` 变量模板不能是 const 限定的。

示例：

```cpp
// ERROR 在 Windows 上（不可移植），const 限定
template <typename T>
__device__ const T var = 0;

 // CORRECT，ptr1 不是 const 限定的
template <typename T>
__device__ const T* ptr1 = nullptr;

// ERROR 在 Windows 上（不可移植），ptr2 是 const 限定的
template <typename T>
__device__ const T* const ptr2 = nullptr;
```

请参阅 Compiler Explorer 上的示例。

### 5.3.13 C++17 限制

#### 5.3.13.1 内联变量

在单个翻译单元中，使用内联变量与使用普通变量相比没有额外功能，也没有任何实际优势。
nvcc 仅在分开编译模式下或对于内部链接的变量，才允许带 `__device__`、`__tile__`、`__constant__` 或 `__managed__` 内存空间的内联变量。

> 注：使用 gcc/g++ 主机端编译器时，带 `__managed__` 内存空间说明符声明的内联变量可能对调试器不可见。

示例：

```cpp
inline         __device__ int device_var1; // CORRECT，分开编译模式（-rdc=true 或 -dc）下编译
                                           // 整程序编译模式下 ERROR

static inline __device__ int device_var2;               // CORRECT，内部链接

namespace {
inline __device__ int device_var3;                  // CORRECT，内部链接

inline __shared__ int shared_var;                   // CORRECT，内部链接

static inline __device__ int device_var4;           // CORRECT，内部链接

inline __device__ int device_var5;                  // CORRECT，内部链接

} // namespace
```

请参阅 Compiler Explorer 上的示例。

#### 5.3.13.2 结构化绑定

结构化绑定不能用内存空间说明符声明，如 `__device__`、`__tile__`、`__shared__`、`__constant__` 或 `__managed__`。

示例：

```cpp
struct S {
    int x, y;
};
// __device__ auto [a, b] = S{4, 5}; // ERROR
```

### 5.3.14 C++20 限制

#### 5.3.14.1 三路比较运算符

三路比较运算符（`<=>`）在 `__device__` 和 `__global__` 函数中受支持，但某些用法隐式依赖于 C++ 标准库的功能，该功能由主机端实现提供。使用这些运算符可能需要指定标志 `--expt-relaxed-constexpr` 来消除警告，并且该功能要求主机端实现满足设备端代码的要求。

示例：

```cpp
#include <compare> // std::strong_ordering 实现

struct S {
    int x, y;

       auto operator<=>(const S&) const = default; // (a)

       __host__ __device__ bool operator<=>(int rhs) const { return false; } // (b)
};

__host__ __device__ bool host_device_function(S a, S b) {
    if (a <=> 1) // CORRECT，调用用户定义的 host-device 重载 (b)
        return true;
    return a < b; // CORRECT，调用隐式声明的函数 (a)
                  // 注：它需要 <compare> 头文件中提供的、与设备端兼容的
                  // std::strong_ordering 实现，以及标志 --expt-relaxed-constexpr
}
```

请参阅 Compiler Explorer 上的示例。

#### 5.3.14.2 consteval 函数

consteval 函数可以从主机端和设备端代码调用，与其执行空间无关。

示例：

```cpp
consteval int host_consteval() {
    return 10;
}

__device__ consteval int device_consteval() {
    return 10;
}

__device__ int device_function() {
    return host_consteval();   // CORRECT，即使从设备端代码调用
}

__host__ __device__ int host_device_function() {
    return device_function(); // CORRECT，即使从 host-device 代码调用
}
```

### 5.3.15 C++23 限制

除了上面 C++23 语言特性表中注明的“不支持”或“不适用”特性外，没有已知的 C++23 特定限制。该表中标记为 × 或 N/A 的条目（包括缺陷报告（Defect Report）决议）反映的是缺失或不适用的特性，而不是附加的行为限制。

设备端代码限制：
- 定宽浮点类型 `float16_t`、`float32_t`、`float64_t`、`float128_t` 和 `bfloat16_t` 在设备端代码中不受支持。

#### 5.3.15.1 等价运算符（P2468R2）

尽管 NVCC 没有完整实现缺陷报告决议《你一直在寻找的等价运算符》（P2468R2），它近似了该行为，而这种近似尚未在用户代码中导致已知失败。
