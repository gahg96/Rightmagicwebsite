# 5.5 浮点运算

## 5.5.1 浮点简介

自 1985 年 IEEE-754 二进制浮点算术标准被采用以来，包括 NVIDIA CUDA 架构在内，几乎所有主流计算系统都实现了该标准。IEEE-754 标准规定了浮点算术结果应当如何近似。

要获得精确的结果，并以所需的精度实现最高性能，必须考虑浮点行为的许多方面。在异构计算环境中，这一点尤为重要，因为运算会在不同类型的硬件上执行。

以下各节回顾了浮点运算的基本属性，并介绍融合乘加（Fused Multiply-Add，FMA）运算与点积运算。这些示例展示了不同的实现选择如何影响精度。

### 5.5.1.1 浮点格式

浮点格式与功能由 IEEE-754 标准定义。

该标准规定二进制浮点数据编码为三个字段：

- 符号：1 位，表示正数或负数。
- 指数：以基数 2 的指数，加上一个数值偏置进行编码。
- 尾数（亦称 mantissa 或 fraction）：编码数值的分数部分。

最新版 IEEE-754 标准定义了以下二进制格式的编码与属性：

- 16 位，即半精度（half-precision），对应 CUDA 中的 `__half` 数据类型。
- 32 位，即单精度（single-precision），对应 C、C++ 和 CUDA 中的 `float` 数据类型。
- 64 位，即双精度（double-precision），对应 C、C++ 和 CUDA 中的 `double` 数据类型。
- 128 位，即四倍精度（quad-precision），对应 CUDA 中的 `__float128` 或 `_Float128` 数据类型。

规格化值的浮点编码对应的数值按如下公式计算：

(−1)^sign × 1.mantissa × 2^(exponent−bias)

对于非规范数，公式调整为：

(−1)^sign × 0.mantissa × 2^(1−bias)

单精度与双精度的指数偏置分别为 127 和 1023。1. 的整数部分隐含在分数中。

例如，数值 −192 = (−1)^1 × 2^7 × 1.5，编码为负符号、指数 7 和小数部分 0.5。因此指数 7 表示为：单精度中 7 + 127 = 134 = 10000110，双精度中 7 + 1023 = 1030 = 10000000110。尾数 0.5 = 2^-1 以首位为 1 的二进制值表示。下图展示了 −192 在单精度与双精度下的二进制编码。

由于分数段使用的位数有限，并非所有实数都能被精确表示。例如，数学分数 2/3 的二进制表示为 0.10101010…，小数点后有无限多位。因此 2/3 在以有限精度浮点数表示之前必须舍入。舍入规则与模式由 IEEE-754 规定。最常用的模式是向最近偶数舍入（round-to-nearest-ties-to-even），简称向最近舍入（round-to-nearest）。

### 5.5.1.2 规格化数与非规格化数

指数段既非全 0 又非全 1 的浮点数称为规格化数（normal）。

浮点数的一个重要特性是：最小可表示正规格化数 FLT_MIN 与零之间的间隔非常大。该间隔远大于 FLT_MIN 与次小的规格化数之间的间隔。

浮点非规格化数（subnormal numbers），也称为非规范数（denormals），就是为解决这一问题引入的。非规格化浮点数的指数段全为 0，且尾数段至少有一位为 1。非规格化数是 IEEE-754 浮点标准的必备部分。

非规格化数允许以精度逐渐损失的方式，作为向零突变舍入的替代方案。然而，非规格化数的计算成本更高。因此，不需要严格精度的应用可能选择避免使用非规格化数以提高性能。nvcc 编译器允许通过设置 `-ftz=true` 选项（flush-to-zero，刷零）禁用非规格化数，该选项也包含在 `--use_fast_math` 中。

### 5.5.1.3 特殊值

IEEE-754 标准定义了浮点数的三种特殊值：

**零：**

- 数学意义上的零。
- 注意浮点零有两种可能的表示：+0 与 −0。这与整数零的表示不同。
- `+0 == -0` 求值为真。
- 零的编码为指数与尾数各位全 0。

**无穷：**

- 浮点数遵循饱和算术，即超出可表示范围的运算结果为 +Infinity 或 −Infinity。
- 无穷编码为指数段各位全 1、尾数段各位全 0。无穷值恰有两种编码。
- 涉及无穷与有限非零值的算术运算通常结果为无穷。诸如 Inf * 0.0、Inf − Inf、Inf ∕ Inf、0.0 ∕ 0.0 等不定式结果为 NaN。

**非数（NaN）：**

- NaN 是表示未定义或不可表示值的一种特殊符号。常见例子有 0.0 ∕ 0.0、sqrt(−1.0)、+Inf − Inf。
- NaN 编码为指数段各位全 1、尾数段为任意非全 0 位模式。可能的编码有 2^(mantissa+1) − 2 种。
- 任何涉及 NaN 的算术运算结果均为 NaN。
- 任何涉及 NaN 的有序比较（<、<=、>、>=、==）结果均为 false，包括 NaN == NaN（不满足自反性）。无序比较 NaN != NaN 返回 true。
- NaN 有两种形式：
  - 静默 NaN（quiet NaN，qNaN）用于传播无效运算或无效值产生的错误。无效算术运算通常产生静默 NaN。其编码为尾数最高位为 1。
  - 信令 NaN（signaling NaN，sNaN）用于触发无效操作异常。信令 NaN 通常显式创建。其编码为尾数最高位为 0。
  - 静默与信令 NaN 的具体位模式由实现定义。CUDA 提供 `cuda::std::numeric_limits<T>::quiet_NaN` 与 `cuda::std::numeric_limits<T>::signaling_NaN` 常量来获取这些特殊值。

### 5.5.1.4 结合律

需要特别注意，由于精度有限，数学算术的规则与性质不能直接套用到浮点算术上。下面示例给出单精度值 A、B、C，以及用不同结合顺序计算的和的精确数学值。

```
A = 2^1 × 1.00000000000000000000001
B = 2^0 × 1.00000000000000000000001
C = 2^3 × 1.00000000000000000000001
(A + B) + C = 2^3 × 1.01100000000000000000001011
A + (B + C) = 2^3 × 1.01100000000000000000001011
```

数学上，(A + B) + C 等于 A + (B + C)。

记 rn(x) 为对 x 的一次舍入步骤。在向最近舍入模式下，按 IEEE-754 用单精度浮点算术执行相同的计算，得到：

```
A + B           = 2^1 × 1.1000000000000000000000110000 …
rn(A + B)       = 2^1 × 1.10000000000000000000010
B + C           = 2^3 × 1.0010000000000000000000100100 …
rn(B + C)       = 2^3 × 1.00100000000000000000001
A + B + C       = 2^3 × 1.0110000000000000000000101100 …
rn(rn(A + B) + C)  = 2^3 × 1.01100000000000000000010
rn(A + rn(B + C))  = 2^3 × 1.01100000000000000000001
```

为便于对照，上面也计算了精确的数学结果。按 IEEE-754 计算的结果与精确数学结果不同。此外，rn(rn(A + B) + C) 与 rn(A + rn(B + C)) 对应的结果也互不相同。在这个例子中，rn(A + rn(B + C)) 比 rn(rn(A + B) + C) 更接近正确的数学结果。

该示例表明，即使所有基本运算都符合 IEEE-754，看似完全相同的计算也可能产生不同的结果。

### 5.5.1.5 融合乘加（FMA）

融合乘加（Fused Multiply-Add，FMA）运算只执行一次舍入步骤即可得出结果。若不用 FMA，结果需要两次舍入：乘法一次、加法一次。由于 FMA 只用一次舍入，其结果更精确。

与分开的两次运算相比，FMA 运算对 NaN 的传播处理可能不同。但 FMA 的 NaN 处理在各目标平台上并不完全一致。对于多个 NaN 操作数的不同实现，可能倾向于使用静默 NaN，或传播某个操作数的有效载荷。此外，当存在多个 NaN 操作数时，IEEE-754 并未严格规定确定的有效载荷选择顺序。中间计算中也可能出现 NaN，例如 ∞ × 0 + 1 或 1 × ∞ − ∞，其有效载荷由实现定义。

为清楚起见，先用十进制算术示例说明 FMA 的工作原理。我们用共 5 位有效数字、小数点后 4 位的精度计算 x² − 1。

- x = 1.0008 时，正确的数学结果是 x² − 1 = 1.60064 × 10⁻⁴。只保留小数点后 4 位时最接近的数是 1.6006 × 10⁻⁴。
- 融合乘加运算只用一次舍入步骤就达到正确结果：rn(x×x − 1) = 1.6006 × 10⁻⁴。
- 替代方案是分别计算乘法与加法步骤。x² = 1.00160064 舍入为 rn(x × x) = 1.0016。最终结果为 rn(rn(x × x) − 1) = 1.6000 × 10⁻⁴。

分开舍入乘法与加法的结果偏差了 0.00064。而对应的 FMA 计算只偏差 0.00004，其结果最接近正确的数学答案。结果汇总如下：

```
x               = 1.0008
x²              = 1.00160064
x² − 1          = 1.60064 × 10⁻⁴   （真值）
rn(x² − 1)      = 1.6006 × 10⁻⁴    （融合乘加）
rn(x²)          = 1.0016
rn(rn(x²) − 1)  = 1.6000 × 10⁻⁴    （先乘后加）
```

下面是另一个二进制单精度数值示例：

```
A = 2^0 × 1.00000000000000000000001
B = −2^0 × 1.00000000000000000000010
rn(A × A + B)    = 2⁻⁴⁶ × 1.00000000000000000000000   （融合乘加）
rn(rn(A × A) + B) = 0                                （先乘后加）
```

- 分开计算乘法与加法会丢失全部有效位，结果为 0。
- 而 FMA 计算的结果等于数学值。

融合乘加有助于防止相减相消（subtractive cancellation）期间的精度损失。当量级相近、符号相反的量相加时，会发生相减相消。此时许多前导位相互抵消，剩下有意义的位变少。融合乘加在乘法阶段计算双倍宽度的乘积。因此，即使加法阶段发生相减相消，乘积中仍保留足够多的有效位，可得到精确结果。

**CUDA 中的融合乘加支持**

CUDA 通过以下几种方式为 float 与 double 数据类型提供融合乘加运算：

- 使用编译标志 `-fmad=true` 或 `--use_fast_math` 时，`x * y + z` 会自动融合。
- C 标准库函数 `fma(x, y, z)` 与 `fmaf(x, y, z)`。
- CUDA 数学内联函数 `__fmaf_[rd, rn, ru, rz]`、`__fmaf_ieee_[rd, rn, ru, rz]` 与 `__fma_[rd, rn, ru, rz]`。
- CUDA C++ 标准库函数 `cuda::std::fma(x, y, z)` 与 `cuda::std::fmaf(x, y, z)`。

**主机端平台的融合乘加支持**

是否采用融合运算取决于平台是否支持该运算，以及代码如何编译。在比较 CPU 与 GPU 结果时，了解主机端平台的 FMA 支持情况非常重要。

- 编译器标志与 FMA 硬件支持：
  - GCC 与 Clang 用 `-mfma`，NVC++ 用 `-Mfma`，Microsoft Visual Studio 用 `/fp:contract`。
  - x86 平台需要 AVX2 指令集，例如 GCC 或 Clang 用 `-mavx2` 编译的代码，Microsoft Visual Studio 用 `/arch:AVX2`。
  - Arm64（AArch64）平台需要 Advanced SIMD（Neon）指令集。
- C 标准库函数 `fma(x, y, z)` 与 `fmaf(x, y, z)`。
- C++ 标准库函数 `std::fma(x, y, z)` 与 `std::fmaf(x, y, z)`。
- CUDA C++ 标准库函数 `cuda::std::fma(x, y, z)` 与 `cuda::std::fmaf(x, y, z)`。

### 5.5.1.6 点积示例

考虑求两个短向量 **a** 与 **b** 的点积问题，两向量各有四个元素。

**a** = (a1, a2, a3, a4)，**b** = (b1, b2, b3, b4)，**a** · **b** = a1·b1 + a2·b2 + a3·b3 + a4·b4

虽然该运算用数学语言写下来很简单，但在软件中实现时有多种选择，可能导致结果略有不同。这里提出的所有策略都使用完全符合 IEEE-754 的运算。

**算法 1（示例）**：计算点积最简单的方法是按顺序累加乘积，保持乘法与加法分开。

最终结果可表示为：((((a1 × b1) + (a2 × b2)) + (a3 × b3)) + (a4 × b4))。

**算法 2（示例）**：使用融合乘加按顺序计算点积。

最终结果可表示为：((a4 × b4) + ((a3 × b3) + ((a2 × b2) + (a1 × b1 + 0))))。

**算法 3（示例）**：采用分治策略计算点积。先分别求向量前半与后半的点积，再用加法合并这两个结果。该算法称为"并行算法"，因为两个子问题相互独立，可并行计算。但该算法并不要求并行实现；它也可以用单线程实现。

最终结果可表示为：(((a1 × b1) + (a2 × b2)) + ((a3 × b3) + (a4 × b4)))。

### 5.5.1.7 舍入

IEEE-754 标准要求支持多种运算。这些运算包括：加、减、乘、除、平方根、融合乘加、求余、转换、缩放、取符号、比较等算术运算。在给定格式与舍入模式（rounding mode）下，这些运算的结果在标准的所有实现中都保持一致。

**舍入模式**

IEEE-754 标准定义了四种舍入模式：向最近舍入、向正无穷舍入、向负无穷舍入、向零舍入。CUDA 支持全部四种模式。默认情况下，运算采用向最近舍入。内联数学函数可为单个运算选择其他舍入模式。

| 舍入模式 | 含义 |
|---|---|
| rn | 向最近舍入，平局取偶 |
| rz | 向零舍入 |
| ru | 向 +∞ 舍入 |
| rd | 向 −∞ 舍入 |

### 5.5.1.8 主机端/设备端计算精度说明

浮点计算结果的精度受多种因素影响。本节汇总了为实现可靠浮点计算结果需要注意的重要事项。其中一些方面在前面的章节中已更详细地描述。

这些方面在比较 CPU 与 GPU 结果时同样重要。主机端与设备端执行之间的差异必须谨慎解读。出现差异并不一定意味着 GPU 的结果不正确，也不意味着 GPU 有问题。

**结合律：**

浮点加法与乘法在有限精度下不满足结合律，因为它们常常产生无法在目标格式中直接表示的数学值，需要舍入。运算求值的顺序影响舍入误差的累积方式，可能显著改变最终结果。

**融合乘加：**

融合乘加以单次运算计算 a×b+c，精度更高、执行速度更快。最终结果的精度可能受到其使用的影响。融合乘加依赖硬件支持，可通过显式调用相关函数或隐式地通过编译器优化标志启用。

**精度：**

提高浮点精度可能改善结果的精度。更高精度能减少有效位损失，并支持更宽的数值范围。但高精度类型的吞吐更低、消耗更多寄存器。此外，用它们显式存储输入与输出会增加内存占用与数据搬运。

**编译器标志与优化：**

所有主流编译器都提供多种优化标志来控制浮点运算的行为。

- GCC（-O3）、Clang（-O3）、nvcc（-O3）与 Microsoft Visual Studio（/O2）的最高优化级别不影响浮点语义。但内联、循环展开、向量化与公共子表达式消除可能影响结果。NVC++ 编译器还需要 `-Kieee -Mnofma` 标志才能保证 IEEE-754 兼容语义。
- 关于影响浮点行为的选项详情，请参阅 GCC、Clang、Microsoft Visual Studio 编译器、nvc++ 与 Arm C/C++ 编译器的文档。
- 另请参阅 nvcc 用户手册中对专门影响 CUDA 设备端代码浮点行为的编译器标志的详细说明：`-ftz`、`-prec-div`、`-prec-sqrt`、`-fmad`、`--use_fast_math`。除了这些浮点选项外，在用户程序的上下文中核实其他编译器优化的效果也很重要。鼓励用户通过广泛测试验证结果的正确性，并比较启用优化与禁用全部设备端代码优化（见 `-G` 编译器标志）所得到的结果。

**库实现：**

IEEE-754 标准之外定义的函数不能保证正确舍入，其行为由实现定义。因此，结果可能在不同平台之间存在差异，包括主机端、设备端与不同设备架构之间。

**确定性结果：**

确定性结果是指，在相同输入与相同指定条件下运行，每次计算产生相同的按位数值输出。此类条件包括：

- 硬件依赖，例如在同一 CPU 处理器或 GPU 设备上执行。
- 编译器方面，例如编译器版本以及编译器标志与优化。
- 影响计算的运行期条件，例如舍入模式或环境变量。
- 计算的输入完全一致。
- 线程配置，包括参与计算的线程数量与组织方式，例如块（block）与网格（grid）大小。
- 原子算术运算的顺序取决于硬件调度，可能在不同运行之间发生变化。

**利用 CUDA 库：**

CUDA 数学库、C 标准库数学函数与 C++ 标准库数学函数旨在提高开发者的生产力，适用于常见的浮点数学与数值密集型常规功能。这些功能提供一致的高层接口、经过优化，并在各种平台与边界情况下经过广泛测试。鼓励用户充分利用这些库，避免繁琐的手动重复实现。

**复数支持：**

- CUDA C++ 标准库在 `<cuda/std/complex>` 头文件中通过 `cuda::std::complex` 类型支持复数。更多细节请参阅 libcu++ 文档。
- CUDA 还在 `cuComplex.h` 头文件中通过 `cuComplex` 与 `cuDoubleComplex` 类型提供基本复数支持。

## 5.5.3 CUDA 与 IEEE-754 的兼容性

所有 GPU 设备遵循 IEEE 754-2019 二进制浮点算术标准，但有以下限制：

- 没有可动态配置的舍入模式；但大多数运算支持多个固定的 IEEE 舍入模式，可通过专门命名的设备端内联函数选择。
- 没有检测浮点异常的机制，因此所有运算都视为 IEEE-754 异常始终被屏蔽。若发生异常事件，则按 IEEE-754 定义的默认屏蔽响应交付。出于这一原因，虽然支持信令 NaN（sNaN）编码，但它们并不触发信令，按静默异常处理。
- 浮点运算可能修改输入 NaN 有效载荷的位模式。取绝对值与取负等运算也可能不符合 IEEE 754 的要求，可能导致 NaN 的符号以实现定义的方式更新。

为最大化结果的可移植性，建议用户使用 nvcc 编译器浮点选项的默认设置：`-ftz=false`、`-prec-div=true`、`-prec-sqrt=true`，不使用 `--use_fast_math` 选项。注意，浮点表达式的重新结合与收缩默认是允许的，与 `--fmad=true` 选项类似。这些编译标志的详细说明请参阅 nvcc 用户手册。

IEEE-754 与 C/C++ 语言标准均未明确规定：当舍入到整数的值超出目标整数格式范围时，把浮点值转换为整数值的行为。GPU 设备的钳位行为在 PTX ISA 转换指令章节中阐明。但编译器优化可能利用这种"未明确规定"的条款——当超出范围的转换不是直接通过 PTX 指令调用时，可能导致未定义行为，使 CUDA 程序无效。CUDA 数学文档针对每个函数/内联函数向用户发出警告。例如 `__double2int_rz()` 指令，其行为可能与主机端编译器和库实现不同。

**原子函数非规范数行为：**

无论 `-ftz` 编译器标志如何设置，原子操作在浮点非规范数方面的行为如下：

- 全局内存上的原子单精度浮点加法始终按刷零模式运行，即等价于 PTX `add.rn.ftz.f32` 语义。
- 共享内存上的原子单精度浮点加法始终支持非规范数，即等价于 PTX `add.rn.f32` 语义。

## 5.5.4 CUDA 与 C/C++ 的兼容性

**浮点异常：**

与主机端实现不同，设备端代码支持的数学运算符与函数不设置全局 `errno` 变量，也不报告浮点异常来指示错误。因此，若需要错误诊断机制，用户应为这些函数实现额外的输入与输出筛查。

**浮点运算的未定义行为：**

数学运算未定义行为的常见情形包括：

- 数学运算符与函数的非法参数：
  - 使用未初始化的浮点变量。
  - 在生命周期之外使用浮点变量。
  - 有符号整数溢出。
  - 解引用非法指针。
- 浮点特有的未定义行为：
  - 将浮点值转换为结果无法表示的整数类型是未定义行为。这包括 NaN 与无穷。

用户有责任确保 CUDA 程序有效。非法参数可能导致未定义行为，并受编译器优化影响。

与整数除零不同，浮点除零不是未定义行为，也不受编译器优化影响，而是实现特定的行为。符合 IEC-60559（IEEE-754）的 C++ 实现（包括 CUDA）产生无穷。注意，无效浮点运算产生 NaN，不应误解为未定义行为。例如零除以零、无穷除以无穷。

**浮点字面量可移植性：**

C 与 C++ 都允许用十进制或十六进制记法表示浮点值。C99 与 C++17 支持的十六进制浮点字面量表示一种可用二进制精确表达的科学记法实值。但这不保证该字面量能映射到目标变量中存储的实际值（见下段）。反过来，十进制浮点字面量可能表示一个无法用二进制表达的数值。

根据 C++ 标准规则，十六进制与十进制浮点字面量按向最近可表示值（较大或较小者，取舍由实现定义）舍入。这种舍入行为在主机端与设备端可能不同。

```c
float f1 = 0.5f;    // 0.5，'0.5f' 是十进制浮点字面量
float f2 = 0x1p-1f; // 0.5，'0x1p-1f' 是十六进制浮点字面量
float f3 = 0.1f;
// f1、f2 表示为 0 01111110 00000000000000000000000
// f3 表示为 0 01111011 10011001100110011001101
```

同一浮点表达式在运行期与编译期求值时存在以下可移植性问题：

- 浮点表达式的运行期求值可能受所选舍入模式、浮点收缩（FMA）与重结合编译器设置，以及浮点异常的影响。注意 CUDA 不支持浮点异常，舍入模式默认为向最近偶数舍入。可用内联函数选择其他舍入模式。
- 编译器可能对常量表达式使用更高精度的内部表示。
- 编译器可能执行常量折叠、常量传播、公共子表达式消除等优化，导致最终值或比较结果不同。

**C 标准数学库说明：**

常见数学函数的主机端实现以平台相关的方式映射到 C 标准数学库函数。这些函数由主机端编译器与相应的主机端 libm（若有）提供。

- 主机端编译器未提供的函数在 `crt/math_functions.h` 头文件中实现。例如 `erfinv()` 在该文件中实现。
- 较少见的函数，如 `rhypot()` 与 `cyl_bessel_i0()`，仅在设备端代码中可用。

如前所述，数学函数的主机端与设备端实现相互独立。有关这些函数的行为详情，请参阅主机端实现的文档。

## 5.5.5 浮点功能暴露方式

CUDA 支持的数学函数通过以下方式暴露：

**内置 C/C++ 语言算术运算符：**

- `x + y`、`x - y`、`x * y`、`x ∕ y`、`x++`、`x--`、`x += y`、`x -= y`、`x *= y`、`x ∕= y`。
- 支持单精度、双精度与四倍精度类型，即 `float`、`double`、`__float128`/`_Float128`。
  - 分别包含 `<cuda_fp16.h>` 与 `<cuda_bf16.h>` 头文件后，也支持 `__half` 与 `__nv_bfloat16` 类型。
  - `__float128`/`_Float128` 类型支持依赖主机端编译器与设备端计算能力，见"支持的浮点类型"表。
- 在主机端与设备端代码中均可用。
- 其行为受 nvcc 优化标志影响。

**CUDA C++ 标准库数学函数：**

- 通过 `<cuda/std/cmath>` 头文件与 `cuda::std::` 命名空间暴露 C++ `<cmath>` 头函数的完整集合。
- 支持 IEEE-754 标准浮点类型 `__half`、`float`、`double`、`__float128`，以及 Bfloat16 `__nv_bfloat16`。
  - `__float128` 支持依赖主机端编译器与设备端计算能力，见"支持的浮点类型"表。
- 在主机端与设备端代码中均可用。
- 它们常常依赖 CUDA 数学 API 函数。因此，主机端与设备端代码之间的精度可能存在差异。
- 其行为受 nvcc 优化标志影响。
- 部分功能也支持常量表达式，如按 C++23 与 C++26 标准规范的 `constexpr` 函数。

**CUDA C 标准库数学函数（CUDA 数学 API）：**

- 暴露 C `<math.h>` 头函数的子集。
- 支持单精度与双精度类型，即 `float` 与 `double`。
  - 在主机端与设备端代码中均可用。
  - 无需额外头文件。
  - 其行为受 nvcc 优化标志影响。
- `<math.h>` 头功能子集也适用于 `__half`、`__nv_bfloat16` 与 `__float128`/`_Float128` 类型。这些函数名称与 C 标准库的类似。
  - `__half` 与 `__nv_bfloat16` 类型分别需要 `<cuda_fp16.h>` 与 `<cuda_bf16.h>` 头文件。它们在主机端与设备端代码中的可用性按函数定义。
  - `__float128`/`_Float128` 类型支持依赖主机端编译器与设备端计算能力，见"支持的浮点类型"表。相关函数需要 `crt/device_fp128_functions.h` 头文件，且仅在设备端代码中可用。
- 主机端与设备端代码之间的精度可能不同。

**非标准 CUDA 数学函数（CUDA 数学 API）：**

- 暴露 C/C++ 标准库之外的数学功能。
- 主要支持单精度与双精度类型，即 `float` 与 `double`。
  - 主机端与设备端代码的可用性按函数定义。
  - 无需额外头文件。
  - 主机端与设备端代码之间的精度可能不同。
- `__nv_bfloat16`、`__half`、`__float128`/`_Float128` 对有限函数集提供支持。
  - `__half` 与 `__nv_bfloat16` 类型分别需要 `<cuda_fp16.h>` 与 `<cuda_bf16.h>` 头文件。
  - `__float128`/`_Float128` 类型支持依赖主机端编译器与设备端计算能力，见"支持的浮点类型"表。相关函数需要 `crt/device_fp128_functions.h` 头文件。
  - 仅在设备端代码中可用。
- 其行为受 nvcc 优化标志影响。

**内联数学函数（CUDA 数学 API）：**

- 支持单精度与双精度类型，即 `float` 与 `double`。
- 仅在设备端代码中可用。
- 比相应的 CUDA 数学 API 函数更快，但精度较低。
- 其行为不受 nvcc 浮点优化标志 `-prec-div=false`、`-prec-sqrt=false` 与 `-fmad=true` 的影响。唯一例外是 `-ftz=true`，它也包含在 `-use_fast_math` 中。

## 5.5.6 内置算术运算符

内置 C/C++ 语言运算符，如 `x + y`、`x - y`、`x * y`、`x ∕ y`、`x++`、`x--` 与倒数 `1 ∕ x`，对单精度、双精度、四倍精度类型遵循 IEEE-754 标准。它们保证在使用向最近偶数舍入模式时最大 ULP 误差为零。在主机端与设备端代码中均可用。

nvcc 编译标志 `-fmad=true`（也包含在 `--use_fast_math` 中）将浮点乘法与加/减收缩为浮点乘加运算，对单精度类型 `float` 的最大 ULP 误差有如下影响：

- `x * y + z` → `__fmaf_rn(x, y, z)`：0 ULP

nvcc 编译标志 `-prec-div=false`（也包含在 `--use_fast_math` 中）对除法运算符 `∕`（单精度类型 `float`）的最大 ULP 误差有如下影响：

- `x ∕ y` → `__fdividef(x, y)`：2 ULP
- `1 ∕ x`：1 ULP

## 5.5.7 CUDA C++ 数学标准库函数

CUDA 通过 `cuda::std::` 命名空间全面支持 C++ 标准库数学函数。这些功能属于 `<cuda/std/cmath>` 头文件的一部分。在主机端与设备端代码中均可用。

以下各节说明与 CUDA 数学 API 的映射关系，以及每个函数在设备端执行时的误差界。

- 最大 ULP 误差表述为：函数返回值与按向最近偶数舍入模式得到的对应精度正确舍入结果之间，以 ULP 为单位的差的绝对值的最大观测值。
- 误差界来源于广泛但非穷举的测试。因此不予保证。

## 5.5.9 内联函数

内联数学函数是其对应的 CUDA C 标准库数学函数的更快、但精度较低的版本。

- 它们与原函数同名，前缀加双下划线，如 `__sinf(x)`。
- 仅在设备端代码中可用。
- 因为映射到更少的原生指令，所以更快。
- `--use_fast_math` 标志自动将相应的 CUDA 数学 API 函数翻译为内联函数。受影响函数的完整列表见"--use_fast_math 影响"一节。

### 5.5.9.1 基本内联函数

一部分数学内联函数允许指定舍入模式：

- 后缀为 `_rn` 的函数采用向最近偶数舍入模式。
- 后缀为 `_rz` 的函数采用向零舍入模式。
- 后缀为 `_ru` 的函数采用向上舍入（向正无穷）模式。
- 后缀为 `_rd` 的函数采用向下舍入（向负无穷）模式。

`__fadd_[rn,rz,ru,rd]()`、`__dadd_[rn,rz,ru,rd]()`、`__fmul_[rn,rz,ru,rd]()` 与 `__dmul_[rn,rz,ru,rd]()` 函数映射到编译器永远不会合并为 FFMA 或 DFMA 指令的加法与乘法运算。相反，由 `*` 与 `+` 运算符生成的加法与乘法通常会被合并为 FFMA 或 DFMA。

下表列出单精度与双精度浮点内联函数。它们的最大 ULP 误差均为 0，符合 IEEE 标准。

| `__logf(x)` | ln(x) | x ∈ [0.5, 2] 时绝对误差 2⁻²¹·⁴¹，其他情况 3 ULP |

| `__log10f(x)` | log₁₀(x) | x ∈ [0.5, 2] 时绝对误差 2⁻²⁴，其他情况 3 ULP |
| `__sinf(x)` | sin(x) | x ∈ [−π, π] 时绝对误差 2⁻²¹·⁴¹，其他情况更大 |
| `__cosf(x)` | cos(x) | x ∈ [−π, π] 时绝对误差 2⁻²¹·⁴¹，其他情况更大 |
| `__sincosf(x, sptr, cptr)` | sin(x)、cos(x) | 按分量，与 `__sinf(x)` 和 `__cosf(x)` 相同 |
| `__tanf(x)` | tan(x) | 由 `__sinf(x)` * (1 ∕ `__cosf(x)`) 导出 |
| `__tanhf(x)` | tanh(x) | 最大相对误差：2⁻¹¹；即使在 `-ftz=true` 编译器标志下，非规格化结果也不会被刷零 |

### 5.5.9.3 --use_fast_math 影响

nvcc 编译器标志 `--use_fast_math` 将设备端代码中调用的一组 CUDA 数学 API 函数翻译为其内联版本。注意 CUDA C++ 标准库函数也受该标志影响。有关使用内联函数而非 CUDA 数学 API 函数的影响（精度降低、特殊情况处理不同），见"内联函数"一节。

> 更稳健的做法是：仅在性能收益合理、且能接受改变后特性（如精度降低、特殊情况处理不同）的场合，有选择地将数学函数调用替换为内联版本。

**表 60：直接受 --use_fast_math 影响的函数**

| 设备端函数 | 内联函数 |
|---|---|
| `x/y`、`fdividef(x, y)` | `__fdividef(x, y)` |
| `sinf(x)` | `__sinf(x)` |
| `cosf(x)` | `__cosf(x)` |
| `tanf(x)` | `__tanf(x)` |
| `sincosf(x, sptr, cptr)` | `__sincosf(x, sptr, cptr)` |
| `logf(x)` | `__logf(x)` |
| `log2f(x)` | `__log2f(x)` |
| `log10f(x)` | `__log10f(x)` |
| `expf(x)` | `__expf(x)` |
| `exp10f(x)` | `__exp10f(x)` |
| `powf(x, y)` | `__powf(x, y)` |
| `tanhf(x)` | `__tanhf(x)` |
