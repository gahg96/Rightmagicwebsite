# 5.7 CUDA C++ 内存模型

标准 C++ 呈现的视图是：同步线程的开销是均匀且低廉的。

CUDA C++ 则不同：同步线程的开销随着线程之间的距离增大而增长。同一线程块内线程之间的同步开销很低，但跨越运行在多个 GPU 和 CPU 上的系统中任意线程的同步开销很高。

为了应对这种不均匀且并非总是低廉的线程同步开销，CUDA C++ 在 `cuda::` 命名空间中用线程作用域扩展了标准 C++ 的内存模型和并发设施，默认保留标准 C++ 的语法和语义。

## 5.7.1 线程作用域

线程作用域指定了哪些线程可以通过 `cuda::atomic` 或 `cuda::barrier` 等同步原语相互同步。

```cpp
namespace cuda {

enum thread_scope {
   thread_scope_system,
   thread_scope_device,
   thread_scope_block,
   thread_scope_thread
};

}     // namespace cuda
```

### 5.7.1.1 作用域关系

每个程序线程都通过一个或多个线程作用域关系与每个其它程序线程相关联：

- 系统中的每个线程都通过系统线程作用域 `cuda::thread_scope_system` 与系统中的每个其它线程相关联；
- 每个 GPU 线程都通过设备线程作用域 `cuda::thread_scope_device` 与同一 CUDA 设备内、同一内存同步域中的每个其它 GPU 线程相关联；
- 每个 GPU 线程都通过线程块作用域 `cuda::thread_scope_block` 与同一 CUDA 线程块中的每个其它 GPU 线程相关联；
- 每个线程都通过线程作用域 `cuda::thread_scope_thread` 与自身相关联。

## 5.7.2 同步原语

`std::` 和 `cuda::std::` 命名空间中的类型，在实例化时指定作用域 `cuda::thread_scope_system` 的情况下，其行为与 `cuda::` 命名空间中的对应类型相同。

## 5.7.3 原子性

当满足以下条件之一时，原子操作在其指定的作用域内是原子的：

- 它指定的作用域不是 `cuda::thread_scope_system`；或者
- 作用域是 `cuda::thread_scope_system`，并且满足以下任一条件：
  - 它作用于系统分配内存中的对象，且 `pageableMemoryAccess` 为 1[0,1]；或
  - 它作用于托管内存（managed memory）中的对象，且 `concurrentManagedAccess` 为 1[1]；或
  - 它作用于映射内存中的对象，且 `hostNativeAtomicSupported` 为 1；或
  - 它是作用于映射内存中自然对齐的 1、2、4、8 或 16 字节大小的对象的加载或存储[2]；或
  - 它作用于 GPU 内存中的对象，只有 GPU 线程访问它，并且满足以下任一条件：
    - 每个访问该对象的源设备 `srcDev` 与对象所在的 GPU `dstDev` 之间，`cudaDeviceGetP2PAttribute(&val, cudaDevP2PAttrNativeAtomicSupported, srcDev, dstDev)` 为 1[1]；或
    - 只有单个 GPU 的 GPU 线程并发访问它。

> **注：**
>
> - [0] 如果 `PageableMemoryAccessUsesHostPagetables` 为 0，那么对映射文件（memory mapped file）或 hugetlbfs 分配的原子操作不是原子的。
> - [1] 在这些情况下，系统作用域的张量归约操作只有在 `hostNativeAtomicSupported` 为 1 时才在系统作用域内原子。系统作用域的张量归约操作包括 PTX `{multimem.}cp.reduce.async.bulk.tensor.relaxed.sys` 指令族，以及暴露这些指令的 API，例如 `cuda::ptx::cp_reduce_async_bulk_tensor`。
> - [2] 如果 `hostNativeAtomicSupported` 为 0，对系统分配内存或映射内存中自然对齐的 16 字节宽对象在系统作用域的原子加载或存储操作需要系统支持。NVIDIA 未知晓任何缺乏该支持的系统，也没有 CUDA API 查询可以检测这类系统。

关于系统分配内存、托管内存、映射内存、CPU 内存和 GPU 内存的更多信息，见本指南的相关章节。

## 5.7.4 数据竞争

按如下方式修改 ISO/IEC IS 14882（C++ 标准）中 `intro.races` 段落 21：

> 程序的执行中包含数据竞争，如果它包含两个可能并发的冲突动作，其中至少一个不是在一个包含执行另一操作之线程的作用域内原子的，并且两者之间没有先行发生（happens-before）关系，信号处理程序的特殊情况除外。任何这样的数据竞争都会导致未定义行为。[…]

按如下方式修改 ISO/IEC IS 14882（C++ 标准）中 `thread.barrier.class` 段落 4：

> 4. 除析构函数外，并发调用 `barrier` 的成员函数不会引入数据竞争，如同它们是原子操作。[…]

按如下方式修改 ISO/IEC IS 14882（C++ 标准）中 `thread.latch.class` 段落 2：

> 2. 除析构函数外，并发调用 `latch` 的成员函数不会引入数据竞争，如同它们是原子操作。[…]

按如下方式修改 ISO/IEC IS 14882（C++ 标准）中 `thread.sema.cnt` 段落 3：

> 3. 除析构函数外，并发调用 `counting_semaphore` 的成员函数不会引入数据竞争，如同它们是原子操作。

按如下方式修改 ISO/IEC IS 14882（C++ 标准）中 `thread.stoptoken.intro` 段落 5：

> 对 `request_stop`、`stop_requested` 和 `stop_possible` 函数的调用不会引入数据竞争，如同它们是原子操作。[…]

按如下方式修改 ISO/IEC IS 14882（C++ 标准）中 `atomics.fences` 段落 2 到 4：

> 释放栅栏 A 与获取栅栏 B 同步，如果存在原子操作 X 和 Y，它们都作用于某个原子对象 M，使得 A 排在 X 之前（sequenced before），X 修改 M，Y 排在 B 之前，且 Y 读取 X 写入的值，或读取若 X 是释放操作、X 将领衔的假想释放序列中任一副作用写入的值，并且每个操作（A、B、X 和 Y）指定的作用域都包含执行其它每个操作的线程。

> 释放栅栏 A 与原子操作 B 同步，如果 B 对原子对象 M 执行获取操作，并且存在原子操作 X，使得 A 排在 X 之前，X 修改 M，B 读取 X 写入的值，或读取若 X 是释放操作、X 将领衔的假想释放序列中任一副作用写入的值，并且每个操作（A、B 和 X）指定的作用域都包含执行其它每个操作的线程。

> 原子操作 A 是原子对象 M 上的释放操作，它与获取栅栏 B 同步，如果存在原子对象 M 上的某个原子操作 X，使得 X 排在 B 之前，且 X 读取 A 写入的值，或读取 A 领衔的释放序列中任一副作用写入的值，并且每个操作（A、B 和 X）指定的作用域都包含执行其它每个操作的线程。
## 5.7.5 示例：消息传递

下面的示例把块 0 中线程存入变量 `x` 的消息，通过标志 `f` 传递给块 1 中的线程：

初始：

```cpp
int x = 0, f = 0;
```

块 0 的线程 0：

```cpp
x = 42;
cuda::atomic_ref<int, cuda::thread_scope_device> flag(f);
flag.store(1, memory_order_release);
```

块 1 的线程 0：

```cpp
cuda::atomic_ref<int, cuda::thread_scope_device> flag(f);
while(flag.load(memory_order_acquire) != 1);
assert(x == 42);
```

在下面前一个示例的变体中，两个线程没有同步就并发访问 `f` 对象，这导致数据竞争，表现出未定义行为：

初始：

```cpp
int x = 0, f = 0;
```

块 0 的线程 0：

```cpp
x = 42;
cuda::atomic_ref<int, cuda::thread_scope_block> flag(f);
flag.store(1, memory_order_release); // UB: 数据竞争
```

块 1 的线程 0：

```cpp
cuda::atomic_ref<int, cuda::thread_scope_device> flag(f);
while(flag.load(memory_order_acquire) != 1); // UB: 数据竞争
assert(x == 42);
```

虽然对 `f` 的内存操作（存储和加载）是原子的，但存储操作的作用域是“块作用域”。由于存储由块 0 的线程 0 执行，它只包含块 0 的所有其它线程。而执行加载的线程在块 1 中，即它不在块 0 存储操作所包含的作用域内，导致存储和加载不满足“原子”条件，从而引入数据竞争。

更多示例见 PTX 内存一致性模型 litmus 测试。
