# 5.8 CUDA C++ 执行模型

CUDA C++ 力求为所有设备执行线程提供并行前向推进（parallel forward progress）[intro.progress.9]，以便用 CUDA C++ 并行化已有的 C++ 应用程序。

[intro.progress]

- [intro.progress.7]：对于提供并发前向推进保证的执行线程，只要它尚未终止，实现保证该线程最终会取得进展。
  - 注 5：无论其它执行线程（如果有）是否已经或正在取得进展，此条都适用。所谓“最终满足这一要求”，是指这将在未指定但有限的时间内发生。——注结束
- [intro.progress.9]：对于提供并行前向推进保证的执行线程，如果它尚未执行过任何执行步骤，实现不要求保证它最终取得进展；一旦该线程执行了一个步骤，它就提供并发前向推进保证。
  - 注 6：这没有指定何时启动该执行线程的要求，通常由创建该执行线程的实体指定。例如，一个提供并发前向推进保证、按任意顺序依次执行一组任务中任务的执行线程，满足对这些任务的并行前向推进要求。——注结束

CUDA C++ 编程语言是 C++ 编程语言的扩展。本节记录对当前 ISO 国际标准 ISO/IEC 14882——C++ 编程语言草案的 [intro.progress] 章节的修改和扩展。修改的章节会明确指出，其差异用加粗标出。其余章节均为新增内容。

## 5.8.1 主机端线程

由主机端实现创建以执行 `main`、`std::thread` 和 `std::jthread` 的执行线程所提供的前向推进，是主机端实现的实现定义行为 [intro.progress]。通用主机端实现应当提供并发前向推进。

如果主机端实现提供并发前向推进 [intro.progress.7]，则 CUDA C++ 为设备线程提供并行前向推进 [intro.progress.9]。

## 5.8.2 设备线程

一旦设备线程取得进展：

- 如果它是协作网格（Cooperative Grid）的一部分，则其网格中的所有设备线程最终都应取得进展；
- 否则，其线程块簇（thread-block cluster）中的所有设备线程最终都应取得进展。
  - 注：其它线程块簇中的线程不保证最终取得进展。——注结束
  - 注：这意味着其线程块内的所有设备线程最终都应取得进展。——注结束

按如下方式修改 [intro.progress.1]（修改处加粗）：

> 实现可以假设任何主机端线程最终会执行以下之一：
>
> 1. 终止；
> 2. 调用函数 `std::this_thread::yield`（[thread.thread.this]）；
> 3. 调用库 I/O 函数；
> 4. 通过 volatile 泛左值执行访问；
> 5. 执行同步操作或原子操作；或
> 6. 继续执行平凡无限循环（[stmt.iter.general]）。
>
> 实现可以假设任何设备线程最终会执行以下之一：
>
> 1. 终止；
> 2. 调用库 I/O 函数；
> 3. 通过 volatile 泛左值执行访问，但指定对象具有自动存储期时除外；或
> 4. 执行同步操作或原子读操作，但指定对象具有自动存储期时除外。
>
> 注：设备线程相对主机端线程的一些当前限制是已知实现缺陷，我们可能随时间修复。例如，对具有自动存储期的对象最终只执行 volatile 或原子操作的设备线程，会产生未定义行为。但设备线程相对主机端线程的其它限制是刻意的选择。它们使得一些性能优化成为可能——如果设备线程严格遵循 C++ 标准，这些优化就不可能实现。例如，为最终只执行原子写入或栅栏的程序提供前向推进，会以微小的实际收益为代价降低整体性能。——注结束

主机端线程与设备线程在前向推进保证上的差异示例，源于对 [intro.progress.1] 的上述修改。

下面的示例用“host.threads.\<id\>”和“device.threads.\<id\>”分别引用上述主机端线程和设备线程的实现假设的条目。

```cpp
// 示例：Execution.Model.Device.0
// 结果：网格最终终止，依据 device.threads.4，因为原子对象不具有自动存储期。

__global__ void ex0(cuda::atomic_ref<int, cuda::thread_scope_device> atom) {
     if (threadIdx.x == 0) {
         while(atom.load(cuda::memory_order_relaxed) == 0);
     } else if (threadIdx.x == 1) {
         atom.store(1, cuda::memory_order_relaxed);
     }
}
```

```cpp
// 示例：Execution.Model.Device.1
// 允许的结果：没有线程取得进展，因为设备线程不支持 host.threads.2。

__global__ void ex1() {
     while(true) cuda::std::this_thread::yield();
}
```

```cpp
// 示例：Execution.Model.Device.2
// 允许的结果：没有线程取得进展，因为设备线程不支持 host.threads.4
// ——针对具有自动存储期的对象（见 device.threads.3 中的例外）。

__global__ void ex2() {
     volatile bool True = true;
     while(True);
}
```

```cpp
// 示例：Execution.Model.Device.3
// 允许的结果：没有线程取得进展，因为设备线程不支持 host.threads.5
// ——针对具有自动存储期的对象（见 device.threads.4 中的例外）。

__global__ void ex3() {
     cuda::atomic<bool, cuda::thread_scope_thread> True = true;
     while(True.load());
}
```

```cpp
// 示例：Execution.Model.Device.4
// 允许的结果：没有线程取得进展，因为设备线程不支持 host.thread.6。

__global void ex4() {
     while(true) { /* empty */ }
}
```
## 5.8.3 CUDA API

CUDA API 调用最终要么返回，要么保证至少一个设备线程取得进展。

CUDA 查询函数（例如 `cudaStreamQuery`、`cudaEventQuery` 等）在没有设备线程取得进展的情况下，不应持续返回 `cudaErrorNotReady`。

> 注：该设备线程不必与 API 调用“相关”，例如，作用于一个流或进程的 API 可以保证另一个流或进程上的设备线程取得进展。——注结束

> 注：测试程序是否符合 CUDA API 前向推进的一种简单但不充分的方法是：设置环境变量 `CUDA_DEVICE_MAX_CONNECTIONS=1 CUDA_LAUNCH_BLOCKING=1` 运行程序，然后检查程序是否仍能终止。如果不能终止，程序就有 bug。这种方法不充分，因为它捕捉不到所有的前向推进 bug，但它能捕捉到许多这类 bug。——注结束

CUDA API 前向推进保证的示例：

```cpp
// 示例：Execution.Model.API.1
// 结果：如果没有其它设备线程（例如来自其它进程的线程）正在取得进展，
// 本程序终止并返回 cudaSuccess。
// 依据：CUDA 保证，如果设备为空：
// - `cudaDeviceSynchronize` 最终保证至少一个设备线程取得进展，这意味着
//   `hello_world` 网格和它的一个设备线程最终启动。
// - 所有线程块线程最终启动（依据“如果一个设备线程取得进展，其线程块簇中的
//   所有其它线程最终取得进展”）。
// - 一旦线程块中的所有线程到达 `__syncthreads` 屏障，所有等待的线程都被解除阻塞。
// - 因此所有设备线程最终退出 `hello_world` 网格。
// - 并且 `cudaDeviceSynchronize` 最终解除阻塞。

__global__ void hello_world() { __syncthreads(); }
int main() {
     hello_world<<<1,2>>>();
     return (int)cudaDeviceSynchronize();
}
```

```cpp
// 示例：Execution.Model.API.2
// 允许的结果：最终，没有线程取得进展。
// 依据：下面的 `cudaDeviceSynchronize` API 只有在设备线程最终取得进展并设置
// 标志时才会被调用。
// 但是，CUDA 只保证在同步 API 被调用时 `producer` 设备线程最终启动。
// 因此，主机端线程可能永远无法从标志自旋循环中解除阻塞。

cuda::atomic<int, cuda::thread_scope_system> flag = 0;
__global__ void producer() { flag.store(1); }
int main() {
    cudaHostRegister(&flag, sizeof(flag));
    producer<<<1,1>>>();
    while (flag.load() == 0);
    return cudaDeviceSynchronize();
}
```

```cpp
// 示例：Execution.Model.API.3
// 允许的结果：最终，没有线程取得进展。
// 依据：与 Example.Model.API.2 相同，再加一条：单次 CUDA 查询 API 调用不保证
// 设备线程最终启动，只有重复的 CUDA 查询 API 调用才保证（见 Execution.Model.API.4）。

cuda::atomic<int, cuda::thread_scope_system> flag = 0;
__global__ void producer() { flag.store(1); }
int main() {
     cudaHostRegister(&flag, sizeof(flag));
     producer<<<1,1>>>();
     (void)cudaStreamQuery(0);
     while (flag.load() == 0);
     return cudaDeviceSynchronize();
}
```

```cpp
// 示例：Execution.Model.API.4
// 结果：终止。
// 依据：与 Execution.Model.API.3 相同，但本示例在标志自旋循环中重复调用
// CUDA 查询 API，这保证了设备线程最终取得进展。

cuda::atomic<int, cuda::thread_scope_system> flag = 0;
__global__ void producer() { flag.store(1); }
int main() {
     cudaHostRegister(&flag, sizeof(flag));
     producer<<<1,1>>>();
     while (flag.load() == 0) {
         (void)cudaStreamQuery(0);
     }
     return cudaDeviceSynchronize();
}
```

### 5.8.3.1 依赖关系

设备线程在它的所有依赖关系完成之前不得启动。

> 注：阻止设备线程开始取得进展的依赖关系可以例如通过 CUDA 流命令创建。这些依赖可能包括对 CUDA 事件、CUDA 核函数等完成的依赖。——注结束

依赖关系带来的 CUDA API 前向推进保证的示例：

```cpp
// 示例：Execution.Model.Stream.0
// 允许的结果：最终，没有线程取得进展。
// 依据：虽然 CUDA 保证有一个设备线程取得进展，但由于 `first` 和 `second`
// 之间没有依赖关系，它不保证是哪个线程；
// 因此它总是可以选中 `second` 的设备线程，该线程就永远无法从自旋循环中解除阻塞。
// 也就是说，`second` 可能饿死 `first`。

cuda::atomic<int, cuda::thread_scope_system> flag = 0;
__global__ void first() { flag.store(1, cuda::memory_order_relaxed); }
__global__ void second() { while(flag.load(cuda::memory_order_relaxed) == 0) {} }

int main() {
     cudaHostRegister(&flag, sizeof(flag));
     cudaStream_t s0, s1;
     cudaStreamCreate(&s0);
     cudaStreamCreate(&s1);
     first<<<1,1,0,s0>>>();
     second<<<1,1,0,s1>>>();
     return cudaDeviceSynchronize();
}
```

```cpp
// 示例：Execution.Model.Stream.1
// 结果：终止。
// 依据：与 Execution.Model.Stream.0 相同，但本示例中 `first` 和 `second` 之间
// 有流依赖关系，这要求 CUDA 按顺序运行这些网格。

cuda::atomic<int, cuda::thread_scope_system> flag = 0;
__global__ void first() { flag.store(1, cuda::memory_order_relaxed); }
__global__ void second() { while(flag.load(cuda::memory_order_relaxed) == 0) {} }

int main() {
     cudaHostRegister(&flag, sizeof(flag));
     cudaStream_t s0;
     cudaStreamCreate(&s0);
     first<<<1,1,0,s0>>>();
     second<<<1,1,0,s0>>>();
     return cudaDeviceSynchronize();
}
```
