# 2.4 编写分块（tile）核函数

CUDA Tile 提供了一种不同于前面章节所述单指令多线程（SIMT）模型的 GPU 核函数编写方式。分块编程允许程序员以不同的方式表达并行性，把最低层次的并行留给编译器和内置操作去处理。这样一来，分块提供了一种更简单的方式来使用 NVIDIA GPU 上最新的性能特性，例如张量内存加速器（TMA）单元和 Tensor Core。

- CUDA Tile 编程在 Python 中可通过 cuTile Python 包 `cuda.tile` 使用。
- CUDA Tile C++ 自 CUDA Toolkit 13.3 起可用。

分块核函数周围的应用代码——例如分配设备端内存、在主机端与设备端之间传输数据、安排核函数启动顺序——与前面章节中为 SIMT 核函数描述的完全相同。分块核函数操作的是通过标准 CUDA API 分配的全局内存，其结果也以相同方式拷贝回主机端。唯一改变的是程序员在核函数内部编写的代码。

在 SIMT 核函数中，程序员以单个线程为单位思考：计算全局线程索引、加载该线程的元素、对它们执行操作、再存储结果。在分块核函数中，程序员以整个线程块为单位思考：加载一块包含许多元素的分块（tile）、对整个分块执行操作、再存储结果。编译器负责把分块操作映射到每个线程块的硬件线程上，而这项工作在 SIMT 编程中由程序员显式处理。

本章只关注这个差异：如何编写核函数入口点及其中的分块操作。每个编程模式都同时用 CuTile Python（`cuda.tile`）和 CUDA Tile C++（`cuda::tiles`）演示，二者共享同一个编译器后端（CUDA Tile IR），因而执行语义也相同。

按惯例，分块 API 在两种语言中都别名为 `ct`：

- Python 中为 `import cuda.tile as ct`
- C++ 中为 `namespace ct = cuda::tiles`

在 Python 中，分块 API 位于 `cuda.tiles` 模块中，按上面的方式导入。

在 C++ 中，分块 API 位于 `cuda::tiles` 命名空间，由 `cuda_tile.h` 头文件提供。

```cpp
#include "cuda_tile.h"
namespace ct = cuda::tiles;
```

下面代码片段中的 `ct.` / `ct::` 前缀指的是分块 API，无论你看的是哪种语言。

## 2.4.1 核函数与函数声明

分块核函数（tile kernel）是 GPU 入口点，在启动网格中的每个线程块上执行一次。分块函数（tile function）可以从分块核函数或另一个分块函数中调用，但它本身不是入口点。与 SIMT 核函数一样，分块核函数不能从主机端代码中直接调用，必须通过启动（launch）来执行。

在 CUDA Tile C++ 中：

- `__tile_global__` 是 `__global__` 的分块对应物，标记一个分块核函数入口点。
- `__tile__` 是 `__device__` 的分块对应物，表示该函数应编译为 GPU 代码，并可从其他 `__tile__` 或 `__tile_global__` 函数中调用。

数组和标量参数的传递方式与 SIMT 核函数相同。分块代码与 SIMT 代码可以共存：单个 `.cu` 文件可以同时定义 `__tile_global__` 和 `__global__` 核函数，单个主机端程序也可以同时启动两种核函数。

> **注**
>
> 目前，`__tile__` 函数不能从 `__global__` 或 `__device__` 函数中调用。同样，`__device__` 函数也不能从 `__tile_global__` 或 `__tile__` 函数中调用。该限制可能在未来的 CUDA 版本中解除。

在 cuTile Python 中：

- `@ct.kernel` 装饰器把一个函数标记为分块核函数入口点。
- `@ct.function` 装饰器把一个函数标记为可从分块核函数或另一个分块函数中调用的函数。

实际上，任何从核函数中调用的函数都会自动编译为分块代码，因此 `@ct.function` 装饰器是可选的。数组参数接受任何驻留在设备端、暴露 DLPack 或 CUDA Array Interface 的数组，例如 PyTorch 张量和 CuPy 数组。标量参数直接传递。

C++

```cpp
#include "cuda_tile.h"

// 分块核函数入口点。不能直接调用；必须启动。
__tile_global__ void my_kernel(float* a, float* b, float* c) {
    ...
}

// 分块函数。可从分块核函数和分块函数中调用。
__tile__ float helper(float x, float y) {
    return x + y;
}
```

Python

```python
import cuda.tile as ct

# 分块核函数入口点。不能直接调用；必须启动。
@ct.kernel
def my_kernel(a, b, c):
    ...

# 分块函数。可从分块核函数和分块函数中调用。
# @ct.function 是可选的，任何从分块代码中调用的函数
# 都会自动编译为分块代码。
@ct.function
def helper(x, y):
    return x + y
```

## 2.4.2 启动核函数

分块核函数在分块线程块（tile block）组成的网格上启动，就像 SIMT 核函数在线程块组成的网格上启动一样。程序员指定网格形状，最多三维。从程序员的角度看，每个分块线程块由单个逻辑线程执行。线程块内部的并行性由编译器管理。

在 C++ 中，分块核函数复用 SIMT 中熟悉的三重尖括号启动语法。第一个尖括号参数是网格形状（分块线程块的数量），第二个是 SIMT 中每线程块的线程数；对于分块核函数，线程数由编译器内部决定，第二个参数必须为 1。分块核函数本身也是普通的 CUDA 核函数，因此可以通过运行时的现有 API `cudaLaunchKernel` 和 `cudaLaunchKernelEx` 启动，配置同为 grid、1。当需要把分块核函数集成到已通过这些 API 驱动启动的现有代码库中时，这很有用。

在 Python 中，`ct.launch` 接受四个位置参数：一个 CUDA 流（stream）、一个指定各维度分块线程块数量的网格元组、核函数对象、以及一个核函数参数元组。

C++

```cpp
my_kernel<<<dim3(num_blocks_x, num_blocks_y), 1>>>(a, b, c);  // 第二个参数必须为 1
```

Python

```python
import torch

stream = torch.cuda.current_stream()     # CUDA 流对象
grid = (num_blocks_x, num_blocks_y, 1)   # 分块线程块网格 (x, y, z)
ct.launch(stream, grid, my_kernel, (a, b, c))
```

### 2.4.2.1 网格尺寸设定模式

一个常见的模式是启动足够多的线程块以覆盖整个数组，包括在某个或某些维度上可能超出数组大小的最后一个线程块。

C++

```cpp
int num_blocks = (N + tile_size - 1) / tile_size;  // 向上取整除法 -> 覆盖尾部不完整的分块

kernel<<<num_blocks, 1>>>(in, out, N);
```

Python

```python
import math

grid = (math.ceil(N / TILE),)   # 向上取整除法 -> 覆盖尾部不完整的分块
ct.launch(stream, grid, my_kernel, (arr_in, arr_out, TILE))
```

当数组大小不能被分块大小整除时如何处理，见第 2.4.6 节各小节的讨论。

## 2.4.3 查询线程块位置

每个线程块需要知道自己在网格中的位置，以确定处理数据的哪一部分。在 SIMT 中，程序员结合 `blockIdx` 和 `threadIdx` 计算全局线程索引。在分块代码中，只需要线程块索引。线程块内部所有线程级别的索引都由编译器处理。

在 C++ 中，`ct::bid()` 返回一个 `uint3`，包含所有三个维度的线程块索引。`ct::num_blocks()` 返回一个 `dim3`，包含各维度的线程块总数（由核函数启动参数决定）。各分量通过 `.x`、`.y`、`.z` 访问。

在 Python 中，`ct.bid(axis)` 返回当前线程块沿给定轴（0、1 或 2）的索引，为 int32 标量。`ct.num_blocks(axis)` 返回沿该轴的线程块总数——可用于边界检查和循环计数。

C++

```cpp
#include "cuda_tile.h"

__tile_global__ void my_kernel(float* a, float* b, float* c) {
    namespace ct = cuda::tiles;
    int bid_x = ct::bid().x;          // 沿 .x 的线程块索引
    int bid_y = ct::bid().y;          // 沿 .y 的线程块索引
    int num_x = ct::num_blocks().x;   // 沿 .x 的线程块总数
}
```

Python

```python
@ct.kernel
def my_kernel(a, b, c):
    bid_x = ct.bid(0)                    # 沿轴 0 的线程块索引
    bid_y = ct.bid(1)                    # 沿轴 1 的线程块索引
    num_x = ct.num_blocks(0)             # 沿轴 0 的线程块总数
```

## 2.4.4 创建分块

确定了线程块的身份之后，下一个问题是分块核函数到底操作什么对象。那就是分块（tile）：一个固定大小、形状与元素类型在编译期已知的标量元素多维数组。分块的每个维度必须是 2 的幂。分块具有值语义，这意味着拷贝分块会拷贝它的元素，两个副本完全独立。尽管如此，拷贝是廉价的，因为编译器控制分块在硬件内部的表示方式。程序员不需要为分块分配或释放内存。

在实践中，分块要么通过从数组加载数据创建（见分块空间加载与存储），要么使用工厂函数创建——工厂函数生成按指定模式填充的分块。

在 C++ 中，分块类型是显式的：`ct::tile<T, ct::shape<dims...>>`，其中 `T` 是元素类型，`ct::shape<dims...>` 把各维度编码为模板参数（整数值是各轴在编译期的大小）。例如，`ct::tile<float, ct::shape<8>>` 是 8 个 float 的一维分块，`ct::tile<float, ct::shape<4, 4>>` 是 4×4 float 分块。因为形状是类型的一部分，所以它在编译期始终已知。

工厂函数以完整的分块类型（下面的 `Tile`）为模板参数：

- `ct::zeros<Tile>()` 和 `ct::ones<Tile>()`——填充为全 0 或全 1 的分块。
- `ct::full<Tile>(val)`——每个元素都为 val 的分块。
- `ct::iota<Tile>()`——包含 (0, 1, ..., N-1) 的分块，其中 N 是分块的大小。

本章的 C++ 示例使用 `using` 别名（例如 `using f32x4x4 = ct::tile<float, ct::shape<4, 4>>`），让分块类型在调用处保持可读。

在 Python 中，分块工厂函数的 `shape` 元组和 `dtype` 参数都是编译期值。Python 字面量（如 `(64, 64)` 和 `ct.float32`）天然满足这一点，也可以用下面 Python Constant[T] 一节所示的 Constant 注解核函数参数来提供。生成的分块暴露 `.shape`、`.dtype` 和 `.ndim` 属性，反映其编译期属性。

工厂函数有：

- `ct.zeros(shape, dtype)` 和 `ct.ones(shape, dtype)`——填充为全 0 或全 1 的分块。
- `ct.full(shape, fill_value, dtype)`——填充为任意常量值的分块。
- `ct.arange(size, dtype=...)`——包含 [0, 1, ..., size-1] 的一维分块。

C++

```cpp
#include "cuda_tile.h"

__tile__ void factories() {
    namespace ct = cuda::tiles;

       using i32x8   = ct::tile<int,   ct::shape<8>>;                       // 1-D: 8 ints
       using f32x4x4 = ct::tile<float, ct::shape<4, 4>>;                    // 2-D: 4x4 floats

       auto z      = ct::zeros<f32x4x4>();                    // 全 0
       auto o      = ct::ones<f32x4x4>();                     // 全 1
       auto filled = ct::full<f32x4x4>(3.14f);                // 全 3.14
       auto seq    = ct::iota<i32x8>();                       // {0, 1, 2, 3, 4, 5, 6, 7}
}
```

Python

```python
import cuda.tile as ct

@ct.function
def factories():
     zeros = ct.zeros((64, 64), dtype=ct.float32)                              # 64x64 tile of 0.0

     ones    = ct.ones((128,), dtype=ct.float16)                               # 128-element tile of 1.0

     filled = ct.full((32, 32), 3.14, dtype=ct.float32)                        # 32x32 tile of 3.14

     seq     = ct.arange(8, dtype=ct.int32)                                    # [0, 1, 2, 3, 4, 5, 6, 7]
```

## 2.4.5 编译期常量

分块编译器为分块形状、数据类型和其他结构参数的每种组合生成特化的机器代码。因此，影响所生成代码的值必须在编译期已知。也就是说，分块的形状和数据类型必须在编译期已知。“创建分块”一节用字面量指定分块形状和数据类型：`ct.zeros((64, 64), dtype=ct.float32)` 和 `ct::tile<int, ct::shape<8>>`。

形状也可以通过核函数接口以编译期已知的值传入，如下面各节所示。

### 2.4.5.1 Python Constant[T]

核函数参数上的 `ct.Constant[T]` 类型注解将其标记为常量嵌入（constant-embedded）。这意味着该参数在核函数内部的每次使用都表现得像把字面量直接写在该处一样。类型参数是可选的，不带类型参数的 `ct.Constant` 可嵌入任意类型的常量。`ct.Constant` 最常用于整数，如 `ct.Constant[int]`，作用于驱动分块形状和循环边界的参数。

Python

```python
import cuda.tile as ct

@ct.kernel
def my_kernel(TILE: ct.Constant[int]):
     # TILE 是常量嵌入的：TILE 出现的任何地方，编译器看到的
     # 都是它的字面量值（例如 128），并生成特化代码。这里 TILE
     # 驱动工厂构建的分块形状。
     zeros = ct.zeros((TILE,), dtype=ct.float32)
```

### 2.4.5.2 C++ integral_constant 与 _ic 字面量

在 CUDA Tile C++ 中，编译期值通过 `ct::integral_constant` 表达，这是一种数值编码在类型自身中的类型。来自 `ct::literals` 命名空间的 `_ic` 字面量提供了一种简洁的简写：`0_ic` 生成一个值为 `ct::integral_constant<0>` 的常量。

接受编译期值的 API 同时接受非类型模板参数（NTTP）形式和 `_ic` 字面量形式。例如，`ct::cat` 沿给定维度拼接两个分块，而该维度必须在编译期已知。下面两行以相同的编译期轴调用 `ct::cat`，区别仅在于编译期值写在了哪里：

C++

```cpp
#include "cuda_tile.h"

__tile__ void concat_demo() {
    namespace ct = cuda::tiles;
    using namespace ct::literals;

       using T = ct::tile<int, ct::shape<4, 8>>;
       T lhs = ct::full<T>(0);
       T rhs = ct::full<T>(1);

       auto a = ct::cat<0>(lhs, rhs);                // NTTP 形式
       auto b = ct::cat(lhs, rhs, 0_ic);             // _ic 形式
}
```

还有一个 `_ic` 字面量经常出现的地方。`ct::extents` 和 `ct::shape` 各有一个 NTTP 形式（例如 `ct::extents<std::uint32_t, 4, 8>`）和一个大括号形式。与 NTTP 形式不同，大括号形式接受运行时值，因此当一个或多个维度只在启动时才知道时就用它：编译期维度用 `_ic` 字面量，运行时维度用普通变量。“分块空间加载与存储”中讲的 `ct::tensor_span` 和 `ct::partition_view` 等分块空间 API 就用这种形式来包装这样的数组：

C++

```cpp
auto shape2d = ct::extents{8_ic, length};                 // 8 是编译期的；length 是运行时的
```

`_ic` 字面量是值形式 API 参数需要编译期值时统一的简写，比如 `ct::cat` 的维度，或 `extents`、`shape` 的分量。

## 2.4.6 加载与存储分块

如第 1.2.2.3.1 节首次介绍的，CUDA 分块编程模型中有两个关键的内存对象：分块和数组。数组是全局内存中所有分块核函数线程块可见的元素多维容器。分块也是元素多维容器，但只属于 CUDA 分块代码中的单个线程块。分块通常是数组元素的一个子集。本节讨论如何从数组加载数据到分块以在分块核函数中使用，以及如何把分块存回数组。

下面各节介绍两种加载和存储分块的方法：

- “分块空间加载与存储”介绍使用分块空间索引的加载和存储，其视图对象规定了数组元素到分块的可预测映射模式。
- “Gather 与 Scatter”介绍使用索引分块或指针分块的加载和存储，指出加载或存储时分块元素的源或目标分别是数组的哪个元素。

**性能提示**：在受支持的硬件上，分块空间加载可由编译器降至张量内存加速器（TMA）执行，比逐元素 gather 快得多。（C++ 方面，另见“C++ 性能提示”。）

程序员必须决定加载时越界元素取什么值。Python 中越界写默认被静默丢弃，C++ 中使用 masked 变体时也是如此。

### 2.4.6.1 分块空间加载与存储

对于分块空间加载，先创建一个视图对象，指定数组如何划分成分块大小区域组成的网格。这种映射称为分块空间（tile-space），分块核函数可以用分块空间索引一次加载或存储一个区域。

分块空间加载的核心是数组的分块视图（tiled view），它指定数组元素如何映射到指定大小的分块。图 19 所示的分块视图是一个划分视图（partition view），即一种分块空间：由指定大小的互不重叠、无间隙的分块组成。

> *图 19：二维数组的分块视图示例，其中数组被划分为 2×2 块组成的网格。数组维度可以不是分块大小的整数倍。*

> *图 19：划分视图的分块空间索引。一个形状为 (10, 16) 的二维数组被划分为形状为 (2, 4) 的分块，得到形状为 (5, 4) 的分块网格。每个单元格标出其分块空间索引 (i, j)。高亮区域在分块空间索引 (1, 2) 处，覆盖元素索引 (2, 8) 到 (3, 11)。*

当数组维度不能被分块整除时，跨过数组边界的分块（在某个或某些维度上）会被部分填充。程序员可以指定加载这些分块时的行为，见第 2.4.6.1.3 节介绍。

划分视图只是数组上可定义的多种分块空间之一。两种语言还提供另外两种：

- 固定形状、按步幅分隔的块，块之间可以留间隙或重叠。C++ 中写作 `ct::strided_view`；Python 中给 `Array.tiled_view` 传入 `traversal_steps` 参数。
- 沿一个维度由元素索引分块选出的块，用于“Gather 与 Scatter”中介绍的不规则访问模式。C++ 中写作 `ct::gather_scatter_view`；Python 中使用 `ct.load_advanced_indexing` 和 `ct.store_advanced_indexing`。

划分视图是本章演示的唯一分块空间，也是 `Array.tiled_view` 默认生成的。对于其他视图，见各语言的 API 参考（CUDA Tile C++ API Reference、cuTile Python tiled views 与 advanced indexing）。

#### 2.4.6.1.1 划分视图的加载与存储

结构化的分块空间加载是把数据在全局内存与分块之间搬运的首选方式。核函数先构建一个定义分块空间的视图对象，再按分块空间索引一次加载或存储一个分块。

在 C++ 中，划分视图分两步构建：

- `ct::tensor_span`——把原始指针与一个 `ct::extents` 配对，赋予指针多维结构。
- `ct::partition_view`——把 span 划分成固定大小分块的网格，并暴露 `.load(idx...)` / `.store(tile, idx...)` 方法，在分块空间坐标上操作。

在 Python 中，`Array.tiled_view(tile_shape)` 返回一个 `TiledView`，把数组划分成给定形状的分块。视图暴露 `.load(index)` / `.store(index, tile)` 方法，接受分块空间索引，与 C++ 的 `partition_view` 直接对应。

> **注**
>
> 本章的 C++ 示例代码用 `__restrict__` 注解指针参数，并在核函数体顶部附近调用 `ct::assume_aligned(ptr, 16_ic)`。这些是重要的性能注解，见第 2.4.12 节进一步说明。数字字面量上的 `_ic` 后缀（如 `128_ic`、`8_ic`）将其标记为编译期常量，如“编译期常量”一节所介绍。

C++

```cpp
__tile_global__ void vec_add(float* __restrict__ a, float* __restrict__ b,
                             float* __restrict__ out) {

     namespace ct = cuda::tiles;
     using namespace ct::literals;

       a   = ct::assume_aligned(a,   16_ic);
       b   = ct::assume_aligned(b,   16_ic);
       out = ct::assume_aligned(out, 16_ic);

       // 步骤 1：给每个原始指针附加一个形状。128_ic 标记 128 为编译期常量。
       auto aSpan = ct::tensor_span{a,    ct::extents{128_ic}};
       auto bSpan = ct::tensor_span{b,    ct::extents{128_ic}};
       auto oSpan = ct::tensor_span{out, ct::extents{128_ic}};

       // 步骤 2：把每个 span 划分成固定 8 元素分块的分块空间。
       auto aView = ct::partition_view{aSpan, ct::shape{8_ic}};
       auto bView = ct::partition_view{bSpan, ct::shape{8_ic}};
       auto oView = ct::partition_view{oSpan, ct::shape{8_ic}};

       int bx     = ct::bid().x;                          // 本线程块沿 .x 的分块空间索引
       auto aTile = aView.load(bx);                       // 取 a 的第 bx 个分块
       auto bTile = bView.load(bx);
       oView.store(aTile + bTile, bx);                    // 把分块写回 out 的第 bx 个位置
}
```

Python

```python
@ct.kernel
def vec_add(a, b, c, TILE: ct.Constant[int]):
    a_view = a.tiled_view((TILE,))
    b_view = b.tiled_view((TILE,))
    c_view = c.tiled_view((TILE,))

     bid = ct.bid(0)
     a_tile = a_view.load((bid,))
     b_tile = b_view.load((bid,))
     c_view.store((bid,), a_tile + b_tile)
```

#### 2.4.6.1.2 Python 单次调用加载与存储

Python 还额外提供一种单次调用形式：每次加载和存储时在调用中内联给出分块形状，不需要显式的视图对象。`ct.load(array, index, shape)` 以给定的分块形状在给定的分块空间索引处读取一个分块。`ct.store(array, index, tile)` 是对应的写入。

`ct.load` / `ct.store` 和 `Array.tiled_view` 表达的是相同的分块空间访问模式，区别在于分块形状写在哪里。用 `Array.tiled_view` 时，分块形状绑定在视图对象上一次完成。用 `ct.load` / `ct.store` 时，分块形状在每次调用时内联提供。当同一划分需要在多次加载和存储中复用时，推荐用 `tiled_view`；当单次加载用更简洁的写法更合适时，用 `ct.load` / `ct.store`。

Python

```python
@ct.kernel
def vec_add(a, b, c, TILE: ct.Constant[int]):
     bid = ct.bid(0)                                                     # 本线程块沿轴 0 的分块空间索引

     a_tile = ct.load(a, index=(bid,), shape=(TILE,))                    # (index, shape) = 取 a 的第 bid 个 TILE 大小的区域

     b_tile = ct.load(b, index=(bid,), shape=(TILE,))
     ct.store(c, index=(bid,), tile=a_tile + b_tile)                     # 把分块写回 c 的第 bid 个区域
```

#### 2.4.6.1.3 分块空间边界处理

在 C++ 中，`partition_view` 提供无掩码（unmasked）和带掩码（masked）两种变体：

- `.load(idx...)` / `.store(tile, idx...)` 假定分块完全在边界内。部分越界的访问是未定义行为。
- `.load_masked(idx...)` / `.store_masked(tile, idx...)` 可安全处理部分越界的边缘分块。
  - `.load_masked()` 默认用 0 填充越界位置；也可选择其他填充模式（如 float 分块用 NaN）。
  - `.store_masked()` 静默丢弃越界写。

当数组能被分块大小整除时，推荐用无掩码的加载和存储变体。当必须处理边界条件时，即使对完全填满的分块也可以用带掩码的变体。

这也是本指南中第一个数组维度为运行时值的 C++ 示例。`ct::extents{N}` 接受运行时维度，`ct::extents` 支持编译期（`_ic`）与运行时值的任意混合，因此 span 和划分视图可以包装大小只在核函数启动时才知道的数组。

在 Python 中，`ct.load` 接受 `padding_mode` 参数，控制越界元素取什么值。常用的两种模式是：

- `PaddingMode.UNDETERMINED`（默认）——越界元素的值由实现决定。分块仍会做边界检查，加载绝不会读取数组之外的内存；只有越界通道接收到的值是未指定的。这适用于越界通道从不会被读取的情形。
- `PaddingMode.ZERO`——越界元素填充为 0。

对于存储，`ct.store` 不需要 `padding_mode` 参数：默认它会把分块与数组做边界检查，静默丢弃对越界位置的写。同样的规则适用于 `tiled_view`，它在视图创建时固定其 `padding_mode`。

`ct.load` 和 `ct.store` 还接受 `check_bounds` 参数，默认为 `True`。`padding_mode` 决定越界通道含有什么值，`check_bounds` 则决定边界到底测不测试：`check_bounds=False` 时，超出数组的访问是未定义行为，可能读取或覆盖相邻内存。它是 Python 对应无掩码 C++ `.load()` / `.store()` 的写法，适用建议也相同。`TiledView.load` 和 `TiledView.store` 接受相同的关键字参数。

C++

```cpp
__tile_global__ void edge_safe(float* __restrict__ in, float* __restrict__
                               out, int N) {

     namespace ct = cuda::tiles;
     using namespace ct::literals;

       in   = ct::assume_aligned(in,         16_ic);

    // ct::extents{N} 用运行时维度；128_ic 仍是编译期的。
    auto inView = ct::partition_view{ct::tensor_span{in, ct::extents{N}},
                                     ct::shape{128_ic}};

    auto outView = ct::partition_view{ct::tensor_span{out, ct::extents{N}},
                                      ct::shape{128_ic}};

     int bx    = ct::bid().x;
     auto tile = inView.load_masked(bx);                  // 带掩码加载：越界通道默认为 0

     outView.store_masked(tile, bx);                      // 带掩码存储：越界写被静默丢弃
}
```

Python

```python
@ct.kernel
def edge_safe(arr_in, arr_out, TILE: ct.Constant[int]):
     bid = ct.bid(0)
     tile = ct.load(arr_in, index=(bid,), shape=(TILE,),
                     padding_mode=ct.PaddingMode.ZERO)   # 部分越界的边缘分块的越界通道变为 0

     ct.store(arr_out, index=(bid,), tile=tile)          # 越界写被静默丢弃
```

在 C++ 核函数内部，`.load_masked()` 和 `.store_masked()` 处理部分越界的边缘分块。在 Python 核函数内部，加载时的 `PaddingMode.ZERO` 确保部分越界的边缘分块被 0 填充，而 `ct.store` 以默认的边界检查静默丢弃超出数组边界的写。完整的填充模式、掩码选项和填充值见各语言的 API 参考（CUDA Tile C++ view padding、cuTile Python padding modes）。

从完全位于数组之外的分块加载或向其存储是未定义行为。这里讨论的边界处理只适用于在某个或某些维度上部分越界的分块。

### 2.4.6.2 Gather 与 Scatter

“分块空间加载与存储”中的分块空间加载使用划分视图，它定义了数组规则、块对齐的划分。当访问模式不规则或与数据相关时，例如查找表或置换，gather 和 scatter 操作允许分块从数组的非均匀、不连续元素加载，并向它们存储……通过任意索引或地址。

Gather 与 scatter 操作在 C++ 和 Python 中略有不同：

- Python 使用传入 `ct.gather()` / `ct.scatter()` 的整数索引分块，带内置边界检查。
- C++ 使用传入 `ct::load()` / `ct::store()` 的指针分块，带接受布尔掩码分块的 masked 变体 `ct::load_masked()` 和 `ct::store_masked()`，用于处理数组边界处的分块。

在 C++ 中，gather 和 scatter 的做法是构造一个指针分块，每个元素对应一个指针，再把指针分块传给 `ct::load()` 或 `ct::store()`。标量指针与整数分块之间的运算按元素进行，产生一个指针分块。这是 C++ 中构造 gather/scatter 索引分块的标准惯用法。

在 Python 中，`ct.gather` 加载索引分块中每个索引处的元素。边界检查默认开启：越界索引返回填充值（默认 0，可通过 `padding_value=` 配置），可用 `check_bounds=False` 禁用。`ct.scatter` 按索引逐个存储值；越界写被静默丢弃，`check_bounds=False` 在此同样适用。

C++

```cpp
__tile_global__ void vec_add_gather(int* __restrict__ a, int* __restrict__ b,
                                    int* __restrict__ out) {

     namespace ct = cuda::tiles;
     using namespace ct::literals;
     using i32x8 = ct::tile<int, ct::shape<8>>;

      a   = ct::assume_aligned(a,   16_ic);
      b   = ct::assume_aligned(b,   16_ic);
      out = ct::assume_aligned(out, 16_ic);

    int bx       = ct::bid().x;
    auto offsets = 8 * bx + ct::iota<i32x8>();                // 元素级偏移，每通道一个

      // 标量指针 + int 分块 = 指针分块（每个偏移一个指针）。
      auto aPtrs = a + offsets;
      auto bPtrs = b + offsets;

     auto aTile = ct::load(aPtrs);                            // gather：每个指针一次加载
     auto bTile = ct::load(bPtrs);
     ct::store(out + offsets, aTile + bTile);                 // scatter：每个指针一次存储
}
```

Python

```python
@ct.kernel
def vec_add_gather(a, b, c, TILE: ct.Constant[int]):
     bid = ct.bid(0)
     indices = bid * TILE + ct.arange(TILE, dtype=ct.int32)                  # 每通道一个元素索引

    a_tile = ct.gather(a, indices)                                           # 每通道加载 a[indices[i]]
    b_tile = ct.gather(b, indices)
    ct.scatter(c, indices, a_tile + b_tile)                                  # 把每个值按索引存入 c
```

#### 2.4.6.2.1 Gather 与 Scatter 的边界处理

“Gather 与 Scatter”中介绍的 gather/scatter 操作的边界处理遵循不同的规则。

在 Python 中，`ct.gather` 和 `ct.scatter` 默认是边界安全的。越界读取返回填充值（默认 0），越界写被静默丢弃。当能证明每个索引都在范围内时可以禁用边界检查；禁用后越界访问是未定义行为。可选的掩码和填充值旋钮见 API 参考（CUDA Tile C++ load operations、cuTile Python load/store operations）。

在 C++ 中，边界检查不是自动的。程序员构造一个布尔掩码（例如把偏移与数组长度比较），再传给 `ct::load_masked` 或 `ct::store_masked`：

C++

```cpp
__tile_global__ void gather_safe(int* __restrict__ arr, int* __restrict__ out,
                                 int N) {

     namespace ct = cuda::tiles;
     using namespace ct::literals;
     using i32x8 = ct::tile<int, ct::shape<8>>;

      arr = ct::assume_aligned(arr, 16_ic);
      out = ct::assume_aligned(out, 16_ic);

    int bx       = ct::bid().x;
    auto offsets = 8 * bx + ct::iota<i32x8>();                  // 元素级偏移，每通道一个

    auto mask    = offsets < N;                                 // 布尔分块：偏移在界内处为 true

     auto ptrs = arr + offsets;                   // 指针分块，每个偏移一个指针
     auto tile = ct::load_masked(ptrs, mask, 0); // 带掩码的通道得到填充值 0

     ct::store_masked(out + offsets, tile, mask); // 存储时跳过带掩码的通道
}
```

## 2.4.7 控制流

从程序员的角度看，分块核函数在每个线程块上走单条控制流路径。条件和循环边界中的标量值驱动控制流，循环体内的分块操作由编译器分发到各硬件线程。

并非所有控制流结构都受支持。例如，在分块代码中不允许从循环内部返回。完整的限制列表见各语言的 API 参考（CUDA Tile C++ general principles、cuTile Python control flow）。

### 2.4.7.1 循环

一个常见模式是遍历数组的分块，逐个处理。

在 C++ 中，`ct::irange` 是一个前向范围，表示从下界开始、到上界（不含）结束、按可选步长递增的整数序列。用 `ct::irange` 为编译器提供了关于迭代边界的结构化信息，可用于更好地优化生成的代码。要让优化生效，循环变量必须通过对 `ct::irange` 的范围 for 表达式绑定。

在 Python 中，内置的 `range()`、`for`、`while` 和嵌套循环在分块代码中都受支持。步长参数必须严格为正；不支持负步长范围。

下面的单线程块核函数对一维数组的所有分块求和：

C++

```cpp
__tile_global__ void tile_sum(float* __restrict__ arr, float* __restrict__
                              out, int num_tiles) {

     namespace ct = cuda::tiles;
     using namespace ct::literals;
     using f32x8 = ct::tile<float, ct::shape<8>>;

       arr = ct::assume_aligned(arr, 16_ic);
       out = ct::assume_aligned(out, 16_ic);

       auto inView    = ct::partition_view{ct::tensor_span{arr, ct::extents{8 *
                                          num_tiles}},
                                         ct::shape{8_ic}};
       auto outView = ct::partition_view{ct::tensor_span{out, ct::extents{8_ic}},
                                         ct::shape{8_ic}};

     auto acc = ct::full<f32x8>(0.0f);
     // 对 ct::irange 的范围 for 给编译器提供结构化的迭代边界。

     for (auto k : ct::irange(0, num_tiles)) {
         auto tile = inView.load(k);
         acc = acc + tile;                                // 把第 k 个分块累加到 acc

     }
     outView.store(acc, 0);                               // 把最终结果写为 out 的第 0 个分块
}
```

Python

```python
@ct.kernel
def tile_sum(arr, out, TILE: ct.Constant[int], N_TILES: ct.Constant[int]):
     # 预期网格：(1,) -- 单个线程块对 arr 的所有分块求和。
     acc = ct.zeros((TILE,), dtype=ct.float32)
     for k in range(N_TILES):                             # range() 在分块代码中原生可用
         tile = ct.load(arr, index=(k,), shape=(TILE,))
         acc = acc + tile                                              # 把第 k 个分块累加到 acc
     ct.store(out, index=(0,), tile=acc)                               # 把最终结果写为 out 的第 0 个分块
```

### 2.4.7.2 条件语句

标准的 if/else 条件语句正常工作。因为每个线程块走单条控制流路径，分块核函数不涉及线程束内的分支分化考量。

C++

```cpp
__tile_global__ void conditional_load(float* __restrict__ arr, float* __
                                      restrict__ out, int N) {

     namespace ct = cuda::tiles;
     using namespace ct::literals;
     using f32x8 = ct::tile<float, ct::shape<8>>;

      arr = ct::assume_aligned(arr, 16_ic);
      out = ct::assume_aligned(out, 16_ic);

    auto inView = ct::partition_view{ct::tensor_span{arr, ct::extents{N}},
                                     ct::shape{8_ic}};
    auto outView = ct::partition_view{ct::tensor_span{out, ct::extents{N}},
                                      ct::shape{8_ic}};

      int bx   = ct::bid().x;
      int nb_x = ct::num_blocks().x;

     auto tile = ct::full<f32x8>(0.0f);     // 最后一个线程块分支的默认值
     // 标量条件 -> 每个线程块一条控制流路径；无需考虑分支分化。

     if (bx < nb_x - 1) {
         tile = inView.load(bx);            // 除最后一个外的所有线程块
     }
     outView.store_masked(tile, bx);        // 带掩码，处理可能部分越界的尾部分块
}
```

Python

```python
@ct.kernel
def conditional_load(arr, out, TILE: ct.Constant[int]):
     bid = ct.bid(0)
     # 标量条件 -> 每个线程块一条控制流路径；无需考虑分支分化。

     if bid < ct.num_blocks(0) - 1:
         tile = ct.load(arr, index=(bid,), shape=(TILE,))     # 除最后一个外的所有线程块
     else:
         tile = ct.zeros((TILE,), dtype=ct.float32)                               # 最后一个线程块：输出全 0

     ct.store(out, index=(bid,), tile=tile)
```

## 2.4.8 逐元素算术与广播

分块支持标准的逐元素算术。当两个操作数形状兼容但不同时，执行操作前先把较小的广播到相同形状。

### 2.4.8.1 广播

广播遵循 NumPy 语义：标量在整个分块上复制，单例维度（长度 1）拉伸以匹配另一操作数的对应维度，低秩操作数通过把缺失的前导维度视为单例维度、对齐到高秩操作数的后部维度。若两个对应维度都是非单例且不相等，则该操作是不合法的。

下面的例子在一个加法中同时演示了单例拉伸和秩提升：形状 8x2 的秩 2 分块先秩提升为 1x8x2，再与形状 4x1x2 的秩 3 分块广播到共同形状 4x8x2。

C++

```cpp
auto x = ct::iota<ct::tile<int, ct::shape<8, 2>>>();                          // 8x2   (rank 2)
auto y = ct::iota<ct::tile<int, ct::shape<4, 1, 2>>>();                       // 4x1x2 (rank 3)
auto z = x + y;                                                               // x 提升为 1x8x2，再广播到 4x8x2
```

Python

```python
x = ct.full((8, 2),    3, dtype=ct.int32)                   # 8x2   (rank 2)
y = ct.full((4, 1, 2), 5, dtype=ct.int32)                   # 4x1x2 (rank 3)
z = x + y                                                    # x 提升为 1x8x2，再广播到 4x8x2
```

### 2.4.8.2 算术运算符

所有受支持的算术运算符都按元素作用于分块，产生广播形状的新分块。标量与分块组合时被广播到每个元素。操作数类型不同时，优先保留信息更多的类型：

- 分块与分块组合：结果为精度或范围更大类型的分块。例如：
  - int + float 得到 float
  - int16 + int32 得到 int32
- 标量与分块组合：当标量的类型能精确表示成分块的元素类型时（例如整数值 2 与 int 分块组合，或 2.0f 与 float 分块组合），按分块的元素类型运算。当标量必须窄化才能装进分块的元素类型时（例如字面量 2.5 与 int 分块组合），两种语言处理不同：
  - Python 把结果提升到能同时容纳两者的类型
  - C++ 把该表达式判定为不合法

下面的代码片段演示标量-分块分歧的情形：

C++

```cpp
using i32x8 = ct::tile<int, ct::shape<8>>;
i32x8 x = ct::full<i32x8>(3);

x + 2;             // OK - int 字面量匹配 int 分块元素类型
x + 2.5;           // 不合法 - 2.5 会窄化为 int
```

Python

```python
x = ct.full((8,), 3, dtype=ct.int32)

x + 2                 # int32 - int 字面量匹配 int32 分块 dtype
x + 2.5               # float32 - 结果提升到能容纳两者
```

实践中，能写成分块元素类型的标量字面量就尽量写成该类型，想要不同精度时显式转换。当操作数是加载的分块时，在核函数内部适用同样的规则：

C++

```cpp
__tile_global__ void elementwise(float* __restrict__ a, float* __restrict__ b,
                                 float* __restrict__ out, int N) {

     namespace ct = cuda::tiles;
     using namespace ct::literals;

       a   = ct::assume_aligned(a,   16_ic);
       b   = ct::assume_aligned(b,   16_ic);
       out = ct::assume_aligned(out, 16_ic);

    auto aView = ct::partition_view{ct::tensor_span{a,   ct::extents{N}},
                                    ct::shape{8_ic}};
    auto bView = ct::partition_view{ct::tensor_span{b,   ct::extents{N}},
                                    ct::shape{8_ic}};
    auto cView = ct::partition_view{ct::tensor_span{out, ct::extents{N}},
                                    ct::shape{8_ic}};

    int bx = ct::bid().x;
    auto x = aView.load(bx);
    auto y = bView.load(bx);
    // 2.0f 匹配 float 分块的元素类型，因此不需要窄化转换。
    // 标量广播到每个元素；然后 + 按元素执行。

     auto z = 2.0f * x + y;
     cView.store(z, bx);
}
```

Python

```python
@ct.kernel
def elementwise(a, b, c, TILE: ct.Constant[int]):
     bid = ct.bid(0)
     x = ct.load(a, index=(bid,), shape=(TILE,))
     y = ct.load(b, index=(bid,), shape=(TILE,))
     # 2.0 是松类型的 float 常量；与 float 分块一起用时，结果仍是 float。
     # 标量先广播到分块的每个元素，然后 + 按元素执行。

     z = 2.0 * x + y
     ct.store(c, index=(bid,), tile=z)
```

当需要显式控制舍入模式或次正规数处理时，CUDA Tile API 提供显式暴露这些选择的数学函数：逐元素算术（如 `ct.add`、`ct::add`）和超越函数（如 exp、tanh）都有。

## 2.4.9 分块原语

工厂函数（“创建分块”）、加载与存储（“分块空间加载与存储”）、逐元素算术（“逐元素算术与广播”）都是分块原语，即语言本身的操作。程序员以分块粒度编写它们，编译器把它们映射到硬件上，包括可用的 Tensor Core。本节介绍 CUDA 分块中可用的其他原语。

### 2.4.9.1 矩阵乘法

两个分块的矩阵乘法是实现两个数组间矩阵乘法的基本操作。CUDA Tile 提供两种形式的分块间矩阵乘法：纯矩阵乘法（matmul）`a @ b`，和矩阵乘累加（mma）`a @ b + acc`。在 mma 中，累加器把部分积从一个 K 分块带到下一个 K 分块。这在分块矩阵乘法的内层循环中很有用。matmul 和 mma 都支持二维矩阵乘法和三维批矩阵乘法，也支持操作数与累加器混用数据类型（精度）。秩和元素类型的约束见各操作的 API 参考（CUDA Tile C++ matrix multiplication、cuTile Python matmul）。

下面的核函数中使用了一个常见模式：无论输入精度如何都用 FP32 累加，存储时转换为输出元素类型。Python 中是给 `ct.mma(a, b, acc)` 传入 FP32 类型的 acc；C++ 中是 `ct::mma(a, b, acc)` 传入显式的 FP32 累加器类型。K 循环迭代 `ceil(K / tk)` 次，以覆盖 A 的右边缘和 B 的下边缘；不完整的 K 分块在加载时用 0 填充（Python 中 `PaddingMode.ZERO`，C++ 中 `.load_masked()`），C 侧不完整的 M/N 边缘分块则靠存储侧的越界丢弃处理（Python 中 `ct.store`，C++ 中 `.store_masked()`）。

C++

```cpp
__tile_global__ void gemm(const __half* __restrict__ A, const __half* __
                          restrict__ B, float* __restrict__ C,
                          std::size_t M, std::size_t K, std::size_t N) {
     namespace ct = cuda::tiles;
     using namespace ct::literals;
     using f32_acc = ct::tile<float, ct::shape<32, 32>>;

      A = ct::assume_aligned(A, 16_ic);
      B = ct::assume_aligned(B, 16_ic);
      C = ct::assume_aligned(C, 16_ic);

      constexpr auto tm = 32_ic;
      constexpr auto tn = 32_ic;
      constexpr auto tk = 16_ic;

    auto aView = ct::partition_view{ct::tensor_span{A, ct::extents{M, K}},
                                    ct::shape{tm, tk}};
    auto bView = ct::partition_view{ct::tensor_span{B, ct::extents{K, N}},
                                    ct::shape{tk, tn}};
    auto cView = ct::partition_view{ct::tensor_span{C, ct::extents{M, N}},
                                    ct::shape{tm, tn}};

      auto [bx, by, bz] = ct::bid();
      auto acc = ct::full<f32_acc>(0.0f);                 // FP32 累加器

     std::size_t num_k = (K + tk - 1) / tk;
     for (auto k : ct::irange(std::size_t{0}, num_k)) {
         acc = ct::mma(aView.load_masked(bx, k),          // 对不完整的 K 分块补 0
                       bView.load_masked(k, by),
                       acc);                              // acc += a @ b
     }
     cView.store_masked(acc, bx, by);                     // 丢弃越界的边缘通道
}
```

Python

```python
@ct.kernel
def gemm(A, B, C,
         tm: ct.Constant[int], tn: ct.Constant[int], tk: ct.Constant[int]):
    bx, by = ct.bid(0), ct.bid(1)
    num_k = ct.num_tiles(A, axis=1, shape=(tm, tk))     # K 分块的数量

    acc = ct.full((tm, tn), 0, dtype=ct.float32)          # FP32 累加器
    for k in range(num_k):
        a = ct.load(A, index=(bx, k), shape=(tm, tk),
                    padding_mode=ct.PaddingMode.ZERO)     # 对不完整的 K 分块补 0
        b = ct.load(B, index=(k, by), shape=(tk, tn),
                    padding_mode=ct.PaddingMode.ZERO)
        acc = ct.mma(a, b, acc)                           # acc += a @ b
    ct.store(C, index=(bx, by), tile=acc.astype(C.dtype))                 # 转换类型后存储
```

### 2.4.9.2 归约与扫描

归约是把分块折叠为标量或一行标量的工具。计算 softmax 的分母、layer norm 的均值和方差、attention 打分中的最大值，都涉及归约操作。

有一个点值得先记住：结果的形状。Python 默认丢弃被归约的轴（传入 `keepdims=True` 可将其保留为长度 1）；C++ 总是保留它，保持分块的秩不变。下面两段代码都沿轴 1 对一个 2x4 分块归约；输出形状是肉眼可见的差异。

C++

```cpp
using namespace ct::literals;
using i32x2x4 = ct::tile<int, ct::shape<2, 4>>;

auto x = ct::iota<i32x2x4>();                                         // [[0,1,2,3],[4,5,6,7]]
auto row_sums = ct::sum(x, 1_ic);                                     // 形状 (2, 1) - 轴被保留

// row_sums == [[6], [22]]
```

Python

```python
x    = ct.arange(8, dtype=ct.int32).reshape((2, 4))                   # [[0,1,2,3],[4,5,6,7]]
s    = ct.sum(x, axis=1)                                              # 形状 (2,)    - 轴被丢弃

s_k = ct.sum(x, axis=1, keepdims=True)                                # 形状 (2, 1)        - 轴被保留

# s == [6, 22]; s_k == [[6], [22]]
```

扫描是其逐项累积的对应操作，沿一个轴产生累积结果。例如，前缀和（cumsum）产生的输出与输入同维，沿指定轴给定索引处的值是到该索引（含）为止所有元素的和。两种语言的完整操作集合见 API 参考（CUDA Tile C++ reductions and scans、cuTile Python reductions and scans）。

### 2.4.9.3 转置与置换

两个相关的原语在不触及数据的情况下重排分块的轴：transpose 交换前两轴，permute 做任意重排。凡是分块的逻辑布局需要在操作之间改变的地方都会用到它们，例如物化 matmul 操作数的转置、在 attention 块中交换行列，或广播前对齐各轴。

在 Python 中，`ct.transpose(x)` 对秩 2 分块交换其两轴；对更高秩的分块接受显式的 `axis0` / `axis1` 参数。`ct.permute(x, axes)` 接受一个轴索引元组。在 C++ 中，`ct::transpose(x)` 交换前两维（后部维度保持不变），`ct::permute(x, map)` 接受一个描述新顺序的 `ct::dimension_map`。

C++

```cpp
using namespace ct::literals;
using t2d = ct::tile<int, ct::shape<2, 4>>;
using t3d = ct::tile<int, ct::shape<2, 2, 2>>;

auto tx = ct::iota<t2d>();
auto ty = ct::transpose(tx);                                                            // 形状 (4, 2)

auto tz = ct::iota<t3d>();
auto tw = ct::permute(tz, ct::dimension_map{2_ic, 0_ic, 1_ic});                         // 轴 (0,1,2) -> (2,0,1)
```

Python

```python
tx = ct.arange(8, dtype=ct.int32).reshape((2, 4))
ty = ct.transpose(tx)                                                                   # 形状 (4, 2)

tz = ct.arange(8, dtype=ct.int32).reshape((2, 2, 2))
tw = ct.permute(tz, (2, 0, 1))                                                          # 轴 (0,1,2) -> (2,0,1)
```

### 2.4.9.4 逐元素选择

逐元素选择是条件语句的分块形式：给定一个布尔分块和两个操作数分块，根据对应的布尔值从二者中挑选每个输出元素。条件会被广播到操作数形状；操作数类型必须兼容（两种语言的确切规则见 API 参考：CUDA Tile C++ select、cuTile Python selection）。Python 中写作 `ct.where(cond, x, y)`；C++ 中写作 `ct::select(cond, lhs, rhs)`。

C++

```cpp
using namespace ct::literals;
auto cond = ct::iota<ct::tile<int, ct::shape<4>>>() < 2;    // {T, T, F, F}
auto t    = ct::full<ct::tile<float, ct::shape<4>>>( 1.0f);
auto f    = ct::full<ct::tile<float, ct::shape<4>>>(-1.0f);
auto r    = ct::select(cond, t, f);                         // {1, 1, -1, -1}
```

Python

```python
cond    = ct.arange(4, dtype=ct.int32) < 2                                     # [T, T, F, F]
x_true = ct.full((4,), 1.0, dtype=ct.float32)
x_false = ct.full((4,), -1.0, dtype=ct.float32)
result = ct.where(cond, x_true, x_false)                                       # [1, 1, -1, -1]
```

## 2.4.10 原子内存操作

在分块代码中有两种情形需要用到内存原子操作：

- 跨线程块竞争（cross-block contention）：每个线程块产生一个部分结果，用原子操作与全局内存位置中其他线程块的部分结果合并。
- 线程块内竞争（intra-block contention）：分块的多个元素写到内存中同一位置。

分块上的原子操作对分块的每个元素执行一次原子更新。逐元素的操作是原子的，但整个调用不是。逐元素原子操作的顺序是未指定的。

在 Python 中，原子操作用数组索引寻址目标，约定与 `ct.gather` 和 `ct.scatter` 相同。可选参数控制边界检查、内存顺序和线程作用域。默认值（开启边界检查、ACQ_REL、设备作用域）让普通调用只需传入数组、索引和更新值。`TiledView` 也把归约式原子操作作为实例方法暴露，命名带 `atomic_store_` 前缀（例如 `TiledView.atomic_store_add(index, update)`）；它们按分块空间索引寻址目标，不返回值，并降为 PTX 中的原子归约。不需要旧值时，`TiledView` 形式性能更好，优先使用。

在 C++ 中，原子操作接受指针和对应的值：单个位置用原始指针和标量，多个位置用指针分块和值分块。内存顺序是调用处的编译期类型标签，如 `ct::memory_order_relaxed_t{}`。线程作用域是同等形式的类型标签，省略时默认为系统级可见。

`ct::partition_view` 和 `ct::strided_view` 还把归约原子操作（`atomic_add`、`atomic_sub`、`atomic_and`、`atomic_or`、`atomic_xor`、`atomic_max`、`atomic_min`）作为成员函数暴露。这些函数按分块空间索引而非指针寻址目标，参数顺序与 `.store()` 一样——值分块在前、索引在后。与返回内存中旧值的自由函数不同，它们不返回任何东西。与 Python 一样，不需要旧值时优先用它们：成员形式降为硬件归约，而指针分块形式降为每个元素一次原子操作。`ct::gather_scatter_view` 不提供这些成员函数。

### 2.4.10.1 跨线程块竞争

在下面的代码示例中，跨线程块竞争之所以发生，是因为不同的线程块写到同一内存位置 `out`。不用原子操作的话，并行运行的线程块会产生错误的结果。本例使用设备线程作用域（C++ 中为 `ct::thread_scope_device_t{}`，Python 中线程作用域默认为设备作用域），因为内存操作的结果必须对设备上运行的所有线程块可见。Python 核函数使用 `TiledView.atomic_store_add`，因为每个线程块的部分和被累加到 `out[0]` 后就直接丢弃。

C++

```cpp
__tile_global__ void block_sum(int* __restrict__ arr, int* __restrict__ out,
                               std::size_t N) {

     namespace ct = cuda::tiles;
     using namespace ct::literals;
     constexpr auto TILE = 16_ic;

      arr = ct::assume_aligned(arr, 16_ic);
      out = ct::assume_aligned(out, 16_ic);

    auto aView = ct::partition_view{ct::tensor_span{arr, ct::extents{N}},
                                    ct::shape{TILE}};
    int bid = ct::bid().x;
    auto tile    = aView.load_masked(bid);        // 部分越界的尾部分块 -> 越界通道默认为 0
    auto partial = ct::sum(tile, 0_ic);           // 归约为 1 元素分块

     ct::atomic_add(out, (int)partial,                           // 把标量累加到 out[0]
                    ct::memory_order_relaxed_t{},                // 单位置累加器 -> relaxed 足够

                    ct::thread_scope_device_t{});                // 在整个设备上可见
}
```

Python

```python
@ct.kernel
def block_sum(arr, out, TILE: ct.Constant[int]):
     bid = ct.bid(0)
     # 部分越界的尾部分块 -> 越界通道默认为 0
     tile    = ct.load(arr, index=(bid,), shape=(TILE,),
                       padding_mode=ct.PaddingMode.ZERO)
     partial = ct.sum(tile)                               # 归约为标量
     out.tiled_view((1,)).atomic_store_add((0,), partial) # 原子地累加到 out[0]
```

### 2.4.10.2 线程块内竞争

在下面的代码片段中，线程块内竞争之所以发生，是因为分块的所有值都被原子地加到内存中同一位置。

本例中，`ptrs` 分块里的每个元素都指向内存中同一位置 `slot`。由 `ct::iota<i32x16>()` 创建的分块的每个元素都被原子地加到该内存位置存储的值上。一个分块到单个内存地址的多个原子操作的执行顺序是未指定的。线程块作用域 `ct::thread_scope_block_t{}` 用来指定原子操作的结果只需要在本线程块内可见。

C++

```cpp
using i32x16 = ct::tile<int, ct::shape<16>>;

int* slot = /* 指向竞争位置的指针 */;

// 16 个通道都指向同一地址。加法满足交换律，因此
// 未指定的顺序不影响求和；竞争只发生在一个线程块内，
// 所以线程块作用域就够了。
auto ptrs = ct::full<ct::tile<int*, ct::shape<16>>>(slot);
ct::atomic_add(ptrs, ct::iota<i32x16>(),
            ct::memory_order_relaxed_t{},
            ct::thread_scope_block_t{});
```

> **注**
>
> 这只是演示。想把一个分块在线程块内归约为标量，推荐的方法是第 2.4.9.2 节所示的分块归约操作。

### 2.4.10.3 支持的原子操作

分块代码支持多种原子内存操作，区别在于写入的值与内存中已有值如何组合：

- `atomic_and`——按元素对传入的值与内存中的值做原子按位与
- `atomic_or`——按元素对传入的值与内存中的值做原子按位或
- `atomic_xor`——按元素对传入的值与内存中的值做原子按位异或
- `atomic_max`——按元素比较传入的值与内存中的值，把较大的值存入内存
- `atomic_min`——按元素比较传入的值与内存中的值，把较小的值存入内存
- `atomic_add`——把传入的值加到内存中的值上，把结果存入内存
- `atomic_sub`（仅 C++）——从内存中的值减去传入的值，把结果存入内存
- `atomic_xchg`——把传入的值写入内存，返回写入前内存中的值
- `atomic_cas`（C++ 中为 `atomic_compare_exchange`）——按元素比较内存中的值与作为参数传入的期望值。若匹配，把内存中的值替换为期望值

所有受支持的原子内存操作的完整文档，见 CUDA Tile C++ API Reference 或 cuTile Python API Reference 的内存操作章节。

## 2.4.11 优化提示

优化提示（optimization hint）是附着在源码构造（分块核函数、加载/存储调用点等）上的元数据，指导编译器的代码生成。提示不改变程序语义：加或不加提示，核函数编译和运行结果相同，因此可以自由地添加、删除或调优，不影响正确性。编译器也可能忽略任何提示。

提示有两个通用性质：

- 提示是按构造粒度的。提示只作用于它所附着的特定核函数或特定调用表达式，不作用于周围代码。
- 提示可以按架构指定。每个提示可以对不同 GPU 架构设置不同的值，也可以设置一个适用于所有目标的单一值。

两种语言暴露提示的方式不同：

- C++ 使用放在相关声明或语句上的 C++ 属性。
- Python 使用核函数装饰器和各内存操作调用点上的关键字参数。

提示种类的集合、每个提示实际控制什么，两种语言是共享的，见“提示种类”。

### 2.4.11.1 C++——cutile::hint 属性

在 C++ 中，提示用 C++ 属性 `cutile::hint` 表达：

```cpp
[[ cutile::hint(arch, kind1=value1, kind2=value2, ...) ]]
```

第一个参数是目标架构，编码为与 `__CUDA_ARCH__` 宏相同约定的整数（例如 sm_90 为 900，sm_100 为 1000）。特殊值 0 表示架构无关的提示，适用于每个目标架构。其余参数是 `kind=value` 对，指定提示种类和值。

`cutile::hint` 属性作用于它前面的构造：

- 对于分块核函数，把属性放在函数声明上。
- 对于 `ct::load`、`ct::store` 和 `ct::partition_view` 加载/存储等内存操作，把它放在包含该调用的表达式语句上。

其他放置位置有限制；完整的规则见 CUDA Tile C++ hint 规范。

下面的核函数演示了两种放置：一个核函数级提示为 sm_90 和 sm_100 设置不同的 `num_cta_in_cga`，一个表达式语句级提示把某次特定加载标记为带宽密集型。

C++

```cpp
[[ cutile::hint(900, num_cta_in_cga=4),      // sm_90: 偏好每个 cluster 4 个 CTA
    cutile::hint(1000, num_cta_in_cga=8) ]] // sm_100: 偏好每个 cluster 8 个 CTA

__tile_global__ void optimization_hints(float* __restrict__ in,
                                         float* __restrict__ out) {
     namespace ct = cuda::tiles;
     using namespace ct::literals;

      in = ct::assume_aligned(in, 16_ic);
      out = ct::assume_aligned(out, 16_ic);

      auto inSpan = ct::tensor_span{in, ct::extents{128_ic}};
      auto outSpan = ct::tensor_span{out, ct::extents{128_ic}};
      auto inView = ct::partition_view{inSpan, ct::shape{8_ic}};
      auto outView = ct::partition_view{outSpan, ct::shape{8_ic}};

      int bx = ct::bid().x;

      // 表达式语句级提示：把这次特定的加载标记为带宽密集型。
      ct::tile<float, ct::shape<8>> tile;
      [[ cutile::hint(0, latency=8) ]]
      tile = inView.load(bx);

      outView.store(tile, bx);
}
```

当多个同种类的提示作用于同一构造时，架构特定的提示覆盖架构无关的提示。

### 2.4.11.2 Python——装饰器参数与调用点关键字

Python 以两种方式暴露提示：

- 核函数级提示是 `@ct.kernel(...)` 装饰器的关键字参数。编译后的核函数对象还有一个 `.replace_hints(**hints)` 方法，返回一个覆盖了提示的新核函数；新核函数有自己的 JIT 缓存，因此 `replace_hints` 是自动调优循环的天然构件。
- 按调用点的提示是内存操作调用点上的关键字参数：`ct.load` / `ct.store`、`TiledView.load` / `TiledView.store` 和 `ct.gather` / `ct.scatter`。

按架构指定值时，把值包在 `cuda.tile.ByTarget(*, default=..., sm_XXX=..., sm_YYY=...)` 中。架构键必须是 `"sm_<major><minor>"` 形式的字符串（例如 `"sm_100"` 或 `"sm_120"`）。普通（非 ByTarget）值适用于每个目标——它是 C++ 中 `arch=0` 的架构无关提示的 Python 对应物。

下面的核函数是上面 C++ 示例的直接 Python 对应：`ByTarget` 携带核函数级提示，`latency=8` 关键字携带按调用点的提示，`replace_hints` 在不改源码的情况下产生一个重新调优的核函数。

Python

```python
@ct.kernel(num_ctas=ByTarget(sm_90=4, sm_100=8))
def optimization_hints(in_, out, TILE: ct.Constant[int]):
    bid = ct.bid(0)

     # 按调用点的提示：这次特定的加载是带宽密集型的。
     tile = ct.load(in_, index=(bid,), shape=(TILE,), latency=8)

     ct.store(out, index=(bid,), tile=tile)


# 自动调优：在不改源码的情况下产生一个覆盖了提示的新核函数。
# 新核函数有自己的 JIT 缓存。
tuned_kernel = optimization_hints.replace_hints(num_ctas=8)
```

### 2.4.11.3 提示种类

下面的提示是两种语言共享的。在每个提示中，C++ 名称和 Python 名称条目是同一底层提示的不同拼写；其他都相同：提示适用的位置、它的值、它的含义。

#### 2.4.11.3.1 每个 cluster 的 CTA 数

- C++ 名称：`num_cta_in_cga`（核函数属性）。
- Python 名称：`num_ctas`（`@ct.kernel` 装饰器参数）。
- 允许的值：1、2、4、8、16。在 sm_80 上只适用 1。
- 含义：启动核函数时编译器偏好每个合作组阵列（CGA）中的合作线程阵列（CTA）数量。

#### 2.4.11.3.2 占用率

- C++ 名称：`occupancy`（核函数属性）。
- Python 名称：`occupancy`（`@ct.kernel` 装饰器参数）。
- 允许的值：闭区间 [1, 32] 内的任意整数。
- 含义：每个流多处理器（SM）上活跃 CTA 的目标数量。编译器把该值视为建议，在代码生成时尽量满足。

#### 2.4.11.3.3 内存访问延迟

- C++ 名称：`latency`（放在包含该调用的表达式语句上的属性）。
- Python 名称：`latency`（调用点上的关键字参数）。

- 适用范围：分块空间加载与存储（C++ 中 `ct::partition_view`；Python 中 `Array.tiled_view` 和 `ct.load` / `ct.store`），以及 gather/scatter（C++ 中用指针分块的 `ct::load` / `ct::store`；Python 中 `ct.gather` / `ct.scatter`）。
- 允许的值：闭区间 [1, 10] 内的任意整数，1 表示 DRAM 流量轻，10 表示流量重。更大的值通常让编译器安排更大的预取深度。

#### 2.4.11.3.4 允许 TMA

- C++ 名称：`allow_tma`（放在包含该调用的表达式语句上的属性）。
- Python 名称：`allow_tma`（调用点上的关键字参数）。
- 适用范围：仅分块空间加载与存储（C++ 中 `ct::partition_view`；Python 中 `Array.tiled_view` 和 `ct.load` / `ct.store`）。Gather 与 scatter 操作不接受此提示。
- 允许的值：true / false（C++）或 True / False（Python）。TMA 默认允许；把提示设为 false/False 指示编译器不要在受支持的硬件上把这次特定的加载或存储降为 TMA。

## 2.4.12 C++ 性能提示

本指南中的 C++ 核函数都使用同样的一小组注解和惯用法。本节解释它们的作用和意义。

### 2.4.12.1 对内存中的数组使用 __restrict__ 指针

`__restrict__` 关键字告诉编译器，通过某指针访问的内存区域在该指针的生命周期内只会通过该指针访问。见第 5.4.1.4 节。

在分块 C++ 中，对满足这些条件的内存中数组使用 `__restrict__` 关键字标注其指针，对获得良好的内存操作性能至关重要。

为什么呢？考虑一个逐元素拷贝，它用的数组指针不是 `__restrict__`：

C++

```cpp
__tile_global__ void tile_elementwise_copy(float* out, float const* in) {
    namespace ct = cuda::tiles;

      using f32x64 = ct::tile<float, ct::shape<64>>;
      using i32x64 = ct::tile<int, ct::shape<64>>;

      auto inPtrs = in + 64 * ct::bid().x + ct::iota<i32x64>();
      auto outPtrs = out + 64 * ct::bid().x + ct::iota<i32x64>();

      auto data = ct::load(inPtrs);            // (1)
      ct::store(outPtrs, data);                // (2)
}
```

在 CUDA Tile 程序中，编译器如何并行化分块操作通常可以忽略。但这里我们考虑它，是为了理解为什么使用不重叠的数组能让编译器生成性能更好的代码。

考虑编译器如何并行化加载和存储分块操作。如果输入和输出数组不重叠，加载可以并行化为一组独立的内存读操作。类似地，存储可以并行化为多个内存写操作，每个只依赖它所写数据元素的加载操作。

但如果输入和输出数组可能重叠，编译器必须确保整个分块的所有内存加载操作都完成后才能发出任何内存存储操作，以保证正确的程序语义。否则，存储操作可能先执行，覆盖某个元素还没被加载读取，造成错误的程序执行。这限制了编译器交错读写的能力，因为所有读必须完成才能发出任何写。

简而言之，当编译器无法保证数组不重叠时，它必须生成更保守的代码。这就是为什么使用不重叠的数组，并用 `__restrict__` 关键字标注其指针告知编译器，有助于获得最佳性能。

当内存区域可能被另一个指针访问时，却把指针标注为 `__restrict__`，会导致未定义行为。

### 2.4.12.2 把数组指针标记为 16 字节对齐

用 `ct::assume_aligned` 把指向数组的指针标记为 16 字节对齐：

```cpp
__tile_global__ void foo(float* __restrict__ in) {
    namespace ct = cuda::tiles;
    using namespace ct::literals;

     in = ct::assume_aligned(in, 16_ic);

     ct::tensor_span t{in, ct::extents{256_ic, 256_ic}};
     ct::partition_view{t, ct::shape{4_ic, 4_ic}};

     // ...
}
```

这个对齐保证是 `ct::partition_view` 使用张量内存加速器（TMA）所必需的。用这种写法时，运行时必须提供 16 字节对齐的指针，否则行为未定义。

`cudaMalloc` 等 CUDA 内存分配器返回的指针保证至少 16 字节对齐。

### 2.4.12.3 内存访问优先用 ct::partition_view

对于结构化内存访问，优先用 `ct::partition_view`，而不是 gather/scatter 形式的 `ct::load` 和 `ct::store`。在受支持的硬件上，基于视图的形式可以降为张量内存加速器（TMA）执行，比逐元素 gather 快得多。gather/scatter 语境见“Gather 与 Scatter”。

### 2.4.12.4 有界循环用 ct::irange

在固定范围上迭代时，用 `ct::irange` 代替普通的 for 循环。结构化的形式让编译器能应用流水线、向量化等优化，而当循环边界和步长是不透明的整数表达式时这些优化不可用（见“控制流”）：

```cpp
for (auto idx : ct::irange(lowerBound, upperBound, step)) {
    // ...
}
```
