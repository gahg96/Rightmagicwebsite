# 2.2 CUDA Python 入门

本章介绍使用 Python 编写 CUDA 核函数的编程。CUDA Python 生态涵盖大量工具和库，且仍在积极演进。本章将先介绍其中一些组件，然后使用其中几个来演示在 Python 中编写和执行 GPU 代码的方法。

在 Python 中利用 GPU 计算的方式有很多，其中许多不需要显式编写 GPU 核函数。CUDA Python 生态的一些组件提供了直接在 GPU 上执行运算的函数，开发者无需做任何特定的 GPU 控制或编码。NVIDIA 加速计算中心（Accelerated Computing Hub）有一份《加速 Python 用户指南》（Accelerated Python User's Guide），介绍并讨论了众多实现 Python GPU 加速计算的库和工具。对于希望尽可能快速、简便地在 Python 中使用 GPU、而不一定直接编写 GPU 代码的用户来说，这份资料是很好的起点。

而本章聚焦于 GPU 的直接控制，以及编写在 GPU 上执行的 Python 核函数。本章的重点是 Python 中的 CUDA 单指令多线程（SIMT）编程。

## 2.2.1 CUDA Python 生态

CUDA Python 是支持 Python GPU 计算的工具和库生态。以下列表介绍了 CUDA Python 的主要组成部分，并非所有组件都为本章内容所必需。该列表改编自 CUDA Python GitHub 仓库中的完整列表。

主要组件——用于 GPU 控制和运行库提供的 GPU 代码：

- `cuda.core`——CUDA 控制（如内存与设备管理）的 Pythonic 接口。为 Python 提供的功能，相当于 CUDA Runtime 为 CUDA C++ 提供的功能。
- `cuda.compute`——Python 模块，提供由 CUDA Core Compute Library（CCCL）实现的 GPU 加速函数。
- `CuPy`——Python 库，提供 NumPy 例程的 GPU 加速版本，以及 ndarray 数据容器的 GPU 加速版本。

核函数编写组件：

- `cuda.lang`——Python 领域特定语言（DSL），使用 Python 语言子集、以 SIMT 编程模型编写 CUDA 核函数和设备函数。
- `cuda.coop`——Python 模块，提供可由设备端调用（通过 `cuda.lang`）的 CUDA Core Compute Library（CCCL）原语。
- `cuda.tile`——Python 领域特定语言（DSL），以 Tile 编程模型编写 CUDA 核函数和设备函数。

其他组件：

- `cuda.pathfinder`——用于在 Python 环境中定位已安装 CUDA 组件的工具。
- `cuda.bindings`——CUDA 库和工具的底层 Python 绑定，包括 CUDA Driver API、CUDA Runtime API、NVRTC、NVVM 等。`cuda.bindings` 通过 CUDA Driver 和 CUDA Runtime 组件提供与 `cuda.core` 相同的功能，但它是以 C 语言 API 的 Python 封装形式提供，而非原生 Pythonic 接口。

### 2.2.1.1 在 Python 中使用 CUDA 库

CUDA C++ 拥有丰富的库生态，可在不直接编写核函数或 GPU 代码的情况下实现 GPU 加速。CUDA C++ 于 2006 年发布时，可用的库很少，开发者大多需要自己编写 GPU 核函数代码。此后，大量库被开发出来，让开发者能够在 C++ 中利用 GPU 计算，而几乎无需编写 GPU 代码。

CUDA Python 生态则从相反的方向演化而来：在能够用 Python 语法和语义直接编写自定义核函数的能力出现之前，像 CuPy 这样的 Python 库就已经为 Python 开发者提供了计算和算法的 GPU 加速实现。这些库中有许多为用 CUDA C++ 实现的 GPU 代码提供了 Python 绑定。

在现代 CUDA 时代，只要 GPU 加速库能提供所需的表达能力，几乎总是建议优先使用这些库。许多库的实现都经过 GPU 计算专家的调优。当没有合适的库或库不够用时，在 Python 中也可以像在 C++ 中一样直接编写 GPU 核函数和设备函数。

### 2.2.1.2 本章范围

尽管开发者应尽可能优先使用库，本章其余部分介绍当开发者需要在 Python 中编写自定义 GPU 代码时的做法。本章以与 2.1 节介绍 C++ 相同的方式，讲解如何在 GPU 上编写和运行自定义 Python 代码：先介绍如何指定 GPU 核函数，然后介绍如何使用 CuPy 提供的 GPU 加速 ndarray 在 GPU 上分配内存、并实现 CPU 与 GPU 之间的通信。

### 2.2.1.3 环境准备

通常，CUDA Python 生态的大多数组件都可以在 PyPI 上找到，可通过 pip 命令或任何流行的 Python 包管理器安装。所有包都要求系统已安装最新版 NVIDIA 驱动。编写或运行 CUDA Python 应用一般不需要 CUDA Toolkit。关于在不同平台上安装和配置 CUDA Python 的信息，请参阅 NVIDIA Developer Zone 上的 CUDA Python 页面。

### 2.2.1.4 运行 CUDA Python 应用

无论使用 CUDA 加速库还是用户编写的 GPU 代码，CUDA Python 应用的运行方式都与常规 Python 应用相同。本节示例一律通过命令行调用 `python3` 运行，如下所示执行名为 `cuda-python-app.py` 的程序：

```bash
$ python3 cuda-python-app.py
```

## 2.2.2 Python 中的 SIMT 核函数

正如 CUDA 编程模型介绍中所说，在 GPU 上执行、可由主机端调用的函数称为核函数。CUDA 提供两种不同的模型：单指令多线程（SIMT）和 CUDA tile。SIMT 核函数编写出来由众多并行线程同时运行。这一概念在 CUDA Python 和 CUDA C++ 中是相同的。本章使用 SIMT 核函数来介绍 CUDA Python。

### 2.2.2.1 指定核函数

在 CUDA Python 中指定核函数之前，必须先导入 `numba.cuda` 包，常见写法如下：

```python
from numba import cuda
```

这会导入 `numba.cuda` 包，使我们能够使用该包提供的 `cuda` 命名空间中的组件。

要在 CUDA Python 中将一个函数指定为核函数，将装饰器 `@cuda.jit` 放在函数定义的上一行，如下所示：

```python
from numba import cuda

@cuda.jit
def function(input_array, output_array):
    ...
```

这将使核函数在首次启动时为当前活动的 GPU 进行 JIT 编译。当未指定其他 GPU 时使用默认 CUDA 设备，本节示例均属于这种情况。

### 2.2.2.2 启动核函数

将执行核函数的线程数量在核函数启动时指定，这称为执行配置（execution configuration）。核函数的每次调用都可以有自己的执行配置，例如不同的块大小或线程块数量。

#### 2.2.2.2.1 核函数启动

要启动核函数，将执行配置放在核函数名之后、函数参数之前的方括号 `[ ]` 中。参数顺序与 2.1.2.2.1 节介绍的 C++ 三重尖括号记法相同，具体为：

```text
kernel_name[number_of_thread_blocks, threads_per_block](arguments, ...)
```

下面的代码片段展示了如何在 Python 源文件中定义并调用核函数：

```python
from numba import cuda

@cuda.jit
def my_kernel(input, output):
    ...

## 启动核函数
my_kernel[num_thread_blocks, threads_per_block](in_array, out_array)
```

每个线程块的线程数量有限，因为一个线程块的所有线程都驻留在同一个流多处理器（Streaming Multiprocessor，SM）上，必须共享 SM 的资源。在当前 GPU 上，一个线程块最多可包含 1024 个线程。如果资源允许，一个 SM 上可以同时调度多个线程块。

#### 2.2.2.2.2 多维网格和线程块

在 CUDA 中，线程块和线程块组成的网格可以是一维、二维或三维的。当网格或线程块是一维时，指定核函数启动的执行配置时可以直接使用整数。当线程块或网格是二维或三维时，使用二维或三维元组，如下所示为二维网格和线程块的启动方式，其中 `gridX` 和 `gridY` 是网格的 x、y 维度，`blockX` 和 `blockY` 是网格中每个线程块的 x、y 维度：

```python
from numba import cuda

@cuda.jit
def function(input, output):
    ...

## 启动核函数
function[(gridX, gridY), (blockX, blockY)](in_array, out_array)
```

### 2.2.2.3 线程和网格索引内建变量

1.2.2.1 节介绍了线程和网格，2.2.2.2 节展示了如何为核函数启动指定网格和线程块的大小。在核函数内部，每个线程都可以访问执行配置的参数，以及线程在网格中的索引和线程块索引。

核函数内部可以使用以下变量来确定线程的身份：

- `cuda.threadIdx.[xyz]` 给出线程在其线程块内的索引。线程块中每个线程的索引都不同。
- `cuda.blockDim.[xyz]` 给出线程块的维度，即核函数启动时执行配置中指定的维度。
- `cuda.blockIdx.[xyz]` 给出线程块在网格中的索引。每个线程块的索引都不同。
- `cuda.gridDim.[xyz]` 给出网格的维度，即核函数启动时执行配置中指定的维度。

这些变量都是 3 分量的向量，带有 `.x`、`.y`、`.z` 成员。如果核函数启动时的执行配置中未指定某一维度，维度默认值为 1，索引默认值为 0。

`cuda.threadIdx` 和 `cuda.blockIdx` 的索引从 0 开始。也就是说，`cuda.threadIdx.x` 的取值范围是从 0 到 `cuda.blockDim.x - 1`（含两端）。`.y` 和 `.z` 在各自维度上的行为相同。

下面展示了一个简单的向量加法核函数代码，它将两个向量按元素相加。该函数接受三个数组 A、B、C，实现按元素的向量加法 C = A + B：

```python
# C = A + B 向量加法
@cuda.jit
def vecadd(A, B, C):
    idx = cuda.threadIdx.x + cuda.blockIdx.x * cuda.blockDim.x
    C[idx] = A[idx] + B[idx]
```

核函数首先计算线程在网格中的唯一索引。该核函数假定以一维线程块、一维网格启动。`idx` 变量是 0 到 N-1 的唯一索引，其中 N 是网格中的线程总数，即 N = `cuda.gridDim.x` * `cuda.blockDim.x`。

上述代码块中计算线程索引的模式非常常见，Numba 为此提供了一种简写语法：`cuda.grid(n)`，其中 n 是维度数。在上面的例子中，这一行：

```python
idx = cuda.threadIdx.x + cuda.blockIdx.x * cuda.blockDim.x
```

可以替换为更简单的：

```python
idx = cuda.grid(1)
```

这个核函数值得注意的一点是，它没有检查对 A、B、C 的越界访问。本章假定这些是由 CuPy 创建的 ndarray，2.2.3.3 节将很快介绍。使用 CuPy ndarray 时，边界检查由数组类型隐式实现。

## 2.2.3 GPU 计算中的内存

> **提示：**像 CuPy 这样的 Python 包直接使用 CUDA C++ API（如 2.1.3.2 节介绍的）来管理 GPU 内存。多个 Python 包提供了控制 GPU 内存分配的封装和工具。本指南只介绍 CuPy。这些概念对大多数包都是类似的，其行为方式也与各自的 C++ 对应物基本相同，另有说明的除外。

正如 1.2.3 节所介绍的，GPU 附带 DRAM。核函数要使用的数据数组通常需要在核函数访问之前先放入 GPU 的 DRAM 中。在 Python 中，控制数据在内存中的位置（即在 CPU 与 GPU 之间移动数据）是程序员的责任。这与 2.1.3.2 节介绍的 C++ 显式内存管理情况相同。

### 2.2.3.1 在 GPU 上实例化数组

CuPy 提供了在 GPU 上创建指定类型和维度的 ndarray 对象、以及在 CPU 与 GPU 之间复制数据的函数。CuPy 中的许多函数与 NumPy 中创建 ndarray 的函数具有相似的函数签名。下面展示了使用 CuPy 在 GPU 内存中创建并填充数组的几个示例：

```python
import cupy as cp
import numpy as np

## 在 GPU 上创建全零矩阵
## 未指定数据类型时，默认使用 float32
A_device = cp.zeros((1024, 1024))

## 在 GPU 上创建包含 2^20 个随机双精度浮点数的数组
B_device = cp.rand.random((2**20), dtype=np.double)

## 创建与现有数组形状和数据类型相同的全零数组
C_device = cp.zeros_like(A)
```

### 2.2.3.2 在主机端与 GPU 内存之间复制数组

CuPy 还可用于将驻留在 CPU 内存中的 NumPy ndarray 数据复制到驻留在 GPU 内存中的 CuPy 数组：

```python
import cupy as cp
import numpy as np

## 在主机端内存中创建数组
A_host = np.zeros((1024, 1024))
## 将数组复制到 GPU
A_device = cp.array(A_host)

## 在 GPU 内存中创建数组
B_device = cp.rand.random((1024, 1024))
## 将数组复制到主机端内存
B_host = cp.asnumpy(B_device)
```

### 2.2.3.3 ndarray 对象类型

上一节展示的 ndarray 对象要么存在于主机端内存，要么存在于 GPU 内存，不能同时存在于两者。将驻留在主机端的数组作为参数传给核函数会导致错误；将驻留在 GPU 内存中的数组传给普通 Python 函数（即非核函数）也会导致错误。CuPy 不会在 CPU 与 GPU 之间隐式复制数据，因为这类复制开销可能很大，过量复制会损害性能。因此，CuPy 要求程序员对数据何时在 CPU 与 GPU 之间复制有明确的意图。

在 GPU 核函数中使用 ndarray 类型的另一个优点是，数组自带其各维度的范围。正如 2.2.2.3 节所示，边界检查会自动进行；当所需线程总数略小于执行块或网格的总大小时，核函数代码无需检查越界访问。

## 2.2.4 同步 CPU 与 GPU

与 C++ 一样，CUDA Python 中的核函数启动相对于主机端线程是异步的。也就是说，核函数启动后，主机端代码在 CPU 上继续执行，无法保证核函数已经完成、甚至已经开始执行。要保证 GPU 核函数已执行完毕，主机端线程必须执行某种与 GPU 的同步操作。

最简单的同步形式是同步整个 GPU。这种设备范围的同步是由 CUDA 驱动提供的操作，CuPy 和 numba.cuda 都通过 `synchronize()` 方法将其暴露给 Python：

```python
import cupy as cp
from numba import cuda

..

## 在主机端线程等待所有待处理的 GPU 工作完成
## 使用 cupy 提供的接口
cp.synchronize()

## 在主机端线程等待所有待处理的 GPU 工作完成
## 使用 numba.cuda 提供的接口
cuda.synchronize()
```

设备范围的同步使主机端线程等待，直到所有先前发出的 GPU 工作都完成。更细粒度的同步可以使用 CUDA 流实现，详见 2.5 节。在 Python 中使用流时，推荐的做法是使用 `cuda.core` 创建 CUDA 流，并根据需要仅与特定流进行同步。

## 2.2.5 综合示例

下面源代码清单以 Python 形式展示了经典的入门 GPU 核函数——并行向量加法：

```python
import numpy as np
from numba import cuda
import cupy as cp


## 定义 CUDA 核函数，实现 C = A + B 向量加法
@cuda.jit
def vecadd(A, B, C):
    work_index = cuda.grid(1)
    C[work_index] = A[work_index] + B[work_index]


# 注意：向量长度既不是 2 的幂，也不是下面 block_size 的整数倍

vector_size = 2**24 + 11

device = cp.cuda.Device()
## 创建均匀随机 float32 输入数组，以及全零的结果数组
a = cp.random.uniform(-1, 1, vector_size)
b = cp.random.uniform(-1, 1, vector_size)
c = cp.zeros_like(a)

block_size = 256
grid_size = int(np.ceil(vector_size/block_size))

vecadd[grid_size, block_size](a, b, c)

## 同步 CPU 线程与 GPU，确保核函数已执行完成
## 包含此行是为了演示良好实践，虽然下面的复制操作
## 会隐式等待核函数执行完成
device.synchronize()

## 将 3 个数组全部复制到 CPU 上成为 ndarray
a_np = cp.asnumpy(a)
b_np = cp.asnumpy(b)
c_np = cp.asnumpy(c)

## 在 CPU 上执行相同的加法以验证答案
expected = a_np + b_np

## 检验答案在浮点误差范围内正确
np.testing.assert_array_almost_equal(c_np, expected)

## 断言失败时会打印诊断信息并中止
## 因此只有断言通过才会打印这一行
print("Test succeeded")
```

在这个例子中，A 和 B 输入数组由 CuPy 在 GPU 上创建并初始化为随机值。代码末尾将它们复制到 CPU，仅仅是为了让 CPU 也能执行向量加法，从而验证 CPU 与 GPU 的答案是否一致。

## 2.2.6 CUDA Python 中的错误检查

任何影响 GPU 的操作——从内存分配和复制到核函数启动——都可能引发错误。如 2.1.7 节为 C++ 展示的那样，在与 GPU 交互过程中确保没有错误发生是最佳实践。

在 Python 中，CUDA 错误会抛出异常，未捕获时将终止程序。异常可以用常规 Python 语法捕获。下面的例子与上面的向量加法相同，但故意加入了一个错误：每个线程块 2048 个线程，超过了任何现有 GPU 的运行能力。这将导致核函数启动失败并抛出异常，代码会捕获该异常：

```python
import numpy as np
from numba import cuda
import cupy as cp


## 定义 CUDA 核函数，实现 C = A + B 向量加法
@cuda.jit
def vecadd(A, B, C):
    work_index = cuda.grid(1)
    C[work_index] = A[work_index] + B[work_index]


try:
       vector_size = 2**24 + 11

       device = cp.cuda.Device()
       a = cp.random.uniform(-1, 1, vector_size)
       b = cp.random.uniform(-1, 1, vector_size)
       c = cp.zeros_like(a)

       ## 这个块大小超过了任何现有 GPU 的能力
       block_size = 2048
       grid_size = int(np.ceil(vector_size/block_size))
       # 错误：用非法块大小启动核函数
       vecadd[grid_size, block_size](a, b, c)

       device.synchronize()
       print("Test did not encounter any errors")

except Exception as e:
    print(f"Exception occurred: {e}")
```

运行这段代码会捕获并显示错误，如下所示：

```text
$ python3 vecadd_error.py
Exception occurred: CUDA_ERROR_INVALID_VALUE: This indicates that one or more of the parameters passed to the API call is not within an acceptable range of values.
```

程序捕获异常后正常退出。如果去掉 `try:` 和 `except:` 直接运行该代码，程序将异常退出并在控制台打印回溯信息，其中应显示相同的错误。
